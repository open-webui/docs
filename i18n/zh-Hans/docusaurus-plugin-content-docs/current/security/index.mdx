## 供应链与安全扫描器 {#supply-chain-and-security-scanners}

**我们对自动化供应链扫描器标记（socket.dev 及类似工具）的立场。**

自动化扫描器会基于行为风险指标和未经确认的分类，标记 Open WebUI 的软件包。本页说明为什么这些标记都不代表已命名的漏洞或恶意代码，并直接回答常见的“无沙箱代码执行”问题：默认代码引擎在浏览器沙箱中运行，服务器端执行则需要主动启用。

| | |
| :--- | :--- |
| **启发式标记，而非实际发现** | 为什么能力标记不等于漏洞 |
| **未经确认的分类** | 解释“潜在恶意软件”横幅 |
| **默认启用沙箱** | 默认使用 Pyodide WASM；服务器端执行需要主动启用 |

[**阅读供应链与安全扫描器 →**](/security/supply-chain-security)

### 漏洞数据库中已被拒绝的 CVE {#rejected-cves-in-vulnerability-databases}

一些漏洞数据库和端点安全产品不会重新处理 CVE 撤销，因此发布 CNA 已正式拒绝的标识符仍会显示为 Open WebUI 的有效漏洞发现。本页记录了受影响的数据库、每次联系及其结果，并说明如何在几秒内根据 cve.org 上的权威状态核对任何记录。

[**阅读漏洞数据库中已被拒绝的 CVE →**](/security/supply-chain-security/vulnerability-databases)

## 厂商判定 {#vendor-dispositions}

**我们对外部报告的 CVE 和安全声明所作的正式评估。**

当某个针对 Open WebUI 提交的 CVE 被我们认为不准确、描述有误，或在我们的威胁模型中并不构成真实漏洞时，我们会发布详细的厂商判定。每份判定都会解释我们的评估、背后的理由，以及适用时已采取的措施。

| | |
| :--- | :--- |
| **正式评估** | 对每份争议报告的详细分析 |
| **威胁模型背景** | 相关声明如何对应 Open WebUI 的架构 |
| **处理状态** | 报告是被接受、存在争议还是被拒绝 |

[**查看厂商判定 →**](/security/vendor-dispositions)

## 已知与已接受的风险 {#known--accepted-risks}

**我们已在技术上尽可能缓解，随后正式接受的剩余风险。**

有些弱点无法在应用程序代码中完全消除，因为其限制来自语言、运行时、操作系统、CPU 或网络，而非我们可以修补的缺陷。我们会尽可能缩小可被利用的部分，并在此记录其余风险、相关理由以及它们与威胁模型的关系。

| | |
| :--- | :--- |
| **尽可能缓解** | 为降低每项风险所做的更改 |
| **剩余风险存在的原因** | 使其无法彻底修复的语言、操作系统、CPU 或网络限制 |
| **威胁模型背景** | 为什么接受剩余风险，而不将其视为缺陷 |

[**查看已接受的风险 →**](/security/accepted-risks)
