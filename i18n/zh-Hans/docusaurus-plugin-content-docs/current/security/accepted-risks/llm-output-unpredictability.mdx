# LLM 输出的不可预测性

|  |  |
| :--- | :--- |
| **类别** | 模型的固有行为（提示词注入、越狱、不安全或虚构的输出），OWASP LLM 十大风险 |
| **状态** | LLM 所固有；不是可修复的应用程序缺陷；其本身不属于漏洞范围，除非根据[安全政策](../security-policy.mdx)被证明与真实的 Open WebUI 漏洞构成攻击链 |

---

## 概述 {#summary}

Open WebUI 尊重并感谢 [OWASP LLM 应用十大风险](https://owasp.org/www-project-top-10-for-large-language-model-applications/)；它是分析 AI 系统如何失效的重要框架。然而，其中记录的许多行为并非传统意义上的安全漏洞。它们是大型语言模型自身固有的风险，存在于任何基于这类模型构建的应用中，而非由特定厂商代码中的缺陷引入。当模型获得工具和自主权时，同样的风险会延伸到智能体行为；请参阅[智能体应用风险](./agentic-application-risks.mdx)。

大型语言模型具有非确定性，并且可以被输入引导。精心构造的提示词、所抓取网页或上传文档中的注入内容，或对抗性对话，都可能诱使模型产生不安全、误导性或符合攻击者意图的输出，例如越狱、提示词注入、虚构事实、不安全建议，或试图以用户不希望的方式使用可用工具。

这种不可预测性是语言模型工作方式的固有属性，**并非 Open WebUI 代码中的缺陷**。

## 我们缓解的风险 {#what-we-mitigate}

Open WebUI 控制模型*周边*的系统，并加固这一层面：

- **访问控制和隔离**限制模型及其工具可以访问的范围，包括按用户划分的数据范围、[工具和函数权限模型](/features/extensibility/plugin/)，以及默认在浏览器中运行（Pyodide）的代码执行；任何服务器端引擎都需要主动启用，并由运维人员进行隔离。
- **模型不能超越调用用户自身的权限。** 代表用户行动时，它受该用户的权限约束；它无法读取或执行用户无法通过 Open WebUI 自身 API 读取或执行的内容或操作。
- **运维人员防护措施**（[Filters](/features/extensibility/plugin/functions/filter)、内容检查、确认提示）让部署可以添加自己的策略层。

这些措施可以减少不良模型输出造成的*后果*，但无法也不可能使模型输出本身在任何情况下都可预测或安全。

## 剩余风险及为何不视为漏洞 {#what-remains-and-why-it-is-not-treated-as-a-vulnerability}

如果一个安全问题的全部影响都是**模型的输出**，即模型被说服说出某些内容、推荐某些内容，或尝试执行其本已获准尝试的操作，那么它就是 **LLM 所固有的风险，其本身不是 Open WebUI 漏洞**。它受限于模型对齐技术的当前水平，而非 Open WebUI 代码可以修补的问题；“让模型永远不产生有害输出”也不是应用层可以实现的修复。

因此，**如果报告的全部影响只是模型产生不良内容，或被说服滥用其本已获准使用的能力，我们不会将其作为漏洞接受。** 该行为是运行 LLM 时一种已接受的固有属性，不会作为缺陷处理。

**这是关于模型行为的范围界定，并非一刀切的豁免。** 一旦精心构造的输入从“模型说了某些内容”演变为 Open WebUI 自身代码或控制措施中的具体缺陷，该报告**就**属于范围，并会被视为真实漏洞，例如：

- 提示词注入**通过 Open WebUI 代码路径升级为代码执行、数据访问或权限提升**；
- **绕过访问控制、权限或隔离检查**；或
- 模型仅是底层应用程序缺陷的**触发因素**的任何漏洞。

这些都是 Open WebUI 缺陷，并会按缺陷进行修复。完整的报告范围请参阅[安全政策](../security-policy.mdx)。
