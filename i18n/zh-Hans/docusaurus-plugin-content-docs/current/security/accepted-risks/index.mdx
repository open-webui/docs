# 已知与已接受的风险

**Open WebUI 已评估、在技术上可行或运维上合理的范围内尽可能缓解，随后正式接受的剩余风险。**

有些弱点无法在应用程序代码中完全消除。它们的限制来自编程语言、运行时、编译器和解释器优化、操作系统、CPU 或网络，而非 Open WebUI 可以修补的缺陷。对于这些弱点，我们会在应用层代码允许的范围内尽可能缩小可被利用的部分，然后在此将剩余部分记录为已知的已接受风险。

少数弱点可以在代码中消除，但代价是会影响合理依赖当前行为的部署，因此改为提供配置选项。

每个条目都会记录风险内容、为缩小风险所做的更改、剩余部分无法修复或只能以影响现有部署为代价修复的原因，以及它如何纳入我们的[威胁模型](#threat-model)。

---

## 为何接受这些风险 {#why-we-accept-these}

接受剩余风险是一项慎重的工程决策，而非疏忽。只有同时满足以下所有条件，弱点才会列在这里：

- **可被利用的部分已得到处理**，处理范围达到应用层代码允许的上限，或已通过运维人员可应用的控制措施解决。
- **剩余风险有明确边界**：它在实践中无法被可靠利用，或仅在运维人员刻意启用受影响的功能时才存在，因此默认部署不受影响。
- **没有必要消除剩余风险**，至少符合以下原因之一：
  - 它在**技术上无法由我们修复**，其来源是语言、运行时、操作系统、CPU 或网络，而非 Open WebUI 自身的逻辑；或
  - 进一步修复会带来**真实且不成比例的代价**，降低或移除用户合理依赖的功能，或损害性能或正确性，却只能换来微小或虚幻的安全收益；或
  - 进一步修复**不会带来安全收益**，因为剩余情况已经采用失败关闭方式，不会向任何人授予任何权限。

无论属于哪种情况，我们都会明确记录剩余风险及其边界，而不是暗示作出无法或不应作出的保证。

---

## 威胁模型 {#threat-model}

Open WebUI 是一个**自托管、单租户、需要身份验证、基于角色**的应用程序。此处列出的风险均在这一模型下评估：

- **用户必须经过身份验证**，才能访问任何用户数据或产品功能。按照设计，浏览器在登录前所需的端点（登录、注册以及登录界面读取的公共配置）无需账户即可访问。
- **管理员**是拥有完整系统控制权的受信人员。
- 报告按**默认或更严格**的配置进行评估。

如果某项剩余风险的实际影响主要由网络和调度噪声决定，或只能在威胁模型已经排除的条件下观察到，我们会接受该风险，而不将其视为可修复的缺陷。完整模型请参阅[安全政策](../security-policy.mdx)。
