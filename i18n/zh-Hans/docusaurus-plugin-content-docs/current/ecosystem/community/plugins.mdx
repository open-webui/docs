[Open WebUI 社区网站](https://openwebui.com/)收录了数百个由社区构建的工具和函数，你可以一键将它们导入自己的实例。本页是一份新手导览：介绍插件库的工作方式、如何按目标选择插件，以及如何安全导入。

:::danger 精选不等于经过审核

在本页获得展示，或者在 Open WebUI 社区网站上被**精选、标记为热门或列入目录，均不构成认可**，也**不**表示代码已经过安全性或质量审查。这些条目由社区提交，未经审计。

工具和函数会在你的服务器上执行**任意 Python 代码**。插件的星标数或展示位置无法说明其代码实际会做什么。每次导入前都要阅读源代码。请参阅完整的[插件安全警告](/features/extensibility/plugin/)。

:::

## 插件库的工作方式 {#how-the-library-works}

- 在 [openwebui.com](https://openwebui.com/) **浏览**工具和函数，或按关键词[搜索](https://openwebui.com/search)。
- 可以一键**导入**、将源代码粘贴到内置编辑器，或向导入功能提供原始文件或 GitHub 文件 URL。Get 按钮会打开你实例的创建页面并预填代码，只有按下 Save 后才会保存。不需要 `pip install`，也不需要重启。
- **导入位置：**导入的**工具**显示在**工作区 > 工具**下，导入的**函数**显示在**管理员面板 > 函数**下。函数仅限管理员使用；拥有 `workspace.tools` 或 `workspace.tools_import` 权限的用户也可以创建和编辑工具，而通过 URL 导入对两者均仅限管理员。两者的区别请参阅[工具与函数](/features/extensibility/plugin/)。

## 按目标查找插件 {#find-a-plugin-by-what-you-want-to-do}

仅凭名称并不总能判断插件的*类型*，因此应从目标出发。在[社区网站](https://openwebui.com/search)上搜索下列术语，然后在导入前阅读代码。

| 我想要…… | 插件类型 | 在社区网站搜索 |
| :--- | :--- | :--- |
| 为模型提供**实时联网搜索**或实时数据 | [工具](/features/extensibility/plugin/tools) | `web search`、`weather`、`search` |
| **添加模型服务提供方**（Anthropic、Gemini、路由器、本地引擎） | [Pipe](/features/extensibility/plugin/functions/pipe) | `pipe`、提供方名称 |
| **跟踪或限制每位用户的成本/用量** | [Filter](/features/extensibility/plugin/functions/filter) | `cost`、`usage`、`budget`、`rate limit` |
| **隐去 PII** 或审核消息内容 | [Filter](/features/extensibility/plugin/functions/filter) | `pii`、`redact`、`moderation` |
| **总结或压缩**长对话 | [Filter](/features/extensibility/plugin/functions/filter) | `context`、`memory`、`compaction` |
| 在消息上添加**按钮**（导出、重新运行、翻译） | [Action](/features/extensibility/plugin/functions/action) | `action`、任务名称 |
| **响应系统事件**（审计日志、注册限制、预配） | [Event](/features/extensibility/plugin/functions/event) | `event`、`webhook`、`audit` |
| 连接**现有 HTTP 服务** | [OpenAPI / MCP 服务器](/features/extensibility/mcp) | 不适用（将 Open WebUI 指向规范） |

不确定哪种类型合适？[我需要哪种扩展？](/features/extensibility#which-extension-do-i-need)表格会逐步帮助你判断。

## 导入前：新手安全检查清单 {#before-you-import-a-beginner-safety-checklist}

社区插件拥有与服务器其他部分相同的访问权限。安装插件应当视为以管理员身份运行他人的脚本。导入前：

1. **阅读代码。** 如果不理解它的作用，就不要安装。尤其要警惕与陌生主机的网络通信、读取你的 `data` 目录或环境变量的代码，以及任何经过混淆的内容。
2. **检查它是否只执行声称的功能。** 一个“翻译”操作没有理由向外部发送数据或读取你的数据库。
3. **查看 `requirements:`。** 额外的 pip 依赖会在加载时安装。未知软件包会带来供应链风险，而在多副本部署中，运行时安装会在 worker 之间产生竞争（请设置 [`ENABLE_PIP_INSTALL_FRONTMATTER_REQUIREMENTS=False`](/reference/env-configuration#enable_pip_install_frontmatter_requirements)，改为将依赖预置到镜像中）。
4. **先在非生产实例上试用**，确认可信后再部署到生产环境。
5. **限制可以导入的人员。** 只有受信任的管理员才应创建或导入插件。除非确有需要，普通用户不应拥有工作区访问权限。

如需深入了解插件加载后可以访问哪些内容（以及随之出现的易误用之处），请参阅[内部机制](/features/extensibility/plugin/development/under-the-hood)。

## 分享你自己的插件 {#sharing-your-own-plugin}

构建了有用的内容？将它发布到社区网站，让其他人能够找到并导入。同样的注意事项也反向适用：清晰的 README 和可读、可审计的代码才能赢得信任，因为没有人会替你审计。请将机密保存在 [Valves](/features/extensibility/plugin/development/valves) 中，而不是硬编码；并编写 `async` 处理程序，使插件在后端逐步转向完全异步执行时保持兼容。
