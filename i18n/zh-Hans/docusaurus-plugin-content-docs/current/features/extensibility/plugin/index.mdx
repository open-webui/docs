:::danger 严重安全警告

**工具、函数、Pipe、Filter 和 Pipeline 会在你的服务器上执行任意 Python 代码。** 这是其设计使然，也是它们强大能力的来源。不过，这也意味着：

1. **只从可信来源安装。** 切勿导入来源未知或不受信任的工具或函数。恶意代码可能危及你的整个系统。

2. **精选不代表经过审查。** 某个插件被突出展示、列为精选、广受欢迎或收录在 [Open WebUI 社区网站](https://openwebui.com/)上，均**不**代表官方认可，也**不**意味着其代码已经过安全性或质量审查。网站收录的内容由社区提交，未经审计。请参阅[社区插件](/features/extensibility/community)。

3. **导入前审查代码。** 安装任何社区工具或函数之前，请审查其源代码。如果你不理解它的作用，就不要安装。

4. **保护你的数据目录。** `data` 目录（在 Docker 中挂载于 `/app/backend/data`）包含你的数据库、配置以及缓存的工具和函数。如果攻击者获得该目录的写入权限，就可以注入将在你的服务器上执行的恶意代码。

5. **限制工作区访问权限。** 只有受信任的管理员才应拥有创建、导入或修改工具和函数的权限。除非明确需要，否则普通用户**不应**拥有工作区访问权限。

6. **定期审计已安装的插件。** 通过**工作区 > 工具**和**管理员面板 > 函数**，定期检查实例中安装的工具和函数。

**可能造成什么后果？** 恶意工具或函数可能窃取数据、安装恶意软件、挖掘加密货币、横向移动到你的网络中的其他系统，或者损坏你的实例。

:::

## 速览 {#tldr}

- **工具**扩展 LLM 的能力，使其能够收集天气、股价等现实世界中的实时数据。
- **函数**扩展 Open WebUI 本身的能力，让你可以添加新的 AI 模型支持（如 Vertex AI），或者提升易用性（如创建自定义按钮或过滤器）。

工具和函数很容易上手，因为一切都已内置在核心系统中！你只需**点击一个按钮**，即可**直接从社区导入这些功能**，无需编写代码或进行深入的技术工作。

:::tip 插件系统的能力远超本文档所能展示的范围
后续页面记录了完整的插件 API：类结构、生命周期方法、参数、事件类型、返回值约定以及管线中的每个钩子。这份参考文档是完整的。

本文档无法涵盖的是人们实际用它构建出的丰富应用。社区插件已被用于实时流式 HTML 仪表板、按用户执行成本控制、汇总并替换较早对话轮次的上下文管理器、双向交互式 UI、聊天内 MCP 应用、取证水印等许多场景。

如果你正在考虑提交功能请求，并认为“这需要修改核心代码”，请先问问能否通过插件实现。插件系统可以访问完整的请求/响应生命周期、持久化状态、用户元数据、事件发射器以及可由管理员配置的 Valves 系统。实际上，大多数看似需要修改核心的功能（自定义身份验证逻辑、按用户限流、响应后处理、特定提供方的路由、成本跟踪、上下文管理策略）都可以完全以插件形式实现，而无需改动核心代码库。在社区网站发布插件还意味着其他用户可以立即受益，无需等待版本发布周期。
:::

## 什么是“工具”和“函数”？ {#what-are-tools-and-functions}

首先，可以把 **Open WebUI** 想象成一款能够完成许多大型语言模型（LLM）相关任务的“基础”软件。但有时，你需要一些并非*开箱即用*的额外功能或能力。这正是**工具**和**函数**的用武之地。

### 工具 {#tools}

**工具**是一项令人兴奋的功能，因为它让 LLM 不再局限于处理文本。工具提供了 LLM 自身原本不具备的**外部能力**。

#### 工具示例： {#example-of-a-tool}

想象一下，你正在与 LLM 聊天，希望它提供最新的天气动态或实时股价。通常情况下，LLM 无法做到，因为它只能依赖预训练知识。这时就需要**工具**！

- **工具就像插件**，LLM 可以使用它们收集**现实世界中的实时数据**。因此，启用“天气工具”后，模型就能访问互联网、收集实时天气数据，并将其显示在你的对话中。

从本质上说，工具是你赋予 AI 的**能力**，帮助它与外部世界交互。添加这些能力后，LLM 就能根据对话上下文“获取”有用信息或执行专门任务。

#### 工具示例（扩展 LLM 的能力）： {#examples-of-tools-extending-llms-abilities}

1. **实时天气预报**。
2. **股价查询**。
3. **航班跟踪信息**。

### 函数 {#functions}

**工具**由 AI 在对话过程中使用，而**函数**用于扩展或自定义 Open WebUI 本身的能力。可以把工具想象成给菜肴添加新食材，而函数则是你用来掌控整个厨房的流程！

#### 具体来说： {#lets-break-that-down}

- **函数**让你能够调整或添加 **Open WebUI** 本身的**功能**。
- 你并不是赋予 LLM 新能力，而是在扩展平台本身的**界面、行为或逻辑**！

例如，你可能希望：

1. 向 WebUI 添加 **Vertex AI** 这样的新 AI 模型服务提供方。
2. 在工具栏中创建一个用于执行常用命令的自定义按钮。
3. 实现更好的**过滤器**功能，从传入文本中拦截不当内容或**垃圾消息**。

没有函数，这些都难以实现。但借助 Open WebUI 中的这个框架，你可以轻松扩展这些功能！

### 在哪里查找和管理函数 {#where-to-find-and-manage-functions}

函数与工具不在同一位置。

- **工具**用于模型访问，位于你的**工作区选项卡**中（与添加模型、提示词和知识库的位置相同）。获得权限的用户可以添加工具。
- **函数**用于**平台自定义**，位于**管理员面板**中。
  它们只能由希望为所有用户扩展平台界面或行为的管理员配置和管理。

### 区别总结： {#summary-of-differences}

- **工具**让 LLM 能够**完成更多超出默认能力的事情**（例如检索实时信息，或根据外部数据执行自定义任务）。
- **函数**帮助 WebUI 本身**完成更多事情**，例如添加新的 AI 模型，或创建更智能的数据过滤方式。

两者都设计为**可插拔**，这意味着你只需从社区一键即可将它们导入系统！你不必花费数小时编写或调试代码。
