Open WebUI 实现了灵活且安全的**基于角色的访问控制（RBAC）**系统。该系统通过三个相互关联的层级，让管理员能够精确管理用户的能力和资源访问权限：

1.  [**角色**](./roles.md)：高层用户类型（管理员、用户、待审核）。它定义基线信任级别。
2.  [**权限**](./permissions.md)：精细的功能开关（例如“可以删除聊天”、“可以使用网络搜索”）。
3.  [**组**](./groups.md)：用于组织用户、授予额外权限以及管理资源（ACL）共享访问的机制。资源也可以直接共享给单个用户。一个组可以位于另一个组内并继承其权限（[嵌套组](./groups.md#nested-groups)），还可以设置成员开始新聊天时使用的[默认模型](./groups.md#default-models-per-group)。

:::info 核心概念：累加式权限
安全模型采用**累加方式**。用户从默认权限开始，组成员关系会**增加**能力。用户实际拥有的是其角色和组所授予全部权限的*并集*。
:::

:::warning RBAC 与提供方凭据的作用范围
RBAC 控制用户可以在 **Open WebUI 内部**执行的操作（功能、资源和界面/API 操作）。

RBAC **不能**取代外部提供方的最小权限配置。如果连接 OpenAI 兼容代理/提供方（例如 LiteLLM、OpenRouter 或自定义网关），请在部署中使用权限范围仅限于推理用途的提供方凭据。

除非部署明确需要这种信任级别，否则请避免为普通用户流量配置管理密钥或主密钥。
:::

## 文档指南 {#documentation-guide}

*   [**角色**](./roles.md)
    *   了解管理员与用户之间的区别。
    *   了解管理员的限制以及安全/隐私配置。
    *   通过[**退出所有设备**](./roles.md#signing-a-user-out-of-every-device)终止用户的每个会话。

*   [**权限**](./permissions.md)
    *   浏览可用权限开关的完整列表。
    *   了解聊天、工作区和功能的精细控制。
    *   **安全提示**：了解正确配置的全局默认设置如何保护系统。

*   [**组**](./groups.md)
    *   了解如何构建团队和项目。
    *   **策略**：区分“权限组”（用于权限）和“共享组”（用于访问）。
    *   管理私有模型和知识库的访问控制列表（ACL）：与组或单个用户共享。
    *   将组放入其他组（[嵌套组](./groups.md#nested-groups)），并[按组设置默认模型](./groups.md#default-models-per-group)。
