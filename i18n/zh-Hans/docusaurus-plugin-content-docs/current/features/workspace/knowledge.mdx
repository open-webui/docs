使用知识库可以针对 Open WebUI 中的 PDF、文档和其他文件提问。上传文件，将知识库附加到模型或对话，然后提出问题。文档内容的处理位置取决于你使用的内容提取、嵌入和模型服务提供方；请参阅[聊天数据隐私与加密](/security/chat-data-privacy-and-encryption)。

## 提出第一个文档问题 {#ask-your-first-document-question}

开始前，请确保 Open WebUI 实例正在运行、已连接模型，并且你拥有创建知识库和上传文件的权限。要进行聚焦检索，请使用支持[原生函数调用](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)的模型，并启用**内置工具（Builtin Tools）**和**知识库（Knowledge Base）**工具类别。原生模式是默认模式；模型必须使用其工具来检索附加的知识。

1. 点击**工作区 > 知识库（Workspace > Knowledge）**，然后点击**创建（Create）**。为知识库命名并填写描述。
2. 上传一个小型文本型 PDF 或文本文件。等待处理完成后再针对它提问。
3. 将知识库附加到聊天，或将其附加到模型并使用该模型开始对话。[附加知识和笔记](#attaching-knowledge-and-notes)介绍了具体操作位置。
4. 提出答案位于文件中的问题，例如：“使用附加的手册查找办公室开放时间，并引用相关段落。”
5. 将答案及任何来源引用与原始文档进行对照。如果模型找不到相关内容，请按照[知识库故障排除](/troubleshooting/rag#13-knowledge-base-attached-to-model-not-working)中的步骤操作。

## 选择文件的使用方式 {#choose-how-to-work-with-files}

| 需求 | 使用方式 |
| :--- | :--- |
| 在一次对话中询问一个文件 | [将文件上传到聊天](/features/chat-conversations/data-controls/files#using-files-in-open-webui) |
| 在多次对话中复用一组文档 | 按照上述步骤使用知识库 |
| 通过代码分析电子表格或创建文件 | [Open Terminal 文件分析指南](/features/open-terminal/use-cases/file-analysis) |

[笔记](/features/notes)会将全文传递给模型，而知识库可以按需检索相关段落。因此，对于完整发送会超出模型上下文窗口的文档集，知识库尤其有用。知识库和笔记可以附加在相同的位置；本页中的“知识”涵盖这两者以及单个文件。对于仅限本地的文档聊天，还请遵循[离线运行 Open WebUI](/tutorials/maintenance/offline-mode)中的说明。

## 附加知识和笔记 {#attaching-knowledge-and-notes}

知识库、笔记和单个文件可以附加到聊天、[文件夹](/features/chat-conversations/chat-features/conversation-organization#attached-knowledge)（应用于其中的每个聊天）或[模型](/features/workspace/models)。

**在聊天中：**

- 在消息输入框中键入 `#`。列表会提供**文件夹（Folders）**、**知识库（Knowledge）**和**文件（Files，知识库中的单个文件）**，并接受网页或 YouTube URL。
- 也可以点击 **+**（**更多（More）**），然后打开**附件（Attachments）**。**附加知识（Attach Knowledge）**列出你的知识库，可通过**显示文件（Show Files）**选择其中的单个文件。**附加笔记（Attach Notes）**列出你的笔记。同一菜单还包含**附加网页（Attach Webpage）**、**附加文件（Attach Files，以前上传的文件）**和**引用聊天（Reference Chats）**。除非启用 [`ENABLE_LOCAL_WEB_FETCH`](/reference/env-configuration#enable_local_web_fetch)，否则**附加网页（Attach Webpage）**会拒绝私有地址和环回地址；请参阅[附加链接失败](/troubleshooting/rag#14-attaching-a-link-or-a-youtube-video-fails)。
- 还可以将侧边栏中的笔记、文件夹或聊天拖到消息输入框中。

**在模型或文件夹上：**打开**知识库（Knowledge）**字段。模型编辑器（**工作区 > 模型（Workspace > Models）**，或**设置 > 模型 > 编辑（Settings > Models > Edit，管理员区域）**）以及文件夹**编辑（Edit）**对话框中的**高级（Advanced）**区域都提供此字段。其搜索列表包含**笔记（Notes）**、**知识库（Knowledge）**和**文件（Files，知识库中的单个文件）**；**上传文件（Upload Files）**可直接从你的计算机添加文件。

**工作区 > 知识库（Workspace > Knowledge）**仅列出知识库。笔记位于[笔记](/features/notes)中。

## 为什么使用知识库？ {#why-knowledge}

### 让 AI 能够搜索你的文档 {#your-documents-become-searchable-by-ai}

上传包含合同、技术规范或研究论文的文件夹。AI 会按含义而不只是关键词进行搜索，并引用答案的来源位置。

### 两种检索模式满足不同需求 {#two-retrieval-modes-for-different-needs}

检索相关段落（RAG），让 AI 高效搜索大型文档集；或者在需要精确内容时启用**全文（Full text）**，逐字注入整个文档。

### 通过原生函数调用自主探索 {#autonomous-exploration-with-native-function-calling}

启用[原生函数调用](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)后，模型不仅能搜索，还能浏览你的知识库、逐页阅读文件，并综合多个文档的内容，无需手动提示。

### 限定范围的访问让内容井然有序 {#scoped-access-keeps-things-organized}

将知识附加到模型、文件夹或聊天时，你可以精确选择该模型要搜索的知识。其知识工具随后只会列出并搜索附加的项目。这样可以使答案更聚焦、更可预测，因为模型仅使用你选择的来源。你还可以决定每个模型搜索哪些文档：云服务商的模型可以只获得公共手册，而运行于自有硬件的模型还可以获得内部文档。用户自身的访问权限仍会在此基础上生效。

以下因素会限定知识工具的范围：

- 模型**知识库（Knowledge）**字段中的所有内容（知识库、笔记和文件）；
- 聊天所在文件夹的**知识库（Knowledge）**字段中的所有内容；
- 当模型的**预加载文件（Preload files）**能力关闭时，聊天中直接附加的知识库和笔记。启用该能力后，这些内容会注入对话。

在聊天中，上传的文件、从知识库中选取的单个文件、文件夹、引用的聊天和网页会各自以独立方式传递给模型，不会改变知识工具的范围。

要让模型浏览用户可读取的所有知识库，不要附加任何内容。要限制其范围，请准确附加它应使用的内容，包括你希望它阅读的笔记。模型也可以通过独立的**笔记（Notes）**工具类别访问笔记；无论附加了什么，该类别都能访问用户的所有笔记。若要将访问范围限定为附加的笔记，请在模型的**内置工具（Builtin Tools）**下关闭**笔记（Notes）**。[工具表](#agentic-knowledge-tools)列出了各种情况下可用的工具。

## 检索模式 {#retrieval-modes}

将文件或知识库附加到模型时，点击已附加的项目，使用其**全文（Full text）**开关在检索相关段落（关闭）和注入整个文件（开启）之间选择：

![知识库列表](/images/workspace/knowledge-list.png)

在打开的预览中，知识库名称会在工作区中打开该知识库，文件或链接名称会打开相应文件或页面。两者均在新标签页中打开。

### 聚焦检索（默认） {#focused-retrieval-default}

使用 RAG，根据用户查询查找并注入最相关的分块。启用混合搜索（`ENABLE_RAG_HYBRID_SEARCH`）后，检索会结合 BM25 关键词搜索与向量搜索，并通过重排序提高准确性。

最适用于只有特定部分相关的大型文档集。

### 完整上下文 {#full-context}

将文件的完整内容注入每条消息，不进行分块或语义搜索。对于聊天中附加的文件和知识库，只要模型的**预加载文件（Preload files）**能力开启，无论采用哪种函数调用模式，都会注入完整内容。但附加到模型的知识库只会在传统函数调用模式下注入；在原生函数调用模式下，无论是否选择完整上下文，模型都通过知识工具访问模型附加的知识。

最适用于简短的参考文档、风格指南或始终相关的上下文。

**设置（Settings）** > **文档（Documents，管理员区域）**中的**全文字符数阈值（Full Text Threshold (Characters)）**或**全文词元数阈值（Full Text Threshold (Tokens)）**由**全文阈值类型（Full Text Threshold Type）**决定。不超过该阈值的文件和文本附件无需开启**全文（Full text）**也会完整包含；**始终使用全文（Always Use Full Text）**则将其应用于每个文档。

## 智能体式知识工具 {#agentic-knowledge-tools}

启用[原生函数调用](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)后，模型会使用**知识库（Knowledge Base）**工具类别中的内置工具与你的知识库（简称 KB）交互。具体可用的工具取决于是否附加了知识，如[限定范围的访问](#scoped-access-keeps-things-organized)所述。

![知识库中的文件，以及搜索和排序功能](/images/workspace/knowledge-detail.png)

| 工具 | 已附加知识 | 未附加任何知识 | 描述 |
|------|:-----------:|:--------------:|-------------|
| `list_knowledge` | 是 | 否 | 列出附加的 KB（含文件数量）、单个文件和笔记；传入 `knowledge_id`（以及 `skip`/`count`，最多 200）可分页查看一个 KB 的文件 |
| `list_knowledge_bases` | 否 | 是 | 浏览可用的知识库及其文件数量 |
| `search_knowledge_bases` | 否 | 是 | 按名称或描述查找知识库 |
| `query_knowledge_bases` | 否 | 是 | 按语义相似度搜索 KB 名称/描述 |
| `search_knowledge_files` | 是（仅限附加内容） | 是（全部） | 按文件名搜索文件 |
| `query_knowledge_files` | 是（仅限附加内容） | 是（全部） | 使用 RAG 管道搜索文件内容；附加的笔记会以其全文返回 |
| `grep_knowledge_files` | 是（仅限附加内容） | 是（全部） | 在知识文件中进行精确文本/正则表达式搜索（返回带行号的匹配行；自动检测 `error|warn` 之类的正则表达式） |
| `view_file` | 附加 KB 或文件时 | 否 | 读取文件内容，支持分页（`offset`/`max_chars`）或行范围（`start_line`/`end_line`，可选 `line_numbers`） |
| `view_knowledge_file` | 附加 KB 或文件时 | 是 | 从任何可访问的 KB 读取文件内容 |
| `display_file` | 附加 KB 或文件时 | 是 | 在聊天中向用户内联显示文件，可选择指定页面或幻灯片 |
| `view_note` | 附加笔记时 | 否 | 读取笔记 |

模型会获知己附加的内容：你的消息之后，一个隐藏的 `list_attached_knowledge` 工具结果会携带 `<attached_knowledge>` 列表，其中包含模型和文件夹的项目及其 ID；每条消息也会列出附加到它的项目。模型使用这些 ID 分页查看某个知识库的文件列表，或将文件名搜索限制在单个知识库中。使用 `query_knowledge_files` 进行内容搜索时，会在一次排序检索中覆盖所有附加知识，并返回其中得分最高的分块，因此不同知识库的分块会竞争相同的结果名额。

`list_knowledge` 和 `list_knowledge_bases` 互斥：附加知识后，模型会列出已附加内容；未附加任何知识时，模型会发现用户可读取的每个知识库。

**笔记工具。** **笔记（Notes）**工具类别独立于知识工具。只要为用户启用了笔记功能且模型的**笔记（Notes）**类别开启，模型就会在每个聊天中获得 `search_notes`、`view_note`、`write_note` 和 `replace_note_content`，无论是否附加知识；这些工具可以访问用户可读取的所有笔记。这就是 `view_note` 会出现在未附加任何内容的聊天中的原因。请参阅[智能体式笔记管理](/features/notes#agentic-note-management)。

#### 何时优先使用 `grep_knowledge_files` 而非 `query_knowledge_files` {#when-to-prefer-grep_knowledge_files-over-query_knowledge_files}

这两个搜索工具互为补充：

| | `query_knowledge_files` | `grep_knowledge_files` |
|---|---|---|
| **匹配方式** | 语义/向量检索（启用 [`ENABLE_RAG_HYBRID_SEARCH`](/reference/env-configuration#enable_rag_hybrid_search) 时可结合 BM25 和重排序） | 精确字符串匹配，自动检测正则表达式（例如 `error\|warn`、`version \d+`） |
| **返回内容** | 相关内容分块 | 匹配行，以及文件 ID、文件名和从 1 开始的行号 |
| **适用场景** | 适合“文档对 X 是怎么说的？”这类改写后的问题和概念查询 | 适合“找出我们提到 `OPENAI_API_KEY` 的所有位置”这类字面标识符、错误字符串和版本号查询 |
| **结果上限** | 工具自身的 `count` 参数，由模型设置（默认 5）。管理员的 Top K 设置不适用于此工具 | 50 个匹配项（[`KNOWLEDGE_GREP_MAX_MATCHES`](/reference/env-configuration#knowledge_grep_max_matches)） |
| **标志** | （无） | `case_insensitive`、`count_only`、`file_id`（单文件模式） |

在智能体式流程中，典型模式是：先用 `query_knowledge_files` 定位相关文档，再用 `grep_knowledge_files` 精确定位行，最后用 `view_file`（下文的行范围模式）读取周边上下文。

#### 使用 `view_file` 读取 {#reading-with-view_file}

`view_file` 支持两种定位模式：

- **字符分页**：`offset` + `max_chars`（默认 `10000`，硬性上限 `100000`；两者可分别通过 [`VIEW_FILE_DEFAULT_MAX_CHARS`](/reference/env-configuration#view_file_default_max_chars) 和 [`VIEW_FILE_MAX_CHARS`](/reference/env-configuration#view_file_max_chars) 配置）。适合流式读取长文档；文件被截断时，响应包含 `next_offset`。
- **行范围**：`start_line` 和/或 `end_line`（从 1 开始，包含边界行）。设置后会覆盖 `offset`/`max_chars`；可与 `grep_knowledge_files` 的行号自然配合。传入 `line_numbers: true` 还可为每个返回行添加 `<n>: <line>` 前缀。

行范围响应包含 `total_lines` 和 `showing_lines`。范围会在不超过 [`VIEW_FILE_MAX_CHARS`](/reference/env-configuration#view_file_max_chars) 的最后一个完整行处停止；`truncated` 和 `next_start_line` 会指明继续读取的位置。

### 文件系统式访问（`kb_exec`） {#filesystem-style-access-kb_exec}

设置 [`ENABLE_KB_EXEC=True`](/reference/env-configuration#enable_kb_exec) 后，Open WebUI 会提供 `kb_exec` 工具，让模型通过文件系统式接口访问知识库。

**不再提供的工具**，因为其功能已由 `kb_exec` 命令覆盖：

- `list_knowledge`：由 `ls` 替代
- `search_knowledge_files`：由 `find "<glob>"` 替代
- `grep_knowledge_files`：由 `grep "<pattern>"` 替代
- `view_file` 和 `view_knowledge_file`：由 `cat`、`head`、`tail`、`sed -n '<a>,<b>p'` 替代

**仍与 `kb_exec` 一起注入的工具**，因为它们提供 `kb_exec` 不具备的功能：

- **`query_knowledge_files`**：语义/RAG 搜索（始终提供）
- **`display_file`**：始终提供
- **`view_note`**：附加笔记时提供（`kb_exec` 仅涵盖文件，因此笔记需要独立的读取工具）
- **`query_knowledge_bases`** 和 **`search_knowledge_bases`**：未附加任何内容时提供，使模型仍能按名称/描述发现并跨知识库搜索

`kb_exec` 遵循相同的[范围限定规则](#scoped-access-keeps-things-organized)。未附加任何内容时，`ls` 列出用户可读取的知识库。附加知识后，`ls` 仅列出附加的知识库，随后在**附加文件（Attached Files）**下列出附加的单个文件。笔记从不出现在 `kb_exec` 中：附加的笔记通过 `view_note` 读取，或通过 `query_knowledge_files` 查找；仅附加笔记时，`ls` 返回 `No knowledge bases found.`

该功能**默认关闭**，仍处于实验阶段；但为了获得增强的智能体式 RAG 体验，建议为运行原生函数调用且能力较强的模型启用它（`ENABLE_KB_EXEC=True`）。它面向已经会“用 Shell 思考”的前沿模型：与编排大量专用工具的并行调用相比，这些模型通常能更可靠地串联 `ls`、`grep` 和 `cat`。它仅在启用原生函数调用时有效；对于设置为传统模式（Legacy）的模型，它不起作用。

**支持的命令**

| 命令 | 用途 |
|---------|---------|
| `ls`、`ls <dir>/`、`ls -a` | 列出当前层级/子目录/所有文件的平铺视图（含完整路径） |
| `ls -t`、`ls -S`、`ls -r` | 对列表排序：最新优先、最大优先，或反转当前生效的顺序 |
| `tree`、`tree <dir>/` | 递归目录树 |
| `cat -n <file>` | 读取文件（可选择带行号） |
| `head -N <file>` / `tail -N <file>` | 前 N 行或后 N 行 |
| `sed -n '<a>,<b>p' <file>` | 打印第 `<a>` 至 `<b>` 行 |
| `grep "<pattern>" [<dir>/\|<file>\|*.ext]` | 精确/正则表达式搜索；标志 `-i`（不区分大小写）、`-l`（仅文件名）、`-c`（计数） |
| `find [<dir>/] "<glob>"` | 按 glob 查找文件，并支持与 `ls` 相同的排序标志 |
| `wc <file>` | 行数/单词数/字符数 |
| `stat <file>` | 文件元数据 |

**管道**

`kb_exec` 可解析单条管道，因此可以组合命令：

```text
grep "auth" | head -5
grep -l "TODO" docs/
find docs/ "*.md" | head -10
```

**文件引用**

文件有三种定位方式，选择含义明确的一种即可：

- **路径**：`docs/api/auth.md`（相对于知识库根目录；通过目录树解析）
- **文件名**：`auth.md`（当多个目录或 KB 中存在同名文件时，会返回包含“ambiguous filename”提示的错误）
- **文件 ID**：`ls`、`find` 或 `grep` 返回的 UUID

**排序**

`ls`、`find` 和 `tree` 默认按路径列出文件，因此列表稳定，且可在多次调用之间比较。三个标志可改变排序：`-t` 将最近更新的文件排在前面，`-S` 将最大的文件排在前面，`-r` 反转当前适用的顺序，因此 `ls -tr` 表示最旧优先。它们可以与其他所有参数组合，例如 `ls -a -t` 或 `find docs/ "*.md" -S`。

对于包含数千个文件的知识库，要询问“最近有什么变化”，应使用 `ls -a -t | head -20`，而不是读取完整列表。

**行为说明**

- `kb_exec` 遵循与其他知识工具相同的访问控制：用户无法读取的文件会被静默排除在结果之外。
- **每次调用的输出都有上限。** 一条命令最多返回 30,000 个字符（[`KB_EXEC_MAX_OUTPUT_CHARS`](/reference/env-configuration#kb_exec_max_output_chars)），无论这些字符由什么命令产生；达到上限时，模型会收到缩小命令范围的指示。这是整条管道共享的单一预算，因此大文件的 `cat` 和大范围的 `grep` 都受同样限制。
- **大范围的 `grep` 会被拒绝，而不会执行。** 搜索超过 200 个文件（[`KB_EXEC_MAX_GREP_FILES`](/reference/env-configuration#kb_exec_max_grep_files)）时，会返回提示，要求将搜索范围限定到某个目录或 glob；`grep` 最多返回 50 个匹配行（[`KNOWLEDGE_GREP_MAX_MATCHES`](/reference/env-configuration#knowledge_grep_max_matches)），与 `grep_knowledge_files` 和 `grep_chat_files` 使用的上限相同。
- 模型仍拥有用于语义搜索的 `query_knowledge_files`；当字面命令找不到经过改写的概念时，应使用该工具。
- 基于目录模型构建。`kb_exec` 是唯一完整反映 UI 中所创建目录结构的工具。

自主探索最适合能够智能地串联搜索、浏览和内容综合的前沿模型。较小的模型可能难以完成多步骤检索。管理员可在**设置 > 模型 > 编辑 > 内置工具（Settings > Models > Edit > Builtin Tools，管理员区域）**中按模型禁用**知识库（Knowledge Base）**工具类别（对于自己的模型，也可在**工作区 > 模型（Workspace > Models）**中操作）。

#### 引导模型在混合知识库中选择工具 {#guiding-tool-choice-across-mixed-knowledge-bases}

启用 `kb_exec` 后，模型会在两个互补工具之间选择。要让模型针对每个知识库选择正确工具，最简单的方法是使用简短的**系统提示词**，指明各知识库及优先使用的工具：

- **叙述性文档和 PDF** 适合 `query_knowledge_files`（语义搜索）。它按含义匹配，因此能很好地处理对文档进行改写后的问题，并且不依赖干净的文本提取结果。
- **文本文件、代码、配置和日志**适合 `kb_exec`（`ls`、`tree`、`grep`、`cat`、按行读取）。模型可以遍历目录树并提取精确行；对于字面标识符、错误字符串和结构，这优于语义搜索。

按知识库明确说明这些规则的提示词能正确引导模型，同时仍允许它自行决定每次调用：

> 已附加两个知识库。**Handbook（手册）**是 PDF 文档：针对它的问题使用 `query_knowledge_files`。**Codebase（代码库）**是源文件：使用 `kb_exec`（`grep`、`cat`、`ls`）查找并读取精确的代码。通常，精确字符串、标识符和文件结构优先使用 `kb_exec`，概念性问题优先使用 `query_knowledge_files`。

未启用 `kb_exec` 时，[`grep_knowledge_files` 和 `query_knowledge_files`](#when-to-prefer-grep_knowledge_files-over-query_knowledge_files)之间也适用同样的分工。

有关内置智能体式工具的完整列表，请参阅[原生/智能体模式工具指南](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)。

:::warning 原生函数调用不会自动注入知识

启用原生函数调用后，附加到模型或文件夹的知识**不会自动注入**。模型必须调用知识工具进行搜索和检索。如果模型未使用附加的知识：

1. **添加系统提示词指令**，告诉模型使用 `list_knowledge` 和 `query_knowledge_files`。
2. **按照[知识库故障排除](/troubleshooting/rag#13-knowledge-base-attached-to-model-not-working)检查模型的工具能力和检索设置**。保持原生模式开启，并使用能够可靠调用工具的模型。
3. **对于小文档，请在聊天中附加它，开启其全文（Full text）开关，并启用模型的预加载文件（Preload files）能力**，以注入其全文。使用原生函数调用时，附加到模型或文件夹的知识绝不会被注入。
:::

## 设置知识库 {#setting-up-a-knowledge-base}

初次创建、上传和聊天的步骤，请参阅[提出第一个文档问题](#ask-your-first-document-question)。以下章节介绍完成设置后的知识库管理。

知识库超过少量几个后，可以点击**标题（Title）**或**更新时间（Updated at）**列标题重新排序。再次点击当前排序所依据的列标题会反转排序方向。列表默认按**更新时间（Updated at）**以最新优先的顺序排列。

要更改谁可以查看或编辑知识库，请打开其所在行的三点菜单并选择**访问权限（Access）**。这会直接打开访问权限设置，无需先打开知识库，并且每项更改都会立即保存。管理员可在每个知识库上看到该菜单；其他用户只能在有权编辑的知识库上看到它，并且必须拥有[**知识共享（Knowledge Sharing）**](/features/authentication-access/rbac/permissions#2-sharing-permissions)权限。知识库内部的**访问权限（Access）**按钮遵循相同规则。拥有写入权限时，保存知识库的名称或描述不会更改其共享设置，包括你自身无权设置的**公开（Public）**设置。[资源访问权限](/features/authentication-access/rbac/groups#resource-access-rbac)介绍了可见性和访问授权。

### 文件限制 {#file-limits}

管理员在**设置 > 文档（Settings > Documents，管理员区域）**中设置全局限制：**知识库批量上传上限（Knowledge Batch Upload Limit）**（每次上传的文件数）、**知识库文件大小上限（Knowledge File Size Limit）**（每个文件的 MB 数）和**知识库文件数量上限（Knowledge File Count Limit）**（每个知识库的文件总数）。留空表示无限制。也可以通过 [`KNOWLEDGE_MAX_UPLOAD_COUNT`](/reference/env-configuration#knowledge_max_upload_count)、[`KNOWLEDGE_MAX_FILE_SIZE`](/reference/env-configuration#knowledge_max_file_size) 和 [`KNOWLEDGE_MAX_FILE_COUNT`](/reference/env-configuration#knowledge_max_file_count) 设置相同的值。

知识库所有者或管理员可以为单个知识库设置更低的**文件数量上限（File count limit）**和**文件大小上限（MB）（File size limit (MB)）**：创建时在**高级（Advanced）**下设置，或之后通过知识库页面上的三点菜单 > **设置（Settings）**设置。同时设置全局和本地限制时，采用较低者。外部知识库没有本地限制。

会导致超出限制的上传将被拒绝，并显示 `Knowledge base file limit exceeded (N files maximum).` 或 `You can only upload a maximum of N file(s) per batch.` 等错误。

### 浏览和预览文件 {#browsing-and-previewing-files}

打开知识库后，左侧以树形结构显示文件，右侧显示预览窗格。点击文件即可在预览中打开；在小屏幕上，预览会滑入并覆盖列表。

预览提供两种视图，可通过上方按钮切换：

- **预览（Preview）**显示文件：PDF、图片、音频、视频、Word 文档、Excel 工作簿（带工作表选择器）、PowerPoint 幻灯片，以及 Markdown、代码、CSV、JSON、HTML 和 SVG 等文本型文件。文本型文件和 SVG 显示其索引文本；其他格式显示原始文件。对于 Markdown、CSV、JSON、HTML 和 SVG 等具有渲染视图的格式，**⋯** 菜单可在**查看源文件（View source）**和**渲染预览（Rendered preview）**之间切换。
- **索引文本（Indexed text）**显示 Open WebUI 从文件中提取的文本。检索和知识工具搜索的正是这部分内容，因此当答案遗漏了文档中实际存在的信息时，应在这里检查。

![左侧包含文件夹和文件、右侧在预览视图中打开 PDF 的知识库](/images/workspace/knowledge-browser-preview.webp)

![同一 PDF 在索引文本视图中显示提取的文本及行号](/images/workspace/knowledge-browser-indexed-text.webp)

如果原始文件不可用，例如只存储了其文本，文件会在**索引文本（Indexed text）**中打开，并隐藏**预览（Preview）**按钮。

**编辑索引文本**

拥有写入权限时，点击**编辑（Edit）**修改索引文本，然后点击**保存（Save）**（或**取消（Cancel）**）。保存会重新处理新文本，并更新包含该文件的每个知识库，使检索使用你更正后的文本。原始文件保持不变；[重新索引](/features/chat-conversations/rag#what-does-re-indexing-do)会再次从原始文件提取文本，替换你的编辑。文本不能为空。如果处理失败，会显示错误；再次保存即可重试。

存在未保存的编辑时，打开其他文件、关闭预览、删除项目、同步、重置或离开页面，都会先询问**放弃未保存的更改？（Discard unsaved changes?）**。

**下载**

**下载（Download）**位于预览的 **⋯** 菜单和每个文件行的三点菜单中。它保存原始文件。对于因原始文件不可用而在**索引文本（Indexed text）**中打开的文件，下载会将索引文本保存为 `.txt` 文件。

**移除文件**

请保留仍在使用的知识库所对应的已存储上传文件。索引会存储可搜索文本，而**下载（Download）**和重新索引仍可能需要原始文件。直接从存储中删除上传文件会留下其 Open WebUI 记录。请使用文件移除操作将文件从知识库中移除，并参阅[文件保留设置](/reference/env-configuration#enable_knowledge_file_retention)了解已存储副本的处理方式。

**搜索、筛选和排序**

目录树上方的**搜索文件（Search Files）**框按文件名搜索整个知识库，文件夹内的结果会在名称旁显示文件夹路径。旁边的筛选按钮提供：

- **搜索文件内容（Search file content）**：同时匹配文件内的索引文本。超大文件仅搜索到字符数上限（[`RAG_FILE_CONTENT_SEARCH_MAX_CHARS`](/reference/env-configuration#rag_file_content_search_max_chars)）。
- **全部（All）**、**由你创建（Created by you）**或**与你共享（Shared with you）**：按文件添加者限制列表。
- **名称（Name）**、**创建时间（Created）**或**更新时间（Updated）**，以及**升序（Ascending）**或**降序（Descending）**：排序方式。默认按**更新时间（Updated）**以最新优先排序。

### 整理到目录中 {#organizing-into-directories}

知识库支持嵌套**目录**，使大型文档集保持易于浏览。通过**添加内容（Add Content）**菜单（**新建目录（New directory）**）创建目录，然后可自由重新整理。

**创建和导航**

- **新建目录（New directory）**位于**添加内容（Add Content）**菜单（搜索框旁的 **+** 按钮）中，该菜单还提供**上传文件（Upload files）**、**上传目录（Upload directory）**、**同步目录（Sync directory）**、**添加网页（Add webpage）**、**添加文本内容（Add text content）**和**重置（Reset，从知识库中移除所有文件）**。在新行中输入名称并按 Enter。名称唯一性按父目录分别校验：两个同级目录不能同名，但可以在不同父目录下复用名称。
- 点击目录可在树中展开或折叠。目录行的三点菜单可直接向该目录添加内容：**新建文件夹（New folder）**、**上传文件（Upload files）**、**上传目录（Upload directory）**、**添加文本内容（Add text content）**和**添加网页（Add webpage）**。
- 目录可以**重命名**或**移动到其他父目录**，不会影响其中的文件。

**拖放**

可以通过拖动移动项目：

- 将**文件**拖到目录行，或拖到目录树顶部的**所有文件（All files）**标签，将其移回顶层。
- 将**目录**拖到另一个目录上进行嵌套，或拖到**所有文件（All files）**上移动到顶层。服务器端会阻止将目录移动到其自身或任一后代目录中。

**删除语义**

删除目录会打开标题为**删除目录？（Delete directory?）**的对话框，其中包含一个复选框：**删除此目录中的所有内容（Delete all contents inside this directory）**：

- 勾选（默认）：从知识库中移除该目录、其子目录及其中的所有文件。
- 取消勾选：移除该目录及其子目录，并将其中任意深度的所有文件移动到被删除目录的父目录（或顶层）。

**对检索和工具的影响**

- **检索和标准 RAG**仍覆盖整个知识库。目录不会拆分向量索引；单次搜索仍可访问任何子目录中的分块。
- **智能体式工具**能够识别目录：
  - `kb_exec`（启用时）将子目录视为文件系统：`ls docs/`、`tree`、`grep "x" docs/` 和路径式引用（`docs/api/auth.md`）均可使用。请参阅下文的[文件系统式访问（`kb_exec`）](#filesystem-style-access-kb_exec)。
  - 其他知识工具（`query_knowledge_files`、`grep_knowledge_files`、`search_knowledge_files`）会忽略目录边界，返回整个 KB 中的匹配项。

### 重命名文件 {#renaming-files}

可以通过工作区中的文件项目菜单直接重命名单个文件，无需重新上传。新名称会同步到引用该文件的所有位置（知识库列表、智能体式工具输出、引用）。

### 同步本地目录 {#syncing-a-local-directory}

**添加内容 → 同步目录（Add Content → Sync directory）**操作会将本地文件夹**增量**镜像到知识库：客户端计算每个本地文件的哈希（SHA-256），服务器将哈希和路径与已存储内容进行比较，仅处理**新增**、**修改**和**删除**的文件。未修改的文件（通常占大多数）保持不变：不重新上传，也不重新生成嵌入。本地文件夹的子目录结构会镜像到 KB；创建缺少的子目录，并移除本地已不存在的子目录。

:::tip 要同步大量文件？请改用 oikb
应用内的**同步目录（Sync directory）**在你的浏览器中运行：它在客户端枚举、计算哈希并上传每个文件。对于规模适中的文件夹，这没有问题；但对于**大型**文件集（数千个文件或数 GB 的库），速度会变慢且进度反馈很少，往往要等很久才会报告文件数量。对于大型或频繁变化的库，我们**强烈建议**改用官方[**知识库同步（Knowledge Base Sync，oikb）**](/ecosystem/knowledge-base-sync)工具：它原生运行，提供进度条、并行上传和重试，专为这类场景设计。将其指向文件夹顶层，它会将整个目录树（递归包含每个子目录）同步到一个知识库。
:::

需要注意以下行为：

- 隐藏文件和文件夹（任何以 `.` 开头的项目）会被跳过。
- 对于本地修改过的文件，同步会先从知识库移除旧条目，再上传替代文件。如果上传或处理失败，在后续同步成功之前，检索中可能缺少该文件。
- 如果同步报告 `Upload failed for … of … files.`，请打开浏览器的开发者控制台，查找 `Upload failed:`，找到每个受影响的相对路径和报告的错误。解决报告的问题，然后使用同一本地文件夹再次运行**添加内容 → 同步目录（Add Content → Sync directory）**。
- 本地已删除的文件会在清理阶段从 KB 中删除。
- 此操作对未更改的文件是**非破坏性**的。
- 知识库中仍标记为**处理中（Processing）**的文件，例如因 Open WebUI 在处理完成前重启而处于该状态的文件，只要路径、名称和内容未变，在原始上传后一小时内不会再次上传。在这一小时内，同步会将其计入 `Sync complete` 消息中的**未修改**文件。一小时后，下次同步会重新上传。
- **处理中（Processing）**的文件没有项目菜单，因此无法从知识库视图中移除。若要在一小时结束前重试，请通过 `GET /api/v1/knowledge/{id}/files/pending` 查找其 ID，使用 `DELETE /api/v1/files/{file_id}` 删除，然后再次同步。

对于程序化使用，同一工作流通过下文 [API 访问](#api-access)中的两个端点提供。

:::tip 同步远程来源或按计划同步
应用内的**同步目录（Sync directory）**操作处理你计算机上的本地文件夹。如果要镜像**远程**来源（GitHub 仓库、Confluence 空间、S3 存储桶以及[另外数十种来源](/ecosystem/knowledge-base-sync#sources-and-connectors)），或按计划或在每次推送时**自动**保持知识库最新，请使用官方[**知识库同步（Knowledge Base Sync，oikb）**](/ecosystem/knowledge-base-sync)配套工具。它会为你调用这些相同的端点。
:::

### 导出 {#exporting}

管理员可以通过项目菜单（三点）> **导出（Export）**将整个知识库导出为 zip 文件。文件会转换为 `.txt`，以实现通用兼容性。普通用户看不到导出选项。

### API 访问 {#api-access}

可以通过编程方式管理知识库：

**文件**

- `POST /api/v1/files/`：上传文件。在上传元数据中传入 `knowledge_id`（以及可选的 `directory_id`），可让后端**在服务器端自动关联文件并将其处理到该知识库中**，相当于随后调用 `POST /api/v1/knowledge/{id}/file/add`，但不依赖客户端在上传后保持连接。这是推荐的单调用路径。服务器对上传的字节计算 SHA-256 哈希并写入 `file.meta.file_hash`；客户端可以预先计算并在元数据中发送 `file_hash`，以跳过服务器端哈希计算（用于下文的增量同步流程）。
- `GET /api/v1/files/{id}/process/status`：检查处理状态。`completed` 表示索引以及任何知识库关联均已完成。
- `POST /api/v1/files/{id}/rename`：重命名文件。
- `GET /api/v1/files/{id}/content`：下载原始文件。对于仅以文本形式存储的文件，返回 404 和 `Original file is unavailable.`。
- `GET /api/v1/files/{id}/content/{file_name}`：以附件形式下载文件。原始上传文件缺失时，以纯文本形式返回索引文本。
- `GET /api/v1/files/{id}/data/content`：读取索引文本。
- `POST /api/v1/files/{id}/data/content/update`：替换索引文本（请求体：`content`），并在包含该文件的每个知识库中重新处理。空 `content` 会被拒绝并返回 `400`。
- `POST /api/v1/knowledge/{id}/file/add`：向知识库添加文件。如果知识库中已存在提取文本相同的文件，该文件会被拒绝，并返回 `Duplicate content detected. Please provide unique content to proceed.`。
- `POST /api/v1/knowledge/{id}/files/batch/add`：一次添加多个文件。同样执行重复检查：重复文件会报告为失败文件，其他文件仍会添加。
- `POST /api/v1/knowledge/{id}/files/validate`：上传前对照[文件限制](#file-limits)进行检查（请求体：`count`，可选 `file_size`（字节）和 `removed_file_ids`）。返回 `{"status": true}`，或返回实际上传会得到的相同错误。
- `GET /api/v1/knowledge/{id}/files`：列出知识库的文件，使用 `page` 分页。添加或更新文件的调用仅在 `files` 中返回这些文件；移除文件、重命名知识库或更改其访问权限会返回空的 `files` 列表，因此请从此端点读取完整列表。
- `POST /api/v1/knowledge/{id}/file/move`：在同一 KB 内的目录之间移动文件（请求体：`file_id`、`directory_id`，其中 `null` 表示移动到 KB 根目录）。

**目录**

- `POST /api/v1/knowledge/{id}/dirs/create`：创建目录（请求体：`name`，可选 `parent_id`）。
- `POST /api/v1/knowledge/{id}/dirs/{dir_id}/update`：重命名目录或更改其父目录（请求体：`name` 和/或 `parent_id`）。
- `DELETE /api/v1/knowledge/{id}/dirs/{dir_id}/delete?move_files=true`：删除目录。`move_files=true`（默认）时，所含文件会重新指定父目录；`move_files=false` 时，文件会随目录一起删除。

**增量目录同步**

- `POST /api/v1/knowledge/{id}/sync/diff`：提交本地清单（`manifest: [{path, filename, checksum}]`，其中 `checksum` 是文件字节的 SHA-256），接收 `{added, modified, deleted, mkdir, rmdir, unmodified_count}`，准确说明要上传、替换、删除的内容以及要创建/移除的目录。该端点为只读，不会更改 KB。上传到 KB 不到一小时且仍处于待处理或处理中状态的文件，如果路径、名称和校验和匹配，会计为未修改，因此第二次同步不会再次上传。一小时后，它会再次列为可上传文件。
- 根据差异执行操作后（创建 `mkdir` 路径，通过 `POST /api/v1/files/` 上传 `added` + `modified` 文件及其哈希），调用：
- `POST /api/v1/knowledge/{id}/sync/cleanup`：请求体：`{file_ids: [...], dir_ids: [...]}`。移除过期文件（从 KB、向量存储和单文件集合中）以及 `sync/diff` 返回的目前已为空的目录。最后运行此调用，避免删除先于上传发生。

文件处理异步进行。必须轮询状态端点，直到处理完成后再将文件添加到知识库，否则会出现“空内容（empty content）”错误。有关工作流示例，请参阅 [API 端点](/reference/api-endpoints#retrieval-augmented-generation-rag)。

## 使用场景 {#use-cases}

### 项目文档 {#project-documentation}

将团队的技术规范、架构文档和运行手册上传到知识库，并附加到“项目助手”模型。AI 会根据你的实际文档回答问题，而不是依赖通用训练数据。

### 法律与合规审查 {#legal-and-compliance-review}

加载合同、政策和监管文档。要求 AI 查找特定条款、比较不同协议的条款，或标出不一致之处。

### 研究综合 {#research-synthesis}

将数十篇论文添加到知识库。AI 会跨所有论文搜索，以回答问题、查找支持性证据，或识别研究之间的矛盾。

## 限制 {#limitations}

### 完整上下文模式下的上下文窗口 {#context-window-with-full-context-mode}

**全文（Full text）**会注入整个文档。将大型文档附加到上下文窗口较小的模型时，会挤占对话历史的空间。

### API 上传的处理延迟 {#processing-delay-for-api-uploads}

通过 API 上传的文件会异步处理。在处理完成前尝试使用文件，可能会静默失败或返回空结果。请注意，使用 `knowledge_id` 上传（如上所述）会在服务器端建立关联，并能应对客户端断开连接，但**不会**让内容立即可查询：提取/嵌入仍在后台运行，因此在依赖检索之前，请轮询 `GET /api/v1/files/{id}/process/status`。

### 原生函数调用会改变行为 {#native-function-calling-changes-behavior}

原生函数调用是默认模式。它不会自动注入附加的 KB，因此模型必须调用知识工具进行检索。有关详细信息，请参阅[知识库故障排除](/troubleshooting/rag#13-knowledge-base-attached-to-model-not-working)。
