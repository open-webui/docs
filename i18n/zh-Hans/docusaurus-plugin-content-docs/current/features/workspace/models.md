**使用自定义指令、工具和知识包装任意模型，构建专用 agent。**

模型工作区可在任意基础模型之上创建配置预设。选择 GPT-5.6、Claude、Qwen 3.6 或连接到 Open WebUI 的其他任何模型，然后为其绑定系统提示词、知识库、工具、技能和参数覆盖值。无需修改底层模型，即可获得面向特定用途的 agent。

始终遵循你的风格指南的“Python 导师”、采用公司模板的“会议摘要助手”、内置代码检查规则的“代码审查员”。每个 agent 都是一层轻量包装：选择基础模型，完成配置，再与团队共享。

## 为什么使用模型？ {#why-models}

### 一个基础模型，多种角色 {#one-base-model-many-personas}

同一个 GPT-5.6 可以同时驱动编程助手、客户支持机器人和创意写作者。每个预设都有自己的系统提示词、工具和知识，因此模型会根据所选预设表现出不同的行为。

### 预先附加知识和工具 {#knowledge-and-tools-come-pre-attached}

无需在每次聊天中手动附加文档并启用工具，只需将它们绑定到模型预设一次。用户开箱即可获得配置完整的 agent。

### 精细的访问控制 {#granular-access-control}

可将模型限制为仅供特定用户或组使用。财务团队看到自己的模型，工程团队看到他们的模型。管理员控制整个实例中可用的内容。

读取权限允许用户与模型聊天，但不能查看其构建方式。在**工作区 > 模型**中，此类模型带有**只读**徽章，打开其编辑器会返回 `You do not have permission to edit this model`。Open WebUI 向该用户发送的数据不包含其系统提示词和其他参数。只有所有者、管理员（启用 `BYPASS_ADMIN_ACCESS_CONTROL` 时）以及拥有写入权限的用户才会收到这些内容。

### 动态系统提示词 {#dynamic-system-prompts}

使用 `{{USER_NAME}}` 和 `{{CURRENT_DATE}}` 等变量，让系统提示词自动适应每位用户和每个会话。大括号内不要带空格，否则带空格的形式会作为字面文本发送给模型。只有聊天和用户变量（`{{ chat.variables.x }}`、`{{ user.variables.x }}`）允许包含空格。

## 主要功能 {#key-features}

| | |
| :--- | :--- |
| **模型预设** | 将系统提示词、工具、知识、技能和参数整合在一个包中 |
| **动态变量** | 自动注入 `{{USER_NAME}}`、`{{CURRENT_DATE}}`、`{{CURRENT_TIME}}` |
| **绑定工具** | 为每个模型强制启用特定工具 |
| **附加知识** | 模型在每次聊天中使用的知识库、笔记和文件 |
| **技能** | 绑定 Markdown 指令集，使每个新聊天开始时都选中它们 |
| **访问控制** | 限制为特定用户或组 |
| **全局默认值** | 一次性为所有模型设置基线能力和参数 |
| **模型控制** | 让用户直接在聊天中从经过批准的参数预设中选择，例如思考强度 |

| **翻译** | 按语言设置名称、描述和提示词建议 |
| **版本历史** | 保留每次保存的配置，任意版本都可重新设为线上版本 |

## 创建模型 {#creating-a-model}

选中**模型**标签页时，点击**工作区**标题栏中的**创建**，或点击现有模型的名称以在编辑器中打开它。名称旁的箭头会在新聊天中打开该模型。

### 编辑器布局 {#editor-layout}

编辑器打开后，顶部是横幅标题：背景图像填满横幅，模型图片、名称和 ID 叠加在其下缘。下方依次为描述、基础模型、标签和系统提示词。已保存的系统提示词会折叠为简短预览；点击预览或**显示更多**即可编辑。系统提示词旁的**比较修订**会在空白的**建议修订**窗格旁打开原提示词。将修订版本粘贴到该窗格中，点击**比较**标记更改，再使用箭头逐项查看。**应用到草稿**会将右侧窗格的内容写入系统提示词；对于不需要的更改，使用 **Original →** 将其放弃，该操作会把此更改的原始文本复制到右侧窗格。对于替换文本的更改，**保留两者**会将原始文本和建议文本依次放入右侧窗格。随后保存模型。

其他所有内容均按行排列，每项设置占一行，点击即可展开。

- **开关**：**功能**、**默认功能**和**内置工具**展开后显示开关。将鼠标悬停在开关标签上即可查看其作用。
- **选择器**：**知识**、**工具**、**技能**、**过滤器**和**操作**会打开可搜索的选择器。**清除**会移除所有已选项目，**管理**会打开创建这些项目的工作区页面。**全部启用**会选择与搜索条件匹配的所有项目（知识选择器中的对应按钮为**上传文件**）。标记为**全局**的项目始终开启。工具、技能、过滤器、操作和子 agent 会在名称下方显示各项描述。列表为空时，选择器会指出可添加项目的工作区页面。
- **高级参数**会显示你更改的参数数量（**已修改 N 项**），未更改时显示**默认**。
- **提示词**包含模型的提示词建议。
- **语音**包含实时语音、语音头像和 TTS 语音。

编辑器通过**保存并更新**保存（新模型为**保存并创建**）。编辑现有模型时，按钮旁会显示**描述此更改**字段。**保存并创建**始终可用；只有内容发生变化后，**保存并更新**才会变为可用。

### 核心配置 {#core-configuration}

| 字段 | 描述 |
| :--- | :--- |
| **头像** | 上传自定义图像。支持动画 GIF 和 WebP |
| **背景** | 显示在编辑器横幅中，并在使用此模型时显示在聊天后方的图像。将鼠标悬停在横幅上，然后使用**添加背景**、**更改**或**移除**。图像必须在此处上传，因为只接受当前实例保存的文件；外部 URL 或粘贴的 data URI 会被直接拒绝。支持 PNG、JPEG、WebP 或 GIF，最大 5 MiB 和 2500 万像素 |
| **名称和 ID** | 显示名称和唯一标识符。ID 不能包含空白字符（空格、制表符或换行符），最多 256 个字符。编辑器会拒绝空白字符并显示 `Model ID cannot contain whitespace.`；API 会拒绝这两种情况并显示 `The model id is too long. Please make sure your model id is less than 256 characters long.`。导入时会跳过任何 ID 不符合这些规则的模型。新模型的 ID 根据名称生成：转为小写，将空格替换为连字符，移除 a 至 z、0 至 9 和连字符之外的其他字符。编辑名称会重写 ID，因此请最后修改 ID。模型保存后无法再更改 ID |
| **基础模型（来源）** | 实际驱动此 agent 的模型。管理员可以在此选择隐藏模型。其他用户只有拥有[**隐藏模型**](/features/authentication-access/rbac/permissions#1-workspace-permissions)权限时才能在此列表中看到隐藏模型，该权限默认关闭。隐藏模型仍不会出现在他们的聊天模型选择器中。此权限仅改变此列表，不改变谁可以使用隐藏模型。个人 Tether 模型不会出现在此选择器中 |
| **描述** | 显示在模型选择器中的简短摘要 |
| **标签** | 在下拉菜单中整理模型 |
| **提供方详情** | 仅限管理员。显示提供方的模型列表为该模型报告的信息：输入和输出、上下文窗口、最大输出及支持的参数。提供方未给出某个字段时显示**未提供**。提供方未报告任何字段时，此部分隐藏 |
| **访问权限** | 右上角的**访问权限**按钮用于设置谁可以使用模型：私有（特定用户/组）或公开。非管理员只有拥有[**模型共享**](/features/authentication-access/rbac/permissions#2-sharing-permissions)权限时才能看到此按钮。对于已保存的模型，每项更改都会立即保存，无需点击**保存并更新**。共享权限不允许的更改会被拒绝，并显示 "You do not have permission to share with the requested audience" |
| **语言** | 右上角**访问权限**旁的地球选择器，可将编辑器切换为名称、描述、提示词建议和模型控制的翻译。请参阅[翻译](#translations) |

![包含基础模型、描述和系统提示词的模型编辑器](/images/workspace/model-editor.png)

:::warning 已保存模型的 ID 中含有空格

现在，编辑器、API 和导入都会拒绝包含空白字符的 ID；导入时会跳过此类模型，而不是创建它。

ID 中已含空格的现有模型仍可响应请求，但保存模型或更改其访问授权会失败，因为两者都会经过相同的检查。请使用不含空白字符的 ID 重新创建模型，并删除旧模型。

:::

### 系统提示词和变量 {#system-prompt-and-variables}

系统提示词定义模型的行为和角色。要在使用重写后的系统提示词之前进行检查，请使用字段旁的**比较修订**（请参阅[编辑器布局](#editor-layout)）。可使用动态变量编写能够感知上下文的指令：

| 变量 | 输出示例 |
| :--- | :--- |
| `{{CURRENT_DATE}}` | `2024-10-27` |
| `{{CURRENT_TIME}}` | `14:30:05` |
| `{{USER_NAME}}` | `Admin` |
| `{{USER_GROUPS}}` | `Engineering, Beta Testers`（以逗号分隔，包括通过父组继承的组；用户不属于任何组时为空） |

```
You are a helpful assistant for {{USER_NAME}}.
The current date is {{CURRENT_DATE}}.
```

:::note 系统提示词是指令，不是保证

Open WebUI 不要求系统提示词采用特殊格式。纯文本、Markdown 列表和简短的结构化部分均可使用；Open WebUI 在此处处理的唯一特殊语法是受支持的变量，例如 `{{CURRENT_DATE}}` 以及聊天/用户变量。

助手遵循提示词的程度取决于所选的**基础模型**、提供方或本地服务器的聊天模板、完整的对话上下文，以及工具、文件、RAG、技能、记忆或过滤器添加的任何额外指令。如果提示词配置在正确位置但模型仍忽略规则，请与指令遵循能力更强的模型进行比较，并检查提供方/后端的请求格式，不要直接认定提示词需要另一种 Open WebUI 专用格式。

:::

:::tip 可感知组的系统提示词
`{{USER_GROUPS}}` 允许单个共享模型根据调用方的 RBAC 组调整行为，例如：*“仅当 `{{USER_GROUPS}}` 包含 'Engineering' 时，才可讨论内部路线图事项。”* 占位符会在聊天时由服务器解析，只有模板实际引用该变量时才会查询数据库。
:::

### 能力和绑定 {#capabilities-and-bindings}

在选择器行中绑定资源：

| 设置 | 控制的内容 |
| :--- | :--- |
| **知识** | 附加知识库、笔记或文件，这也会[将模型的知识搜索范围限制在这些内容中](/features/workspace/knowledge#scoped-access-keeps-things-organized)。选择器中的**上传文件**可直接从计算机添加文件。点击已附加的项目并使用其**全文**开关，可在相关片段与整个文件之间选择。请参阅[检索模式](/features/workspace/knowledge#retrieval-modes) |
| **工具** | 强制启用特定工具（例如为数学机器人启用计算器） |
| **技能** | 绑定[技能](/features/workspace/skills)。使用该模型创建的每个新聊天都会自动选中它们。请参阅[模型附加的技能](/features/workspace/skills#model-attached-skills) |
| **过滤器** | 附加管道过滤器（例如 PII 脱敏）。每个已附加的[可切换过滤器](/features/extensibility/plugin/functions/filter#toggleable-filters-making-filters-user-controllable-selftoggle)在选择器中都有**在新聊天中默认启用**开关，用于设置模型的默认过滤器。实例至少有一个过滤器函数后才会显示此行 |
| **操作** | 附加操作脚本（例如“添加到记忆”）。实例至少有一个操作函数后才会显示此行 |

在**功能**行及其后两行中切换模型可以执行的操作：

编辑器只显示可在当前实例上使用的选项，例如仅在网页搜索开启时显示**网页搜索**。隐藏选项会保留其已保存的值。

![模型编辑器中的功能和内置工具类别](/images/workspace/model-editor-capabilities.png)

| 设置 | 控制的内容 |
| :--- | :--- |
| **视觉** | 启用图像分析（需要支持视觉的基础模型）。光栅图像（PNG、JPEG、WebP、GIF）会作为图像输入发送给模型；SVG 会作为文档读取，因此通过**文件上传**传递，模型处理的是其源文本。关闭视觉时，工具返回的图像会作为简短的 `[image]` 注释发送给模型。 |
| **网页搜索** | 启用已配置的搜索提供方 |
| **代码解释器** | 启用 Python 代码执行 |
| **终端** | 允许模型驱动已连接的 [Open Terminal](/features/open-terminal) 机器来运行命令和处理文件。默认开启。关闭时，聊天的机器绝不会提供给模型 |
| **图像生成** | 启用图像生成。开启且有多个可用的[图像模型](/features/chat-conversations/image-generation-and-editing)时，会显示**默认图像模型**行，用于选择此模型的聊天默认使用的图像模型，用户另行选择时除外 |
| **视频生成** | 启用[视频生成](/features/chat-conversations/image-generation-and-editing/video-generation)。开启且有多个可用的视频模型时，会显示**默认视频模型**行，用于选择此模型的聊天默认使用的视频模型，用户另行选择时除外 |
| **用量** | 要求提供方在流式回复中报告令牌数量（`stream_options.include_usage`）。默认关闭。大多数 OpenAI 兼容提供方只有收到请求才会报告，因此不开启时，响应没有可显示的令牌数据，也无法在[分析](/features/administration/analytics)中汇总 |
| **引用** | 显示回复背后的来源，包括知识、文件检索以及返回来源的内置工具。默认开启；关闭时不显示来源。在 Native 模式下，网页搜索结果不属于来源，请参阅 [Agentic Search](/features/chat-conversations/web-search/agentic-search) |
| **状态更新** | 显示回复在处理过程中发出的进度行，例如网页搜索步骤。默认开启 |
| **记忆** | 控制是否将用户保存的记忆注入此模型的上下文（默认开启）。对于应在无个人上下文的情况下回答的模型，请关闭此项；它不会删除任何内容，并且与**记忆**内置工具类别相互独立，后者用于让模型自行读取和写入记忆 |
| **内置工具** | 该能力开关用于整体启用内置工具。开启时，**功能**下方的**内置工具**行控制可用的工具类别，请参阅[内置系统工具](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)。只有相应功能开启时才会显示某个类别 |
| **子 agent** | 启用**子 agent** 内置工具类别时显示：列出此模型可以将[子 agent](/features/chat-conversations/chat-features/subagents)工作转交给哪些模型。用户只能获得列表中自己有权访问的模型。留空时，子 agent 在当前模型上运行 |
| **文件上传** | 控制是否允许在消息中附加文件。默认开启；关闭时，使用此模型的聊天会拒绝上传，并且此编辑器中的**预加载文件**会消失，因为没有可提取的内容 |
| **预加载文件** | 启用时，附加文件会通过 RAG 处理并注入对话。禁用时，不注入任何内容，模型使用内置**文件**工具读取附加文件。使用 Native 函数调用时默认关闭，使用 Legacy 时默认开启；编辑器和**模型默认值**会显示实际生效的值 |
| **默认功能** | **功能**正下方的一行列出**网页搜索**、**图像生成**、**视频生成**和**代码解释器**，各项仅在相应能力开启时显示。在此开启的功能会在使用该模型的每个新聊天中默认启用；用户仍可按聊天关闭 |
| **默认机器** | **终端**开启时显示：与此模型聊天时默认选择的[机器](/features/open-terminal/setup/connecting)。每个模型使用独立实例的机器需要拥有该模型的访问权限 |
| **TTS 语音** | 位于**语音**行：此模型回复使用的特定语音 |

:::info 用量设置覆盖模型运行的所有聊天
令牌数量请求由服务器端添加，因此无论模型在哪里使用都会生效：聊天界面、API，以及 Open WebUI 通过[自动化](/features/chat-conversations/chat-features/automations)、[计时器](/features/chat-conversations/chat-features/timers)、[子 agent](/features/chat-conversations/chat-features/subagents)和[频道](/features/channels)代你启动的聊天。无需按请求设置。该设置仅影响流式请求，因此关闭**流式聊天响应**的模型不受影响。
:::

### 语音头像 {#voice-avatar}

**语音**行提供**语音头像**设置；管理员将**通话模式**设为**实时**时，还会显示**实时语音**。**语音头像**可在两种通话模式下为模型提供用于语音通话的动画 3D 角色，并支持可选的动画和手势。设置方法和文件要求请参阅[语音头像](/features/chat-conversations/chat-features/voice-mode#voice-avatars)。

### 高级参数 {#advanced-parameters}

**高级参数**行会显示此模型更改的参数数量，例如**已修改 2 项**；点击后打开完整列表。

- **停止序列**：遇到特定字符串时强制停止生成（例如 `<|end_of_text|>`、`User:`）。使用一个文本字段，以逗号分隔。
- **Temperature、Top P 等**：调整创造性和确定性。
- **上下文压缩阈值**：设置此模型自己的[上下文压缩](/troubleshooting/context-window#the-built-in-option-context-compaction)阈值。仅在上下文压缩开启时显示。

此处设置的值适用于所有未自行设置相同参数的聊天。用户在聊天的**模型控制 > 控制**或自己的**设置 > 常规**中设置某个参数，以及 API 调用方在请求中发送某个参数时，都会使用各自的值。请参阅[聊天参数](/features/chat-conversations/chat-features/chat-params)。

### 模型控制 {#model-controls}

模型控制为用户提供一些简单的聊天选项，例如模型思考的强度或回答的长度，而你可以精确决定每个选项发送哪些参数。例如，名为**思考**的控制可提供 Minimal、Low、Medium 和 High 选项，分别将 `reasoning_effort` 设为对应值，让任何人都能调整推理强度，而无需知道该参数的存在。

任何拥有模型写入权限的人都可以定义其控制，入口位于**工作区 > 模型**或**设置 > 模型**（管理员区域）。使用**高级参数**下方的**模型控制**行：**+** 添加控制，**编辑**修改控制，**×** 删除控制，左侧手柄用于调整顺序。每行会显示控制的默认选项。

控制随模型保存，并应用于所有可以使用该模型的人。可以编辑模型的人能在编辑器、JSON 预览和导出内容中看到每个选项背后的参数。只能使用模型的人只能看到名称、描述和选项名称，这些内容均可翻译（请参阅[翻译](#translations)）。

![“思考”控制的编辑对话框，以滑块显示；Minimal、Low、Medium 和 High 选项分别设置 reasoning_effort](/images/features/models/model-controls-edit.webp)

| 字段 | 作用 |
| :--- | :--- |
| **名称** | 用户在聊天中看到的标签，例如**思考** |
| **默认选项** | 用户尚未选择任何内容时应用的选项。选择**无**时，在用户选择某个选项之前，该控制不会发送任何内容 |
| **描述** | 显示在聊天中的可选帮助文本 |
| **显示方式** | **菜单**以列表形式显示选项。**滑块**按此处列出的顺序将选项显示为滑块上的步骤，且至少需要两个选项 |
| **选项** | 每个选项都有一个名称以及一对或多对**参数**和**值**，通过**添加参数**添加。拖动手柄可调整选项顺序 |

选项参数的工作方式与**高级参数**中通过**添加自定义参数**添加的参数相同：参数名会按原样发送给提供方；可按 JSON 解读的值（数字、`true`、对象）会以对应类型发送，其他值则作为文本发送。一个选项包含多个参数时，所有参数会一起发送。对于 Ollama 模型，它们最终位于 Ollama 的 `options` 中，但 `think`、`format` 和 `keep_alive` 除外，这三项位于请求顶层。模型自身设置的 `think`、`format` 或 `keep_alive` 仍优先于控制；如果需要由控制驱动这三项，请不要在模型上设置它们。

在管道函数驱动的模型或路由器模型上保存控制会失败，并显示 **Model controls require a server-managed provider model.**

#### 在聊天中使用模型控制 {#using-model-controls-in-chat}

所选模型具有控制时，消息输入框的模型选择器旁会出现旋钮图标（**模型控制**）。点击后会打开一个面板，列出每项控制及其当前选择。**滑块**控制通过移动滑块更改；下方的**默认 · Medium**（默认选项名称）可用于恢复默认值，描述位于 **?** 图标后。**菜单**控制会打开一个列表，其中包含描述、**默认 · Medium** 和所有选项。

![聊天中的模型控制，“思考”滑块设为 High，“详细程度”滑块使用默认值 Balanced](/images/features/models/model-controls-slider.webp)

![聊天中以菜单显示的模型控制，“思考”子菜单已打开，Low、Medium 和 High 上方显示“默认 · Medium”](/images/features/models/model-controls-menu.webp)

只要所选模型具有控制，并且用户有权使用[控制](/features/chat-conversations/chat-features/chat-params)，该图标就会显示。任何拥有模型访问权限的人都可以选择其选项，无论其**允许聊天控制**和**允许聊天参数**[权限](/features/authentication-access/rbac/permissions#3-chat-permissions)如何设置。这样，管理员可以通过模型控制提供经过筛选的选项（例如思考级别），同时继续对用户隐藏**控制**和原始参数。选择两个模型时，每个模型的控制都会显示在其名称下，并且各自保存独立的选择。

- **选择按模型保存到账户。** 选择某个选项后会立即保存，并应用于该模型的所有新旧聊天以及所有设备，直到用户选择其他内容。
- **默认值跟随模型。** 勾选**默认**时，每条消息都会发送默认选项的参数；默认选项为**无**时，该控制不发送任何内容。如果之后有人更改默认选项，所有选择**默认**的用户都会随之更新。
- **已选选项会覆盖其他位置的相同参数。** 其值优先于模型的**高级参数**、[全局模型默认值](#global-model-defaults-admin)、用户的**设置 > 常规**和聊天的**控制**。如果两个控制设置相同参数，列表中位置较低的控制优先。
- **已移除的选项会阻止模型，直至重新选择。** 如果编辑者删除了某人选择的选项，该用户向模型发送的消息会失败并显示 `Model control <key>: the selected option is no longer available.`，直到其选择其他选项或**默认**。已删除控制的选择会被跳过。
- **自动化使用默认值。** [自动化](/features/chat-conversations/chat-features/automations#model-settings-used-by-a-run)使用每个控制的默认选项。默认值为**无**时，底层参数设置保持生效。

API 调用方也可以使用相同的控制。请求如何选择选项，请参阅 [Chat Completions](/reference/api-endpoints#chat-completions)。

### 提示词建议 {#prompt-suggestions}

用户使用此模型打开新聊天时显示的可点击起始短语。添加“逐步解释这段代码”或“总结这份文档”等短语来引导用户。它们可以按语言翻译，请参阅下文。

这些建议位于**提示词**行。选择**默认**时，模型显示[全局模型默认值](#global-model-defaults-admin)中的实例级建议；**自定义**可为模型设置独立列表，并摘要显示为**自定义**及建议数量；**使用默认值**则恢复为实例级建议。

### 翻译 {#translations}

名称、描述、提示词建议和[模型控制](#model-controls)的名称都可以按语言分别设置版本。这样，使用德语界面的 Open WebUI 用户会看到德语模型名称和德语起始短语，而其他人仍看到原始文本。

从编辑器右上角的地球选择器中选择语言，编辑器就会切换为编辑该语言，原文显示为占位文本。随后，**模型控制**行列出每个控制名称、描述和选项名称供翻译。用户会看到与自己界面语言匹配的版本；未翻译的内容则显示原文。

同样的机制也适用于工具、技能、函数、横幅和[路由器模型](/features/administration/router-models)。完整说明（包括如何翻译 valve 标签）请参阅[翻译](/features/administration/translations)。

### 版本历史 {#version-history}

每次通过**保存并更新**更改模型配置都会保留为一个版本，同时保存按钮旁**描述此更改**中输入的文本。模型编辑器顶部**返回**旁的版本选择器默认显示**生产版本**，即聊天使用的配置。打开后可查看已保存版本，最新版本优先，每页 20 个；每个版本均显示作者和描述（描述留空时显示简短版本 ID）。任何可以编辑模型的人都可以使用它，入口包括**工作区 > 模型**，以及已保存设置的模型在**设置 > 模型**（管理员区域）中的页面。

![模型编辑器中的版本选择器已在“返回”旁打开，列出生产版本及按描述显示的旧版本](/images/features/models/model-version-history.webp)

- 选择版本即可**打开版本**。编辑器以只读方式显示该版本。
- **设为生产版本**会将打开的版本设为线上配置。如果编辑器中有未保存的更改，会先要求你确认，因为这些更改将被丢弃。
- 版本 **⋯** 菜单中的**删除**会移除该版本。生产版本无法删除。基于已删除版本保存的后续版本会重新链接到其父版本，因此版本链保持完整。

一个版本包含名称、基础模型、系统提示词、参数和编辑器的其余设置，例如描述、标签、能力、提示词建议，以及绑定的知识、工具、技能、过滤器、操作和机器。访问设置、**隐藏模型**和**启用**开关属于线上模型，切换版本时会保留当前值。每个现有模型都以升级时创建的一个版本开始。

将版本设为生产版本时，系统会检查它引用的所有内容，因为旧版本可能引用此后已删除或你无法访问的内容。出现以下情况时，线上配置保持不变，切换会被拒绝：

- 其基础模型不再可用。
- 它绑定的知识库、知识文件、笔记、技能、工具或机器缺失或你无权访问。
- 它绑定的过滤器或操作函数缺失或已关闭。
- 其背景图像或语音头像文件不再可供你访问。

要继续，请恢复缺失项目或获得其访问权限，或者选择其他版本。

API 也提供相同的操作，每个请求均使用 `?id=` 指定模型 ID：`GET /api/v1/models/model/history`（通过 `&page=` 分页）、`GET /api/v1/models/model/history/{history_id}`、带 `{"version_id": "..."}` 的 `POST /api/v1/models/model/update/version`，以及 `DELETE /api/v1/models/model/history/{history_id}`。通过 `POST /api/v1/models/model/update` 保存时，可提供可选的 `commit_message`。

### 启用和禁用 {#enabled-and-disabled}

你可编辑的行还带有**启用**开关，在**工作区 > 模型**和**设置 > 模型**（管理员区域）中均如此。关闭后，该模型会从所有人的模型列表中移除：它不再出现在选择器中，指定该模型的请求会失败并显示 **"Model not found"**。不会删除任何内容，其他所有模型保持原位；重新开启后，该模型会立即恢复。

**隐藏**是更轻量的选项。它会将模型保留在列表中，只将其从选择器中移除，因此隐藏的基础模型仍能驱动基于它构建的预设。隐藏模型仍会从 `/api/models` 返回，其中 `info.meta.hidden` 设为 `true`，并且仍会响应明确指定它的 API 请求。

### 导入和导出 {#import-and-export}

- **导入**：从 `.json` 文件或 Open WebUI 社区链接导入
- **导出**：将所有你可编辑的自定义模型下载为单个 `.json`，不受搜索框或筛选器当前显示内容影响。启用 `BYPASS_ADMIN_ACCESS_CONTROL` 时（默认启用），管理员可获取所有自定义模型
- **发现**：在页面底部浏览社区预设

模型的背景图像会随模型一起迁移。导出会将图像包含在文件中，导入会将其作为新上传的文件存储在目标实例上，因此在实例之间移动模型时，无需手动移动文件即可保留背景。导出和导入调用请参阅 [API 端点参考](/reference/api-endpoints)。

如果模型的 ID 已被你无法编辑的模型占用，导入会停止并显示 **Uh-oh! This model id is already registered. Please choose another model id string.** 文件中排在它之前的模型会被导入。

:::info 下载基础模型
要下载新的基础模型，请前往**设置 > 连接**（管理员区域），打开 Ollama 连接上的**管理**，或在模型选择器中输入 `ollama run hf.co/{username}/{repository}:{quantization}`。
:::

## 全局模型默认值（管理员） {#global-model-defaults-admin}

管理员可以在**设置 > 模型**（管理员区域）中设置应用于所有模型的基线能力和参数。点击列表顶部的**模型默认值**打开该页面，并使用页面上的**保存**按钮保存。它使用与模型编辑器相同的行：**模型能力**包含**功能**、**默认功能**和**内置工具**行，**工具**选择器设置默认工具，**模型参数**包含高级参数，**提示词建议**包含起始短语。

- **默认模型元数据**（`DEFAULT_MODEL_METADATA`）：基线能力（视觉、网页搜索、预加载文件、代码解释器、内置工具）。发生冲突时，模型级覆盖值始终优先。
- **默认模型参数**（`DEFAULT_MODEL_PARAMS`）：基线推理参数（temperature、top_p、max_tokens、function_calling）。模型级显式设置的值优先。此值从环境变量加载为 JSON；无效 JSON 会被忽略并回退到 `{}`。
- **工具**：对于没有自己工具列表的每个模型，在新聊天中默认启用的工具。拥有自己工具列表的模型会保留该列表。新模型表单初始会选中这些工具。
- **默认机器**：对于没有自己机器的每个模型，新聊天初始使用的机器。
- **提示词建议**：模型没有自己的建议时显示的起始短语。已有聊天记录的用户会在此处看到最近聊天，因此这些建议主要面向新用户。地球选择器可按语言翻译它们，方式与模型自己的建议相同。请参阅[翻译](#translations)。

这些设置适用于聊天补全。后台任务请求（标题、标签、后续问题、搜索查询、自动补全、上下文压缩摘要）不会经过这些设置；其参数在[任务模型](/features/administration/task-models)中单独设置。

### 合并行为 {#merge-behavior}

| 设置类型 | 策略 | 示例 |
|---|---|---|
| **能力** | 深度合并 | 全局设置 `file_context: false`，模型设置 `vision: true` > 模型同时获得两者 |
| **其他元数据** | 仅填充 | 全局设置描述，模型没有描述 > 模型获得全局值 |
| **参数** | 简单合并 | 全局设置 `temperature: 0.7`，模型设置 `0.3` > 模型获得 `0.3` |
| **自定义参数** | 按键逐项合并 | 全局添加 `service_tier`，模型添加 `tools` > 模型同时获得两者；名称相同时采用模型的值 |

自定义参数是通过**添加自定义参数**添加并存储在 `custom_params` 下的参数。只有这一组会逐项合并，因此模型定义自己的参数后，仍会同时保留全局参数。

**默认功能**和**内置工具**以整行为单位生效。模型在任一行保存自己的选择后，该选择就会替换对应的全局行。模型可以关闭**模型默认值**开启的任何默认功能；**模型默认值**关闭的内置工具，在模型自行开启后仍会为该模型启用。

:::info 请求中设置的参数会保留自己的值
两层默认值都只填充请求未提供的内容。[聊天补全](/reference/api-endpoints#chat-completions)请求正文中发送的参数会被保留，因此自行发送 `temperature` 或 `max_tokens` 的集成会获得其请求的值，而不是模型保存的值。唯一的例外是**流式聊天响应**，无论请求如何设置，它仍决定回复是否采用流式传输。
:::

:::warning 知识库与函数调用的交互
在全局参数中设置 `function_calling: native` 会改变**所有**模型处理附加知识库的方式。在原生模式下，模型附加的知识库不会自动注入。模型必须调用内置工具来检索知识。如果知识库突然停止工作，请先检查全局默认值。

请参阅[知识库故障排除](/troubleshooting/rag#13-knowledge-base-attached-to-model-not-working)。
:::

### 批量管理 {#bulk-management}

管理员模型列表默认打开**可用**视图：显示当前连接提供的每个基础模型，以及每个工作区模型。**不可用**列出连接不再提供但仍保存有设置的基础模型，例如提供方停用模型或连接被移除后的情况。**全部**同时显示两者。

每个模型的省略号（**...**）菜单以两种操作之一开头，两者都会先要求确认：

- **重置**显示在连接仍提供的基础模型上，将该模型已保存的设置恢复为默认值。模型仍保留在列表中。
- **删除**显示在工作区模型和不可用基础模型上，将模型及其已保存设置从列表中移除。

可按状态（已启用、已禁用、可见、隐藏、公开、私有、已选、已固定）筛选管理员模型列表，并使用**操作**菜单一次性启用、禁用、显示或隐藏当前视图中的所有模型。当外部提供方公开数百个模型时，这尤其有用。拖拽排序在筛选视图中同样有效：移动的模型会放在放置位置旁的可见模型旁边，被筛选器隐藏的所有模型则保持原位。

菜单将这些操作标记为**全部启用**、**全部禁用**、**全部显示**和**全部隐藏**。**全部隐藏**会将当前视图中的所有模型标记为隐藏，包括工作区模型，使它们从所有人的模型选择器中移除，管理员也不例外。即使视图中只有部分模型，提示消息也会显示 `All models are now hidden`。在同一视图中使用**全部显示**可一步撤销，但它也会显示此前已经隐藏的模型，因此如果某些模型是有意隐藏的，请先检查**隐藏**视图。**全部隐藏**不会更改**已选**或**已固定**模型设置，但新聊天选择模型时会跳过隐藏模型。如果所有模型都被隐藏，新聊天打开时不会选择任何模型。

每行会在模型名称旁显示**公开**、**共享**或**私有**。**公开**表示每位用户都有读取权限。**共享**表示特定用户或组拥有访问权限。**私有**表示模型没有任何访问授权。行内省略号（**...**）菜单中的**设为公开**和**设为私有**无需打开模型即可切换此状态。**设为私有**会移除所有访问授权，包括组和用户共享，而不仅是公开访问。在没有已保存设置的基础模型上使用**设为公开**，会为其保存一个条目。**私有**筛选器也会列出共享模型。

## 已选模型和固定模型（管理员） {#selected-and-pinned-models-admin}

这两项实例级设置决定用户初始使用哪个或哪些模型。它们此前称为**默认模型**；界面现在将其称为**已选**和**固定**模型。背后的配置键保持不变，因此现有环境配置仍可正常工作。

| 设置 | 菜单操作 | 作用 | 配置键 |
| :--- | :--- | :--- | :--- |
| **已选模型** | **设为已选模型** | 对于没有自己的模型偏好且没有[组默认模型](/features/authentication-access/rbac/groups#default-models-per-group)的用户，在新聊天中预先选择此模型 | [`DEFAULT_MODELS`](/reference/env-configuration#default_models) |
| **固定模型** | **设为固定模型** | 对于从未自行固定、取消固定或重新排序模型的用户，在侧边栏中将此模型显示为快捷方式 | [`DEFAULT_PINNED_MODELS`](/reference/env-configuration#default_pinned_models) |

两者都接受多个模型，因此你可以为用户提供一小组初始模型，而不是单个模型。

:::info 与模型默认值不同
同一页面顶部的**模型默认值**面板属于另一项功能：它为所有模型设置基线能力、参数和提示词建议。请参阅[全局模型默认值](#global-model-defaults-admin)。
:::

### 设置已选模型或固定模型 {#setting-a-selected-or-pinned-model}

1. 前往**设置 > 模型**（管理员区域）。
2. 使用**搜索模型**查找模型，或使用视图筛选器缩小列表范围。
3. 点击模型行末尾的省略号（**...**）。
4. 选择**设为已选模型**或**设为固定模型**。

![模型省略号菜单中的“设为已选模型”和“设为固定模型”](/images/features/models/model-row-menu.png)

更改会立即保存，无需单独执行保存步骤，模型名称旁会显示**已选**或**固定**标签。可对任意数量的模型重复此操作。要移除其中一项，请打开同一菜单并选择**移除已选模型**或**移除固定模型**。

:::tip 更快切换
在模型列表打开时按住 **Shift**，每行都会显示用于相同操作的内联图标按钮：眼睛切换可见性，对勾切换已选状态，图钉切换固定状态，地球或锁切换公开访问权限，铅笔打开模型。已固定的模型会显示带删除线的图钉，因为点击它会取消固定。松开 Shift 后，图标会再次隐藏。当通过 `Tab` 聚焦到某个按钮或链接时，按住 Shift 不会显示内联快捷操作图标，因此 `Shift+Tab` 仍可照常反向浏览列表。

![按住 Shift 后显示的内联快捷操作图标](/images/features/models/model-quick-actions.png)
:::

### 查看已配置内容 {#reviewing-what-is-configured}

打开视图筛选器（**操作**旁默认为**可用**的下拉菜单），选择**已选**或**固定**，即可只列出当前采用相应配置的模型。同一下拉菜单还可按全部、可用、不可用、已启用、已禁用、可见、隐藏、公开和私有筛选，并可按**基础模型**或**工作区模型**区分提供方提供的模型与在此基础上构建的模型。**路由器模型**列出管理员设置的[路由器模型](/features/administration/router-models)。

![包含“已选”和“固定”选项的视图筛选器](/images/features/models/model-view-filter.png)

### 用户的已选模型如何解析 {#how-a-selected-model-resolves-for-a-user}

对于新聊天，Open WebUI 会按以下顺序采用第一个能够产生用户实际可用模型的来源：

1. `model` 或 `models` [URL 参数](/features/chat-conversations/chat-features/url-params)。
2. 启动聊天所在文件夹绑定的模型（如果有）。
3. 用户在同一浏览器标签页中最后打开的已保存聊天所选的模型。Open WebUI 仅为该标签页保留这些模型，并将其用于一个新聊天，随后清除；因此此步骤会优先于**设为默认**一次。
4. 用户自己的默认模型，即在聊天中通过模型选择器的**设为默认**保存的模型。
5. [用户所属组的默认模型](/features/authentication-access/rbac/groups#default-models-per-group)，取自组层级中设置了默认模型的最深层组（并列时采用最早创建的组）。通过父组继承的组也计算在内。
6. 实例的**已选模型**。
7. 列表中的第一个可用模型。

第 4 至第 6 步也决定笔记和游乐场中的初始模型。

已隐藏或已移除的模型会在每一步被排除，因此最近使用的模型消失时，用户会获得一个可用模型，而不是空的选择器。

打开现有聊天时也遵循相同规则。聊天中已移除或用户不再有权访问的模型会从选择器中排除。如果没有剩余模型，聊天会按第 4 至第 7 步回退：用户自己的默认模型，然后是组默认模型或**已选模型**，最后是第一个可用模型。仅被隐藏的模型在该聊天中仍保持选中。

**固定模型**的工作方式不同：从未固定、取消固定或重新排序模型的用户，会在侧边栏中遵循实例的**固定模型**，因此之后对这些模型的更改仍会同步给该用户。用户首次固定、取消固定或重新排序模型时，当前列表会成为用户自己的列表，管理员的更改不再同步。用户通过取消所有固定而清空的自有列表会保持为空。指向隐藏或已删除模型、或用户无权访问模型的固定项仍保留在用户设置中，但不会显示在侧边栏中；模型恢复可用后，这些固定项也会恢复显示。

:::warning 已选只是起点，不是限制
将模型设为已选不会阻止任何人切换到他们有权访问的其他模型。要控制用户可以访问的内容，请使用按模型设置的访问控制或**隐藏**，具体说明请参阅[定制界面部署](#curated-interface-deployments)。
:::

## 在聊天中切换模型 {#model-switching-in-chat}

在对话中途切换模型不会丢失上下文。最多可同时选择两个模型进行并排比较，并使用箭头按钮在它们之间导航。模型选择器支持**搜索**，在**搜索模型**框中输入即可筛选长列表；自定义模型只有在其**基础模型**可用时才可选择。

在聊天模型选择器中，打开搜索框旁的**全部**并选择模型标签，即可仅显示具有该标签的模型。当相应连接类型可用时，同一菜单还提供**本地**和**外部**。每次可以应用一个菜单筛选器，同时仍可使用**搜索模型**按名称、ID 或标签缩小结果范围。选择活动筛选器旁的**清除筛选器**（×）即可返回**全部**。

![可搜索并显示固定模型的模型选择器](/images/features/chat/model-selector.png)

你也可以不打开选择器就切换模型。发送 `/model`，后跟模型 ID，例如 `/model gpt-5.1`，聊天就会切换到该模型；单独发送 `/model` 则会显示聊天当前使用的模型。ID 必须完全匹配，显示名称无效；无法访问的 ID 会报告 `Model not found`。从 `/` 菜单中选择**模型**，则会打开选择器并将焦点置于搜索框。其他内置斜杠命令请参阅[聊天功能](/features/chat-conversations/chat-features/)。

模型更改会立即随聊天保存，因此重新打开聊天时会使用该模型。切换会应用新模型的默认工具、技能、过滤器、功能和机器，同时保留你自行开启或关闭的内容。新模型无法使用的功能和过滤器会被关闭。向通过 `@` 选择的模型发送消息，会将聊天切换到该模型。

## 使用场景 {#use-cases}

### 团队专用 agent {#team-specific-agents}

创建一个“销售助手”，为其配置 CRM 知识库、异议处理提示词和电子邮件起草工具，然后与销售组共享。工程团队不会看到它。

### 新用户上手 {#onboarding-new-users}

构建带有描述性提示词建议的模型（“向我介绍公司的政策”、“帮我搭建开发环境”），让新团队成员确切知道可以询问什么。

### 实施组织标准 {#enforcing-organizational-standards}

设置全局默认值，在所有模型上禁用代码解释器、统一 temperature，或要求使用函数调用。各个模型可在需要时覆盖这些设置。

## 定制界面部署 {#curated-interface-deployments}

一种常见的部署模式是向普通用户展示定制模型（具有特定名称、图标、系统提示词和工具的预配置 agent），同时避免他们直接接触原始基础模型。

在选择方案之前，需要理解支配这一切的一条规则。

### 规则：自定义模型始终需要其基础模型的访问权限 {#the-rule-a-custom-model-always-requires-access-to-its-base-model}

你在**工作区 > 模型**下创建的每个模型都是*工作区模型*：它指向一个基础模型并存储对该模型的引用，而不是成为该基础模型的独立副本。创建工作区模型永远不会生成第二个独立的基础模型，它始终位于现有基础模型之上。

用户运行工作区模型时，Open WebUI 会同时检查对工作区模型**和**其底层基础模型的访问权限。如果用户无法访问基础模型，即使工作区模型已公开共享给该用户，请求仍会失败并显示 **"Model not found"**。

对于非管理员，基础模型只有在**设置 > 模型**（管理员区域）中具有已保存条目时才可访问。直接来自连接且从未在该处保存的基础模型仅限管理员使用。基于它构建的工作区模型可供管理员使用，也仍会显示在其他用户的模型选择器中，但这些用户使用时会失败并显示 **"Model not found"**。服务器日志会将原因标记为 `reason=base_model_unregistered`；如果基础模型有条目但用户无法读取，则标记为 `reason=base_model_read_denied`。要解决此问题，请在**设置 > 模型**（管理员区域）中基础模型的省略号（**...**）菜单里选择**设为公开**。这会为基础模型保存一个条目，并授予每位用户读取权限。如需仅向某些组开放，请随后更改其**访问权限**。如果不希望用户直接选择它，再按下文所述将其**隐藏**。

这是有意设计的行为。否则，任何人都可以在受限基础模型上构建工作区模型并公开共享该包装，从而绕过基础模型的访问控制。共享的包装绝不能授予基础模型未给予的访问权限。

:::warning
如果你此前依赖工作区模型向用户提供他们原本无法看到的基础模型，那么这依赖的是一个已经修补的访问控制缺口。该方式已不再有效，而且从来都不是安全的做法。
:::

实际结果是：任何应使用定制模型的人都必须同时拥有其基础模型的访问权限。你需要对这些用户**隐藏**基础模型，而不是限制他们访问基础模型。

### 推荐：在隐藏的公开基础模型之上构建定制模型 {#recommended-a-hidden-public-base-model-with-a-curated-model-on-top}

这是为所有人提供单一定制体验的可靠方式：

1. 将基础模型（例如“GPT-5.6”）设为**公开**，使所有目标用户都能通过基础模型访问检查。
2. **隐藏**基础模型（省略号 **...** > **隐藏**），使其不出现在模型选择器中。
3. 在该基础模型之上创建定制工作区模型。为其设置独立名称、头像、系统提示词、知识和工具，然后与用户共享（或保持公开）。

普通用户现在只能在选择器中看到定制模型。基础模型在底层仍可访问，这是定制模型能够运行的前提，但它不会显示在列表中。管理员仍可通过直接 URL 打开隐藏的基础模型。

:::tip 升级上游模型
迁移到更新的 LLM 时，请更新定制工作区模型上的基础模型选择，并重新指向基于旧基础模型构建的其他所有内容。**导出**和**导入**可帮助你在条目之间转移设置。
:::

### 如果部分用户还必须看到原始基础模型 {#if-some-users-must-also-see-the-raw-base-model}

**隐藏**是全局设置：隐藏的基础模型对所有人都隐藏，因此无法用它向高级用户显示原始模型，同时使其不出现在普通用户的选择器中。工作区模型也无法实现这一点，因为它会继承上述基础模型访问规则。

要让一个组在选择器中看到原始模型，而其他所有人只能看到定制模型，同一个上游 LLM 必须显示为**两个独立的基础模型**，各自拥有独立的访问控制。这需要在连接层配置（例如通过第二个连接添加模型），无法从**工作区 > 模型**创建。将一个基础模型条目限制为仅供高级用户使用，并将定制模型设为公开。由于两者都是基础模型，它们不会继承彼此的访问权限。

## 限制 {#limitations}

### 预设，而非微调 {#preset-not-fine-tune}

模型预设通过系统提示词和工具绑定来配置行为，不会修改底层模型权重。要实现深层次的行为改变，需要进行真正的微调。

### 回退需要配置 {#fallback-requires-configuration}

如果基础模型变得不可用，预设将会失败，除非将 `ENABLE_CUSTOM_MODEL_FALLBACK` 设为 `True`，并在**设置 > 模型**（管理员区域）中至少配置一个[已选模型](#selected-and-pinned-models-admin)。回退会使用第一个已选模型。
