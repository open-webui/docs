# 创建机器

**机器**是一个预先配置好的工作区，AI 可以在其中运行命令和处理文件。你可以直接从聊天中创建机器，为其命名并决定谁可以使用。每台机器会启动一个或多个**实例**，也就是实际运行命令的容器。

当 AI 需要一台真实计算机来运行代码、编辑文件或构建项目，并且每个人员或聊天都需要干净、独立的空间时，请使用机器。一台机器可以通过共享组服务于整个团队，也可以为每个用户、聊天或模型提供独立实例，使文件互不混杂。只需设置一次镜像、资源、起始目录和安装脚本，每个实例就会以相同方式启动。

管理员将 Terminals 服务器添加为连接，并向人员授予**写入**权限。拥有**写入**权限的人员可以创建和管理机器，其他人则使用共享给他们的机器。

## 连接访问权限 {#connection-access}

按照[连接到 Open WebUI](/features/open-terminal/setup/connecting) 和[身份验证](/features/open-terminal/terminals#authentication)部分中的说明，在**设置 > 集成**（管理员部分）中添加连接。连接表单包含名称、ID、URL、API 密钥、身份验证、**验证连接**、聊天上传、**访问权限**和**高级**选项。机器本身从聊天中创建，管理员也可以点击该列表中连接所在行的 **+** 创建（参见[创建机器](#create-a-machine)）。

连接的**访问权限**包含两种权限：

| 权限 | 允许用户执行的操作 |
| :--- | :--- |
| **读取** | 查看并使用共享给自己的机器 |
| **写入** | 在此服务器上创建和管理机器，并查看服务器上的每台机器 |

## 创建机器 {#create-a-machine}

1. 打开消息输入框中的机器菜单（云图标）。拥有**写入**权限时，即使尚未拥有机器，该菜单也会显示。
2. 在**机器**下，点击**新建机器**。
3. 填写对话框并点击**创建**。

管理员也可以在**设置 > 集成**（管理员部分）中执行此操作。Terminals 连接旁的 **+** 会打开同一个对话框，连接下方会列出其机器，每台机器都有用于打开设置的齿轮图标。这适合为他人配置的机器，例如随后要设为公开的机器。

| 字段 | 作用 |
| :--- | :--- |
| **名称** | 机器菜单中显示的名称 |
| **服务器** | 运行该机器的 Terminals 连接。仅在创建机器且有多个 Terminals 连接可用时显示 |
| **独立实例** | 一个开关。开启后，旁边的下拉菜单可选择**用户**、**聊天**或**模型**，初始选择为**用户**。关闭后，所有有权限的人员共享一个实例。参见[机器作用域](#machine-scope)。存在实例时该设置会锁定，因此必须删除所有实例才能更改 |
| **起始目录** | 位于**高级**下。命令开始运行的文件夹。必须位于主目录内，否则命令会在主目录中开始。存储为 `OPEN_TERMINAL_START_DIR` |
| **安装脚本** | 位于**高级**下。每次实例启动时，在就绪之前于起始目录中运行的 shell 脚本。重启之间仅保留主目录，因此脚本应能安全地重复运行。存储为 `OPEN_TERMINAL_SETUP_SCRIPT`。进度和失败信息（包括退出码和日志末尾）会显示在**系统信息**中 |
| **高级** | **起始目录**、**安装脚本**、**镜像**、**CPU**、**内存**、**存储**、**网络**和**环境变量**。空字段使用服务器默认值。值会根据服务器上限进行校验 |

新机器默认为私有。创建后，从机器菜单中打开**机器设置**，点击对话框顶部的**私有**按钮打开**访问权限**，即可与选定用户和组共享机器。管理员也可以将机器设为公开，与所有用户共享。共享访问权限仅供使用。

:::warning 写入权限可以访问他人的实例
对 Terminals 连接拥有**写入**权限的人员，可以打开该连接上任何正在运行实例的**系统信息**和文件，并可完全访问这些文件。请仅向可以托付所有人工作区的人员授予**写入**权限。
:::

有关原始值和保留键，请参阅[环境变量](/features/open-terminal/terminals/orchestration/environment-variables)；有关**镜像**字段，请参阅[自定义镜像](/features/open-terminal/terminals/orchestration/custom-images)。

有权访问机器的人员可以在其中运行命令。关闭**独立实例**时，所有有权限的人员共享一个实例；选择**模型**时，使用同一模型的所有人共享一个实例。他们会看到该实例的文件，因此仅应与获准查看这些文件的人员共享此类机器。

## 机器作用域 {#machine-scope}

| 独立实例 | 结果 |
| :--- | :--- |
| 关闭 | 使用该机器的所有人共享一个实例 |
| 开启，**用户** | 每个用户拥有自己的实例 |
| 开启，**聊天** | 每个已保存的聊天拥有自己的实例和文件 |
| 开启，**模型** | 每个模型拥有自己的实例 |

- **聊天**机器需要已保存的聊天。它可在已保存的聊天中使用，即在发送第一条消息之后。
- **模型**机器需要拥有该模型的访问权限。
- 能够在以**允许回复**方式共享的聊天中回复的人员，会使用该聊天自己的机器。
- 向频道发布内容的自动化无法使用**聊天**机器。

**聊天**和**用户**会增加正在运行的实例数量。请让管理员设置空闲超时，以清理已放弃聊天的实例，参见[空闲清理、生命周期与定时重置](/features/open-terminal/terminals/orchestration#idle-cleanup-lifetime-and-scheduled-resets)。

## 管理机器 {#manage-machines}

对话框中的**实例**列表会显示机器的每个实例及其名称，以及实例正在运行还是已停止。打开某一行的**更多选项**菜单即可对实例执行操作。正在运行的实例提供**重启**和**停止**，以及**系统信息**和**查看文件**。已停止的实例提供**启动**。每个实例都提供**删除实例**。操作执行期间，该行会显示当前状态和加载指示器（**正在重启...**、**正在停止...**、**正在启动...**或**正在删除...**）。**删除机器**会移除机器及其实例和文件。

## 机器菜单 {#machine-menu}

菜单中的每台机器都有**更多**菜单：实例运行时显示**重启**和**停止**，实例停止时显示**启动**。实例运行时还会列出**系统信息**和**查看文件**。**机器设置**始终可用。**查看文件**会打开该机器的[文件浏览器](/features/open-terminal/file-browser)，但不会将其选为聊天使用的机器。**系统信息**会显示 CPU、内存、磁盘和网络使用情况、运行时间及主要进程，并在打开期间每 5 秒刷新一次。

## 聊天 {#chats}

每个聊天都会保存其机器和工作文件夹，并在重新打开时恢复。未选择机器而保存的聊天，在打开时也不会选择机器。
