# 文件浏览器

连接 Open Terminal 后，[**选项卡**](/features/chat-conversations/chat-features/#tabs-side-panel)的**文件**选项卡中会提供一个**文件浏览器**。它的工作方式与计算机上的文件资源管理器类似。你可以浏览文件夹、打开文件、上传内容和下载结果。AI 创建的所有内容都会自动显示在这里。

![打开了“文件”选项卡的新聊天](/images/open-terminal-file-browser.png)

---

## 浏览 {#browsing}

点击文件夹进行导航，点击文件进行预览。顶部的面包屑栏会显示当前位置。点击路径可输入要打开的文件夹。

“选项卡”的 **+** 菜单中的**文件**会打开另一个文件选项卡，因此可以并排打开多个文件夹。每个文件选项卡以所显示的文件夹命名。

要选择多个文件，请从列表空白处拖出选择框。在触摸屏上，先将手指按住不动片刻，再开始拖动。

![通过面包屑导航浏览项目目录](/images/open-terminal-file-browser-project.png)

### 排序 {#sorting}

使用文件列表上方的工具栏，按**名称**、**大小**、**修改日期**或**添加日期**升序或降序排序。文件夹始终排在文件之前，因此排序只会在各组内部重新排列条目。按日期排序时，每行会在大小旁显示该日期，便于找到 AI 刚放入工作目录的最新输出。按**添加日期**排序需要终端能够报告文件的创建时间。

### 网格和列表视图 {#grid-and-list-view}

工具栏中的**操作**菜单（**...**）可在**列表视图**和**网格视图**之间切换。浏览器会记住你的选择。

## 预览文件 {#previewing-files}

在桌面设备上，将鼠标悬停在文件上会显示小型预览：文本文件最大 1 MB，其他文件最大 20 MB。

点击任意文件可查看完整预览。不同文件类型的显示方式不同：

:::info Word 和 PowerPoint 渲染需要较新的终端
这些文件由机器自行排版，需要运行默认镜像的 Open Terminal 0.12.1 或更高版本。否则，浏览器会绘制近似效果。如果预览比这里描述的更粗糙，请参阅[更新](./setup/updating.mdx)。
:::

### 文本和代码 {#text-and-code}

源代码和文本文件会在带语法高亮和行号的代码编辑器中打开。请参阅[编辑文件](#editing-files)。

![带语法高亮和行号的 Python 代码](/images/open-terminal-preview-code.png)

### PDF {#pdfs}

PDF 文档直接在浏览器中渲染，因此无需下载即可阅读。文档旁会显示带编号的页面**缩略图栏**；点击页面即可跳转。在狭窄面板中，缩略图栏会隐藏。

![带渲染 Markdown 预览的文件浏览器](/images/open-terminal-preview-markdown.png)

### 电子表格（CSV、TSV） {#spreadsheets-csv-tsv}

数据文件会渲染为带表头和整齐行的**格式化表格**，比原始逗号分隔文本更易阅读。

![渲染为整齐表格的 CSV 数据](/images/open-terminal-preview-csv.png)

### Excel 工作簿（XLSX、XLS） {#excel-workbooks-xlsx-xls}

`.xlsx` 和 `.xls` 文件以表格形式打开，每次显示一个工作表。包含多个工作表的工作簿会显示选择器，用于切换工作表。

你有权写入的 `.xlsx` 文件可以在预览中编辑。双击单元格或直接输入即可更改，也可以粘贴单元格区域。**保存**会将工作簿写回文件。公式单元格、表头和受保护的工作表保持只读。如果文件在打开后已在机器上发生更改，保存会停止并要求你重新加载，你的编辑则保留在编辑器中。

### Word 文档（DOCX） {#word-documents-docx}

`.docx` 文件由机器本身使用与办公套件相同的引擎排版，预览会显示完成后的文档。你看到的就是文件打印出来的效果：真实分页、页眉、页脚、脚注和尾注、嵌入图像、字体及间距。

文档旁会显示带编号的页面**缩略图栏**；点击页面即可跳转。页面会缩放以适应面板宽度。按住 **Ctrl**（macOS 上为 **Cmd**）滚动，可围绕指针缩放。

如果机器无法排版文档，浏览器会改为绘制，并在预览中说明效果可能与下载文件不同。这种渲染会保留文本、表格和图像，但无法精确匹配布局。只有这种方式也失败时，才会报告错误并建议改为下载文件。

### 演示文稿（PPTX） {#presentations-pptx}

`.pptx` 文件在**幻灯片查看器**中打开，每次显示一张幻灯片。机器使用与 Word 文档相同的方式渲染演示文稿，因此每张幻灯片都是完成后的效果：背景、填充、字体、间距，以及每个占位符从布局或母版继承的位置。

左侧会显示带编号的幻灯片**缩略图栏**；点击缩略图即可跳转到该幻灯片。在狭窄面板中，缩略图栏会隐藏。滚动可平移幻灯片；按住 **Ctrl**（macOS 上为 **Cmd**）并滚动可缩放；放大后可以拖动幻灯片。

如果机器无法渲染演示文稿，浏览器会改为绘制每张幻灯片的近似效果，并在预览中说明效果可能与下载文件不同。这种近似渲染支持单一系列条形图、折线图、饼图和圆环图，包括负值。堆积图、组合图和其他图表类型会显示**图表预览不可用**。需要精确渲染时，请在文件自己的应用程序中打开。

### Markdown {#markdown}

你有权写入的 Markdown 文件会在**富文本编辑器**中打开：直接编辑格式化文本，**保存**会将其以 Markdown 写回。数学公式、提示框和 Mermaid 图表会显示渲染结果；点击其中之一可编辑其源代码。粘贴或拖放到编辑器中的图像会上传到机器中 Markdown 文件所在的文件夹，并使用相对路径链接。**源码**切换到原始 Markdown 的代码编辑器，**编辑器**则切换回来。

只读 Markdown 文件会显示**渲染预览**，使用与聊天回复相同的渲染器，因此数学公式、脚注、高亮代码块、提示框和 Mermaid 图表都会显示。混入 Markdown 的 HTML 区块也会一起渲染，因此 `<details>` 部分和 `<div align="center">` 等包装元素中的 Markdown 内容会按格式显示。指向终端上另一个文件的链接会在浏览器中打开该文件。

在两种模式下，使用相对路径的图像都会从机器加载。

![带标题、表格和代码块的渲染 Markdown](/images/open-terminal-preview-markdown.png)

### 文档中的评论 {#comments-in-documents}

Word、Excel、PowerPoint 和 PDF 预览会显示文件中存储的评论及其回复，并锚定到它们在文档中的位置。将鼠标悬停在标记上可阅读评论串，在触摸屏上则可轻点标记。无法在预览中定位的评论会集中收纳在角落的计数器中。如果无法读取评论，预览会显示 **“Could not read comments. Download the original file to review them.”**（无法读取评论。请下载原始文件进行查看。）

### 图像 {#images}

图像会以舒适的大小内联显示。

![文件浏览器显示图像预览](/images/open-terminal-file-browser-home.png)

### 3D 模型 {#3d-models}

`.glb`、`.gltf`、`.stl`、`.obj` 和 `.ply` 文件会在 3D 查看器中打开。拖动可旋转，滚动可缩放；**重置视图**会将模型重新放入画面。纹理和材质文件从相对于模型的路径加载。

### HTML {#html}

HTML 文件在**沙箱化** iframe 中渲染。脚本和下载可以工作，但页面会被赋予独立的唯一来源，因此无法读取 Cookie 或 `localStorage`，返回 Open WebUI 的同源请求也会失败。

这种隔离正是目的所在：预览的文件属于不受信任的内容，赋予它你的来源会让它能够以你的身份操作。需要同源行为的页面会静默失败而不显示错误；当预览看似损坏但文件本身正常时，这通常就是原因。

如果你了解风险且确实需要，每用户的**设置 > 界面 > iframe 沙箱允许同源**开关可以授予此能力。它**默认关闭**，并应用于每个嵌入的 iframe，而不仅是此预览。完整取舍请参阅[富 UI](/features/extensibility/plugin/development/rich-ui#sandbox-and-security)。

## 上传文件 {#uploading-files}

将计算机上的文件或整个文件夹**拖放**到文件浏览器中即可直接上传。文件夹会保留其结构：机器上会重新创建每个子文件夹。工具栏和右键菜单中的**上传文件夹**会通过选择器完成相同操作。这就是与 AI 共享数据的方式：放入电子表格、PDF、图像或任何希望 AI 处理的文件。

![浏览器中列出的文件及其名称和大小](/images/open-terminal-file-browser-documents.png)

:::tip 上传到任意文件夹
先导航到目标文件夹，再拖放。文件会上传到你当前正在查看的目录。
:::

标记为**只读**的文件夹会关闭上传，将文件拖放到其中不会执行任何操作。

### 从聊天输入框上传 {#from-the-chat-input}

在聊天输入框中附加的文件通常会进入 Open WebUI，在那里提取文本供模型阅读。将连接的**聊天上传**设置为 `Filesystem` 后，文件会改为进入机器。附件随后会落在聊天的工作文件夹中（未设置时使用机器的默认文件夹），并像其他内容一样显示在这里。模型使用机器自己的工具打开它们。请参阅[聊天上传](/features/open-terminal/setup/connecting#chat-uploads)。

### 将终端文件附加到消息 {#attaching-terminal-files-to-a-message}

将文件从文件浏览器拖到消息输入框，即可将其附加到下一条消息。选择的多个文件会一起附加。在触摸屏上，长按文件后再拖动。文件保留在终端上，模型会获得其路径，与**聊天上传**设置为 `Filesystem` 时相同。这需要[允许文件上传](/features/authentication-access/rbac/permissions#3-chat-permissions)权限，并且一条消息中的所有终端文件必须来自同一终端。

## 比较两个文件 {#comparing-two-files}

使用复选框或 `Ctrl` 点击选择两个文件，然后选择**比较**。也可以先在一个文件的菜单中选择**选择用于比较**，再在另一个文件的菜单中选择**与所选文件比较**。两个文件会并排显示并标记差异。

文本文件会在只读比较视图中打开：使用箭头逐项查看更改，**交换两侧**可切换左侧文件，**刷新**会重新读取两个文件。**比较选项**菜单（**...**）提供**忽略空白**、**忽略强调标记**（跳过只添加或移除 `*` 和 `_` 的更改）以及**仅显示更改**（折叠大段未更改的行）。更改的行会按匹配文本对齐。此视图支持每个最大 2 MiB 的 UTF-8 文本文件。

文档（PDF、Word、Excel、PowerPoint、OpenDocument 和 RTF 文件）通过从中提取的**文本**进行比较，因此 Word 文件与 PDF、昨天的电子表格与今天的电子表格都可以比较。

:::info 需要较新的 Open Terminal
文档比较在机器上运行。如果机器不支持，浏览器会显示 **“File comparison is not available on this terminal. Update Open Terminal to use Compare.”**（此终端不支持文件比较。请更新 Open Terminal 以使用比较功能。）请参阅[更新](./setup/updating.mdx)。
:::

## 下载文件 {#downloading-files}

点击任意文件上的**下载按钮**，即可将其保存到计算机。这是取回结果的方式：AI 生成图表、创建电子表格、处理图像或撰写报告后，直接下载即可。

### 聊天消息中显示的文件 {#files-shown-in-the-chat-message}

AI 还可以将文件直接放入回复，无需你自行在浏览器中查找。要求将文件显示在聊天中后，消息会带有一张小卡片，其中包含文件名、内容预览，以及下载文件或在文件浏览器中打开文件的按钮。

预览支持与浏览器相同的格式，因此电子表格会显示为表格、图像显示为图片、PDF 显示为页面。卡片每次打开时都会使用你自己的访问权限从机器读取文件，因此没有任何内容被复制出机器，也不存在指向文件的公开链接。因此，卡片只有在其来源机器已连接并被选中时才有效，否则会报告机器不可用。

长文档可以直接打开到相关位置。对于 PDF、Word 文档或演示文稿，AI 可以指定所指的页面或幻灯片，预览会直接打开到那里，而不是开头。让 AI 提供答案来源页面后，文档会预先滚动到该位置，无需在数百页中寻找回复引用的段落。文件在浏览器而不是消息中打开时，也同样适用。

![AI 引用电缆额定值并打开手册第 132 页](/images/open-terminal-display-file-manual-page.png)

在这里，AI 搜索了一本 150 页的手册，引用找到的规格，并打开 PDF 第 132 页，以便在上下文中阅读该引文。

不知道要查看哪个文件时，工作方式也相同。询问哪份文档涵盖某项内容时，会先搜索文件夹，再将匹配文档打开到正确页面。

![AI 找到正确文档并打开相关页面](/images/open-terminal-display-file-report-page.png)

![CSV 和生成的图表以卡片形式显示在助手消息中](/images/open-terminal-inline-file-card.png)

演示文稿也以相同方式显示，带有幻灯片栏、页面控件和缩放功能，因此无需离开对话即可翻阅。

![在聊天消息中内联渲染的演示文稿](/images/open-terminal-display-file-deck-inline.png)

卡片标题是一个开关，因此当预览占用回复过多空间时，可以将其折叠为仅显示文件名；图像和文档预览还带有缩放控件和调整大小手柄。

默认由 AI 决定，并且除非 AI 要求使用卡片，否则它显示的文件会在文件浏览器中打开。**设置 > 界面 > 机器文件显示**可更改 AI 未明确指定时的行为：保持**侧边栏**以使用浏览器，或设置为**内联**以让文件显示在消息中。

![在聊天旁的文件查看器中打开的 Word 报告](/images/open-terminal-display-file-report-viewer.png)

## 编辑文件 {#editing-files}

文本和代码文件会直接在代码编辑器中打开：输入更改，然后点击**保存**或按 `Ctrl+S`（macOS 上为 `Cmd+S`）。这非常适合快速修正：编辑配置值、纠正拼写错误或微调 AI 生成的内容。拥有独立预览的文件（如 HTML、JSON 或 CSV）也可通过**源码**打开相同的编辑器。[Markdown](#markdown) 和 [Excel](#excel-workbooks-xlsx-xls) 文件在各自预览中编辑。

输入时，编辑器会建议文件中已经出现的词语；按 `Tab` 可接受建议。在 Git 仓库中，与上次提交相比，新增行的行号旁会显示绿色标记，更改行旁会显示琥珀色标记。

![直接在文件浏览器中编辑文件](/images/open-terminal-preview-code.png)

如果离开带有未保存编辑的文件（例如打开另一个文件或文件夹），系统会先要求你**保存**或**放弃更改**。

## 询问所选内容 {#asking-about-a-selection}

在打开的文件中选择文本后，旁边会出现**询问或编辑…**框。输入问题或指令并按 `Enter`。请求会进入聊天，同时附加文件并引用所选文本；如果存在对应页面或工作表，也会一并提供。模型在同一终端中处理该文件，因此可以回答相关问题或修改文件。

一次最多可以选择 16 KiB 文本。如果文件有未保存的编辑，系统会先要求你**保存并发送**。在回复仍在运行时发送的请求会进入聊天队列，并在回复完成后发出。

你可以直接在文件浏览器中创建新文件和文件夹，或删除不再需要的内容。文件夹的菜单中也有**新建文件**和**新建文件夹**。

## 只读文件和文件夹 {#read-only-files-and-folders}

某些文件和文件夹无法更改。文件浏览器会将其标记为**只读**，并将无法执行的操作置灰，让你在尝试之前就能发现，而不是事后才知道。

无法写入的文件夹会在顶部面包屑旁标记为**只读**。位于其中时，**新建文件**、**新建文件夹**和**上传**会置灰，将文件拖放到其中不会执行任何操作，其中的任何内容也无法重命名或删除。

无法更改的单个文件或文件夹会在名称旁标记为**只读**。其菜单中的**重命名**和**删除**会置灰，无法将它拖到另一个文件夹，其预览也无法编辑。如果一次选择多个项目，只要其中任意一个为只读，**删除**就会保持置灰。

只读仅限制更改，不影响其他操作。你仍可照常浏览、预览和下载这些文件。

## 工作目录 {#working-directory}

选择机器后，消息输入框中机器旁的**工作目录**按钮（文件夹图标）可选择聊天的工作文件夹。除正在生成回复时以外，随时可以更改，临时聊天中也是如此。对于每个聊天使用独立实例的机器，该按钮会在聊天保存后出现，临时聊天只提供其他机器。每个聊天都会保存其工作文件夹，并在重新打开时恢复。菜单提供搜索框、使用机器自身默认设置的**无文件夹**、你的**最近使用**文件夹，以及用于打开机器浏览对话框的**打开文件夹**。在对话框中，**使用此目录**会选择当前所在文件夹。**最近使用**行上的文件夹图标（同样标记为**打开文件夹**）会在文件选项卡中显示该文件夹。

**最近使用**会列出你在该机器上最近使用的八个文件夹。它们作为文件存储在机器主目录的 `.open-webui/users/<user id>/folders` 下，因此会随你同步到其他浏览器。任何能够读取该主目录的人都可以看到它们。

### 克隆仓库 {#cloning-a-repository}

当机器支持 Git 时，**打开文件夹**对话框和[文件夹设置](/features/chat-conversations/chat-features/conversation-organization#default-machine-and-working-directory)中的文件夹选择器会提供**克隆仓库**。输入 HTTP(S) 或 SSH 仓库 URL 后，仓库会克隆到当前文件夹内一个以仓库命名的新文件夹中，该新文件夹随后会成为所选文件夹。克隆在终端上运行 `git clone`，因此终端需要 Git、访问远程仓库的网络连接；对于私有仓库，还需要已在终端上配置凭据。Git 不会提示输入密码，SSH 主机也必须已在终端的已知主机列表中。

## Git {#git}

通过 Git 面板，你可以审查、提交和发布 AI 对项目所做的更改；对于 GitHub 仓库，还可以在不离开聊天的情况下处理 Issue 和拉取请求。当 AI 在你机器上的代码项目中工作时，可以使用它：检查更改、提交更改，然后一键将下一个 Issue 交给 AI；该操作会填写消息输入框，供你审查和发送。任何使用包含 Git 仓库的机器的人都可以使用它。

当文件浏览器中打开的文件夹位于 Git 仓库内时，文件选项卡底部会显示 **Git** 面板。它需要开启工具服务器，并使用支持 Git 的 Open Terminal。点击即可展开。

- **更改**：统一或拆分差异视图以及**隐藏空白**。可暂存、取消暂存或丢弃文件，使用摘要和描述提交，以及**撤销上次提交**。
  **放弃更改**适用于已暂存、未暂存和新文件。使用 **Ctrl** 或 **Shift** 点击（macOS 上为 **Cmd**）选择多个已更改文件可一起丢弃，也可使用“更改”菜单中的**放弃所有更改**。确认后，它会丢弃对文件的所有更改，并删除不在上次提交中的文件。
- **历史**：过去的提交及其差异。
- **Issue**，适用于机器支持时的 GitHub 仓库：搜索、按**开放**、**已关闭**或**全部**筛选，创建、编辑、评论、以已完成或不计划处理关闭，以及重新打开。
- **拉取请求**，适用于机器支持时的 GitHub 仓库：搜索、按**开放**、**已关闭**、**已合并**或**全部**筛选，创建、编辑、评论、批准、请求更改、关闭、重新打开、检出、更新分支和标记为就绪。拉取请求提供**摘要**、**代码**、**检查**和**活动**视图，并显示是否存在冲突。合并按钮带有**合并方法**菜单，提供**压缩并合并**、**创建合并提交**和**变基并合并**。

Issue 上的**处理此项**、失败检查上的**修复**、拉取请求上的**处理反馈**，以及存在冲突的拉取请求上的**在聊天中解决冲突**，都会将请求写入消息输入框。评论或审查（位于拉取请求的**活动**中或 Issue 上）上的**添加到聊天**会将该评论文本写入其中。审查并发送，即可将工作交给 AI。

分支菜单可切换、创建、重命名和删除分支，并管理 worktree。同步按钮会根据分支需要发布、拉取、推送或获取。暂存、推送、拉取和获取会显示进度。拖动文件列表旁的分隔条可调整其大小。有更改的文件会在文件浏览器工具栏中显示**显示差异**。

文件列表也会标记更改。已更改文件会按状态着色，并显示添加和移除的行数。已更改的二进制文件会显示状态字母，例如 `M`（已修改）或 `U`（未跟踪）。

## 使用须知 {#good-to-know}

:::tip 文件自动更新
AI 创建或更改文件时，文件浏览器会自动刷新，无需手动重新加载。
:::

:::tip 记住你的位置
切换聊天会在该聊天的工作文件夹中打开文件选项卡。选择另一台机器会将文件选项卡移动到该机器的工作文件夹。
:::

:::tip 实时更新
在报告实时事件的机器上，Git 面板和[浏览器选项卡](./use-cases/web-development.md#the-browser-tab)的**端口**列表会实时更新，**文件**选项卡也是如此：其显示的文件夹会在后台刷新，不显示加载动画，包括在聊天之外运行命令之后。文件选项卡中有文件打开时，会暂停这种实时更新。否则，Git 面板在展开时刷新，**端口**列表则提供**刷新**按钮。
:::

:::tip 终端位于下方
**文件**选项卡底部包含[终端窗格](./terminal-pane.md)，AI 运行的每个命令对应一个选项卡。
:::

:::tip 多个终端
如果连接了多台机器，在下拉列表中切换机器会更新文件浏览器，显示该机器的文件。
:::

:::info 为每个聊天提供独立文件的终端
一台机器可以为每场对话提供独立实例，使每个聊天拥有自己的文件。此类机器要求对话先存在：发送第一条消息后才会显示文件浏览器；新聊天会列出此类机器，但其文件和详情要在聊天保存后才会打开。临时聊天不会列出它。要在不选择机器的情况下浏览其文件，请使用其**更多**菜单中的**查看文件**。请参阅[创建机器](/features/open-terminal/terminals/orchestration/creating-terminals)。
:::
