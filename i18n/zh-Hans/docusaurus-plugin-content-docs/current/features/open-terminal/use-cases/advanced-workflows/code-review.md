# 自动化代码审查

让 AI 审查拉取请求、分支差异或文件，即可获得详细的代码审查结果，包括安全问题、性能问题、风格违规和改进建议。

> **你：** $代码审查员 <br/>
> 审查 `feature/auth-refactor` 分支相较于 `main` 的更改。

## AI 会执行哪些操作 {#what-the-ai-does}

1. 运行 `git diff main..feature/auth-refactor` 查看所有更改
2. 在完整上下文中阅读每个修改过的文件（不只是差异，还会理解周围代码）
3. 对发现的问题进行分类：安全、性能、正确性、风格、文档
4. 按从严重到细枝末节的顺序确定问题优先级
5. 通过代码片段提出具体的修复建议
6. 保存一份结构化的审查报告

## 技能内容 {#skill-content}

将以下内容复制到**工作区 → 技能 → 创建**：

```markdown
---
name: code-reviewer
description: 审查代码更改中的安全、性能、正确性和风格问题
---

## 代码审查

当被要求审查代码时：

1. **获取差异**：使用 `git diff`、`git log` 或阅读指定文件，了解发生了哪些更改
2. **阅读完整上下文**：不要只查看更改的行，还要阅读整个文件，理解周围逻辑、导入以及这些更改如何融入其中
3. **检查以下类别**：
   - **安全**：SQL 注入、XSS、硬编码凭据、缺少身份验证检查、不安全的反序列化、路径遍历
   - **正确性**：逻辑错误、差一错误、未处理的边界情况、竞态条件、缺少错误处理
   - **性能**：N+1 查询、不必要的循环、缺少索引、大额内存分配、异步代码中的阻塞调用
   - **风格与可维护性**：命名不一致、函数过于复杂、缺少 docstring、无用代码、魔法数字
   - **测试**：新代码路径缺少测试覆盖、边界情况未经测试
4. **确定问题的优先级**：
   - 严重：合并前必须修复（安全、数据丢失、崩溃）
   - 警告：应当修复（性能、正确性边界情况）
   - 建议：最好具备（风格、重构机会）
   - 细枝末节：可选（命名偏好、格式）
5. **对于每个发现的问题**：
   - 引用确切的文件和行号
   - 解释它为什么是问题（而不只是指出哪里有问题）
   - 提供具体的修复方法和代码片段
6. **撰写总结**：整体评估、按严重程度统计的问题数量、建议（批准/要求修改）

审查要全面而公正。认可良好的模式和编写出色的代码，而不只是指出问题。
```
