**让你的团队与 AI 实时共同思考。**

频道是持久的共享空间，人类和 AI 模型可以在其中参与同一对话。与私人且相互隔离的标准聊天不同，频道让多位用户和多个模型在单一时间线上互动。无论来自人类还是 AI，每一次交流都会成为整个团队可以继续利用的共享上下文。

Open WebUI 是发现、创造和分享知识的地方，而频道让这一过程支持协作。

---

## 为什么使用频道？ {#why-channels}

### AI 是参与者，而非独立工具 {#ai-as-a-participant-not-a-separate-tool}

标记 `@gpt-5.6` 起草计划，再标记 `@claude` 对方案进行批判性评审。整个团队都能在同一频道中看到两份回复。在一个讨论串中提问，第二个模型会读取第一个模型的回答。无需切换标签页，也无需在工具之间复制粘贴。

### 持久的共享记录 {#persistent-shared-record}

每条消息都会成为记录的一部分，团队可以在下周搜索和重读。你标记的模型只会读取它回复所在的讨论串，具体请参阅[模型读取的内容](#what-the-model-reads)。

### 多个模型，同一对话 {#multiple-models-one-conversation}

在同一频道中，用一个模型审查代码，用另一个模型写作，再用第三个模型分析数据。将它们串联起来，可以获得比任何单一模型都更丰富的回答。

### 实时协作 {#real-time-collaboration}

即时更新、表情回应、讨论串回复、置顶消息和未读指示器。

## 核心功能 {#key-features}

| | |
| :--- | :--- |
| **`@model` 标记** | 按需让任何 AI 模型加入对话 |
| **共享记录** | 每条来自人类或 AI 的消息都会保留在频道中，供团队搜索和重读 |
| **讨论串与表情回应** | 通过回复、置顶和表情回应让讨论井井有条 |
| **文件共享** | 拖入图片、文档和代码，AI 可以查看并处理它们 |
| **消息队列** | 在消息或文件上传仍在进行时继续发送：新消息会在输入框上方排队，可以编辑或移除，并按顺序发出 |
| **访问控制** | 公开、私有、基于用户组及私信频道 |
| **AI 频道感知** | 模型可以自主跨频道搜索和综合信息 |
| **[应用](/features/channels/apps)** | 外部服务加入频道、回复 `@mentions`，并发布带按钮的消息 |
| **[加密聊天](/features/channels/encrypted-chats)** | 在私信和私有群组中进行临时端到端加密对话，绝不会保存在服务器上 |

## 频道类型 {#channel-types}

| 类型 | 适用场景 |
|------|----------|
| **标准（Standard）** | 按主题划分的房间（`#engineering`、`#marketing-strategy`），可公开或私有 |
| **群组（Group）** | 面向团队的空间，具有明确成员关系并支持用户组同步 |
| **[私信（Direct Message）](#direct-messages)** | 私密的 1:1 或小群组对话，显示在线/离线状态 |

## 工作原理 {#how-it-works}

### 与 AI 对话 {#talking-to-ai}

频道默认处于**被动模式**。AI 不会主动加入每段对话。需要模型提供意见时，只需标记它：

> **你：** `@gpt-5.6` 这是我们第三季度的收入数据。有哪些显著趋势？
>
> *（GPT-5.6 分析数据并给出关键见解）*
>
> **你：** `@claude` 你同意这项分析吗？还缺少什么？

这样，你的团队可以自由讨论而不受 AI 打扰，并在需要时准确调用合适的模型。

#### 回复显示位置 {#where-the-reply-appears}

默认情况下，模型回复顶层提及时，会在你的消息下方**以讨论串形式**回复，避免长回答将频道对话挤出屏幕。管理员可以在**设置 > 通用（Settings > General）**（管理员区域）中更改此行为（**模型回复模式（Model Response Mode）**，或 [`CHANNEL_MODEL_RESPONSE_MODE`](/reference/env-configuration#channel_model_response_mode)）：将其设为**频道（Channel）**后，回复会直接发布到时间线上，团队无需打开讨论串即可阅读。无论采用哪种设置，在讨论串内提及模型时，都会始终在该讨论串中回复。

#### 模型读取的内容 {#what-the-model-reads}

被标记的模型不会读取频道的时间线。它会收到你的消息所属讨论串中的消息，最多为最近的 50 条，每条都标注撰写者（人员或模型）的名称。在频道顶层发布提及会开始一个新讨论串，因此模型只能看到这一条消息。**模型回复模式（Model Response Mode）**只改变回复的发布位置，不改变模型读取的内容。使用**频道（Channel）**模式时，回复会进入时间线；之后再次从顶层提及模型，即使是回复模型自己的消息，也同样不会携带更早的消息。要让模型获取此前的讨论，请将对话保留在同一讨论串中，或将所需内容粘贴到你的消息里。

### 完整的聊天补全流程 {#full-chat-completion-pipeline}

在频道中提及模型时，会经过与标准聊天相同的聊天补全流程。回复会随着模型生成而**实时流式显示**，并且模型可以使用其配置授予的全部能力：

| 能力 | 在频道中的作用 |
|------------|------------------------------|
| **原生和默认函数调用** | 工具调用会在消息生成过程中解析并执行 |
| **内置工具** | 网页搜索、图像生成、代码解释器、日历 |
| **用户工具和 MCP 工具** | 模型可以调用其配置允许调用的任何工具 |
| **过滤器** | 入口、出口和流式过滤器的应用方式与聊天中相同 |
| **知识（RAG）** | 查询并注入附加到模型的知识库 |
| **附加文档** | 讨论串中上传的图片**和**非图片文件（PDF、DOCX 等）会传入模型上下文 |
| **结构化回复** | 回复根据模型的完整输出呈现，因此推理块、工具调用、生成的图像和代码结果会像在聊天中一样显示在频道中，而不是被扁平化为纯文本 |

换句话说，在频道中调用的模型是功能完备的智能体，而非一次性补全工具。

### 标记人员和链接频道 {#tagging-people-and-linking-channels}

使用 `@username` 通知团队成员。建议列表会优先显示当前频道自己的成员，然后显示实例中名称与你输入内容匹配的其他人，因此你仍可标记不在频道中的人。标记只会通知能够读取该频道的人。使用 `#channel-name` 可在对话之间创建可点击的交叉引用。

你也可以完整输入提及，而不从列表中选择。粘贴或发送时，如果 `@name` 恰好匹配一位人员、一个模型或一个应用的名称，或者匹配 `@gpt-5.6` 这样的模型 ID，它就会成为真正的提及。如果 `#name` 恰好匹配一个频道，它就会成为频道链接。如果有两个同名匹配项，则必须从列表中选择。从其他消息粘贴的提及仍会指向同一个人。

将鼠标指向消息旁或频道成员列表中的头像，或指向某人的 `@mention`，即可打开其个人资料卡片。卡片会显示姓名、在线状态、个人状态、简介、所属用户组、本地时间和最后活跃时间。本地时间采用其上次使用 Open WebUI 时所在浏览器的时区。每位已登录用户都可以打开任何其他用户的卡片，并且可以通过 API 获取相同信息以及电子邮件地址和角色。

### 消息交互 {#message-interactions}

将鼠标悬停在任意消息上，即可添加表情回应、将消息置顶以供参考、内联回复或发起讨论串侧边对话。在宽度至少为 768 px 的屏幕上，讨论串会在频道旁打开；在较窄的屏幕上，则会覆盖在频道上方。

频道标题栏中的**搜索（Search）**按钮用于搜索该频道的消息。搜索框下方会将该频道显示为筛选条件；移除它可以扩大搜索范围。

你可以删除自己的消息，管理员可以删除任何人的消息。删除发起讨论串的消息时，也会删除该讨论串中的所有回复，包括其他人撰写的回复。

如果你只能读取频道，消息不会显示悬停操作，其下方的表情回应也无法点击。消息输入框会显示**你没有在此频道发送消息的权限（You do not have permission to send messages in this channel.）**。

### 将频道静音 {#muting-a-channel}

侧边栏或频道标题栏中的频道或私信 **...** 菜单提供**通知（Notifications）**设置。**仅提及（Mentions only）**会为你将频道静音：频道在侧边栏中变暗，并且不显示未读数量。只有 @提及你的消息仍会发送弹出提示、浏览器通知或[通知 webhook](/features/chat-conversations/chat-features/notifications)；这类消息也仍不显示未读数量。**所有消息（All messages）**会重新开启通知。此设置按成员分别生效，因此将频道静音不会对其他人产生任何影响。另请参阅你的[收件箱](/features/chat-conversations/chat-features/notifications#inbox)。

### 应用 {#apps}

外部服务也可以作为[应用](/features/channels/apps)加入频道。管理员在**设置 > 集成（Settings > Integrations）**（管理员区域）的**应用（Apps）**下安装它们，然后由频道创建者或管理员将它们添加到频道。它们会带有**应用（App）**标记显示在成员列表中，在你 `@mention` 它们时回复，并可以发布带按钮的消息。

### 私信 {#direct-messages}

私信是你与所选人员之间的对话，每组参与者只对应一个私信。可以从频道中某人个人资料卡片上的**发消息（Message）**按钮发起，也可以在侧边栏的**频道（Channels）**区域点击 **(+)**，将**频道类型（Channel Type）**设为**私信（Direct Message）**来发起。给之前联系过的人发消息时，会重新打开你们已有的对话及其历史记录，而不是在旁边再创建第二个对话。私信名称是可选的；未设置名称时，会以其他参与者的名称列出。

成员关系根据仍然存在的账户计算。某人的账户被删除后，就不再计入该对话：此人会从成员列表和标题栏人物图标旁的成员数量中消失，其余参与者再次相互发消息时，仍会回到同一个对话。群组频道采用相同的成员计数方式。系统不会合并已经存在的两个相同参与者对话，因此，如果曾创建重复对话，它会连同其中已发送的消息一起保留在侧边栏中，与原对话并存。

### 加密聊天 {#encrypted-chats}

在私信或私有群组频道中，拥有**加密频道（Encrypted Channels）**权限的成员可以通过对话的 **...** 菜单，点击**加密聊天（Encrypted Chat）**发起临时[加密聊天](/features/channels/encrypted-chats)。消息在浏览器中端到端加密，绝不会存储在服务器上。管理员在**设置 > 通用（Settings > General）**（管理员区域）中开启此功能（**加密频道（Encrypted channels）**）并授予权限；该权限默认关闭。

## AI 频道感知 {#ai-channel-awareness}

启用[**原生函数调用**](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)后，模型可以自主浏览你的频道：

- 按名称或描述**搜索频道**
- 跨所有可访问的频道**搜索消息**
- **读取讨论串**以理解完整的讨论上下文

> **你：** `#dev-team` 中对迁移时间线作出了什么决定？
>
> *（AI 搜索频道、读取相关讨论串并为你综合回答，全程无需离开当前聊天。）*

这样就无需在私人聊天和共享频道之间手动传递信息，AI 会代你完成。

:::tip 社区操作：转发到频道
如果希望从聊天消息一键进入频道，社区 **[Forward to Channel](https://openwebui.com/posts/b60c1f03-e29c-47c0-862c-3741a382616e)** 操作会为每条助手消息添加一个按钮，将回复（或选中的内容）发布到你选择的频道。它适合将私人聊天中的优质回答分享到团队可见的空间，无需复制粘贴。
:::

## 快速上手 {#getting-started}

:::info
频道必须由管理员启用后才能使用。
:::

1. 前往**设置 > 通用（Settings > General）**（管理员区域）
2. 开启**频道（Channels）**并保存
3. 频道会出现在侧边栏中。点击 **(+)** 创建你的第一个频道

只有管理员可以创建标准频道。拥有**频道（Channels）**权限（[`USER_PERMISSIONS_FEATURES_CHANNELS`](/reference/env-configuration#user_permissions_features_channels)）的人可以创建群组频道和私信。频道支持精细权限，包括只读访问、写入访问，以及通过环境变量或用户组权限控制的功能级开关。

标准频道的**访问权限（Access）**决定谁可以在其中读取或写入：指定用户、用户组或实例中的所有用户。只有频道创建者或管理员可以更改它，且只有管理员才能将其开放给所有用户。与用户或用户组共享时遵循[共享权限](/features/authentication-access/rbac/permissions#2-sharing-permissions)。群组频道和私信没有**访问权限（Access）**设置；其成员决定谁可以读取。

## 使用场景 {#use-cases}

### 团队知识中心（`#engineering`） {#team-knowledge-hub-engineering}

你的团队在一周内持续讨论架构决策。有人标记 `@claude` 评估各种方案的取舍。AI 的分析会成为永久记录的一部分：频道中的每个人都可以搜索、引用和阅读。

### 多模型应急指挥室（`#incident-response`） {#multi-model-war-room-incident-response}

粘贴日志和错误跟踪信息，然后在其下方的讨论串中协作。标记 `@gpt-5.6` 分析堆栈跟踪，标记 `@qwen3.6` 提议修复方案，再标记 `@claude` 起草事后复盘。三个模型，同一讨论串，每个模型都能读取其他模型撰写的内容。

### 项目策略（`#product-launch`） {#project-strategy-product-launch}

在一个讨论串中进行二十条消息的人类头脑风暴。然后，在该讨论串中输入：`@gpt-5.6` 阅读此讨论串，并创建一份按优先级排序的行动计划，明确负责人和截止日期。AI 会将讨论串中的所有内容综合为结构化交付物。

### 创意协作（`#story-mode`） {#creative-collaboration-story-mode}

多个“角色”模型在同一时间线上互动，适合长期叙事项目。切换角色时不会丢失上下文。

:::warning 隐私
公开频道对实例上的所有用户可见。请勿在公开频道中分享 API 密钥、密码或敏感数据。
