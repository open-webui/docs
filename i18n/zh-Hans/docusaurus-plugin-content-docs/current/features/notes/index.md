**在 AI 的陪伴下写作、思考和完善内容。**

你搜索、发现并综合信息，笔记则将它们沉淀为持久知识。它是一个专门的工作区，用于存放独立于任何单次对话的内容：草稿、速查表、研究发现、项目简报。这些内容可以随时间不断积累、借助 AI 完善，并作为上下文注入未来的聊天。

与线性且短暂的标准聊天不同，笔记是可以随时返回、编辑和共享的持久文档。与使用向量搜索查找相关片段的[知识库](/features/workspace/knowledge)不同，笔记会以完整文本送达模型，让你精确控制 AI 能看到的内容。

## 为什么使用笔记？ {#why-notes}

![笔记列表](/images/features/notes/notes-list.png)

### 内置 AI 辅助写作 {#ai-assisted-writing-built-in}

打开**聊天侧边栏**，无需离开编辑器即可对内容进行头脑风暴、评论、扩展或改写。它提供完整的聊天界面，因此仍可使用模型选择器、工具和附件，并且每篇笔记可以进行多场独立对话。先选中一段文字，模型就会只就地改写该部分。

### 精确的上下文注入 {#precise-context-injection}

将笔记附加到聊天后，AI 会逐字阅读整篇文档。无需分块、向量搜索或猜测，你可以精确控制模型看到的内容。

### 持久保存，而非一次性 {#persistent-not-disposable}

笔记独立于聊天存在。编写一份编程参考资料，用数周时间持续完善，并在需要时将其附加到任何对话。

### AI 可以读取和写入你的笔记 {#ai-can-read-and-write-your-notes}

启用[原生函数调用](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)后，模型可以自主搜索、读取、创建和更新笔记，将笔记变成动态的长期记忆。

## 主要功能 {#key-features}

| | |
| :--- | :--- |
| **富文本编辑器** | Markdown 和富文本，配有浮动格式工具栏 |
| **AI 增强** | 让笔记的聊天就地改写或改进所选文本 |
| **聊天侧边栏** | 笔记内的完整聊天界面，每篇笔记可以包含任意多场对话 |
| **上下文注入** | 将笔记附加到任意聊天，提供完整、不失真的上下文 |
| **页面** | 将笔记拆分为页面和子页面 |
| **附件** | 文件以区块形式放在页面中添加它们的位置 |
| **标签** | 在笔记列表中使用与聊天相同的标签标记笔记，然后按标签筛选列表或显示未标记的笔记 |
| **文件夹** | 将笔记与同一项目的聊天一起存放在[文件夹](/features/chat-conversations/chat-features/conversation-organization#notes)中 |
| **固定到侧边栏** | 固定常用笔记，以便从侧边栏快速访问 |
| **智能体式访问** | 模型可以自主搜索、读取和更新笔记 |
| **导出** | 下载为 `.txt`、`.md` 或 `.pdf` |

## 编辑器 {#the-editor}

笔记使用可感知上下文的**浮动工具栏**设置格式：

* **点击空白处**可开始新建标题、列表或任务列表
* **双击文本**可应用粗体、斜体、下划线、删除线或行内代码
* **拖放**列表项可重新排序
* **拖动手柄**（⋮⋮）可移动任何顶级区块，点击手柄则可选择**上移**和**下移**

顶栏会实时显示**字数和字符数**。笔记的聊天输入框与[聊天输入框](/features/chat-conversations/chat-features)一样支持录音。如果你可以编辑笔记，录音上传后会立即保存到笔记中，其转写在服务器上完成。

:::info 聊天中的富文本
此编辑器也可以为标准聊天启用：**设置 > 界面 > 聊天富文本输入**和**显示格式工具栏**。
:::

## 页面 {#pages}

一篇笔记包含多个页面，每个页面还可以包含子页面。点击编辑器顶部当前打开页面的标题，即可显示**页面**面板。在宽度至少为 768 px 的屏幕上，面板在笔记旁打开；在较窄的屏幕上，面板覆盖在笔记上方。

* **添加页面**会添加顶级页面，页面旁的 **+** 会添加子页面
* 拖动页面可重新排序，或将其嵌套到另一个页面中
* 每个页面的 **⋯** 菜单提供**添加子页面**、**重命名页面**、**上移**、**下移**、**移动页面…**（选择父页面或**顶级**；其子页面会随之移动）、**复制页面链接**、**下载页面**和**删除页面**

删除页面会将其子页面上移一级。第一个页面无法移动或删除。页面链接会打开笔记并定位到该页面，搜索结果和笔记链接也会打开匹配的页面。

## AI 集成 {#ai-integration}

点击编辑器工具栏中的**对话气泡**按钮（位于笔记顶部“撤销/重做”旁），即可打开笔记的聊天。AI 对笔记执行的所有操作都通过该聊天进行，并且会作用于当前打开的页面。

### 增强 {#enhance}

改写通过聊天完成，没有单独的**增强**按钮。选择要修改的段落，打开聊天，然后使用**改写所选文本。**建议或直接说明你的要求。模型会通过 `replace_note_content` 就地改写笔记，更改会实时出现在编辑器中。不选择任何内容，即可讨论整篇笔记。

### 聊天侧边栏 {#chat-sidebar}

在笔记旁的窗格中打开完整聊天界面；在宽度小于 768 px 的屏幕上，界面会覆盖在笔记上方。它使用与普通聊天相同的组件，因此提供模型选择器、工具和技能选择、文件附件、Web 搜索以及聊天输入框的其余功能。你可以让 AI 总结、提取数据、评论或改写特定部分。

**语音模式**是例外。笔记的聊天中不提供其按钮，因此如需免提语音对话，请使用普通聊天。聊天输入框中的麦克风按钮仍可用于听写。

**将响应插入笔记。**拥有笔记写入权限时，每条助手响应都带有**插入笔记**按钮，可将该响应插入笔记中的光标位置。只读协作者没有此按钮。插入前会先创建一个笔记版本，因此可通过**撤销/重做**（右上角）还原。

**每篇笔记包含多场对话。**面板标题是一个下拉列表，列出附加到此笔记的所有聊天。可用它切换、新建或删除聊天。只有发送第一条消息后，新对话才会保存，因此仅打开对话再离开不会留下任何内容。删除最后一场聊天后，会立即重新创建一场空聊天。

**建议提示词。**对话为空时会提供四个提示词：增强并更新笔记、总结笔记、提取行动项、改写所选文本。对话中一有消息，它们就会消失；如果将**设置 > 界面 > 落地页模式**设置为**聊天**，也不会显示这些提示词。

**所选文本会一并传递。**如果笔记中有选中的文本，该选区会附加到你发送的任何内容之后，作为改写目标。未选择任何内容时，消息会单独发送。

:::info 模型实际如何查看笔记

笔记不会粘贴到对话中。聊天携带包含笔记 ID 的系统提示词，每条消息都会指明当前打开的页面，模型通过 `view_note` 读取页面，并通过 `replace_note_content` 进行编辑。模型做出编辑时，更改会直接出现在编辑器中，无需重新加载。

这会带来两个结果。无法调用工具的模型将完全看不到笔记内容；内置工具在此聊天中的行为也与其他位置不同：笔记工具始终会被注入，即使管理员配置模型时未启用内置工具，整个内置工具接口也会被强制启用。请参阅[附加笔记的聊天中的内置工具](/features/extensibility/plugin/tools#tool-reference)。

:::

:::info 笔记聊天独立于聊天历史

从笔记打开的聊天属于内部聊天。它们不会显示在侧边栏聊天列表或搜索中，并且按用户隔离：对于共享笔记，每位协作者都有自己的一组对话，无法看到其他人的对话。拥有笔记读取权限即可打开聊天。

:::

所有 AI 更改都由**撤销/重做**（右上角）跟踪，因此始终可以还原。

## 在聊天中使用笔记 {#using-notes-in-chat}

1. 前往**聊天输入**栏
2. 点击 **+（更多）**按钮
3. 打开**附件**并选择**附加笔记**
4. 选择要附加的笔记

**附加笔记**需要启用笔记功能并具备**笔记**权限。

开启模型的**预加载文件**能力后，笔记的完整内容会注入对话。关闭该能力时（原生函数调用的默认行为），模型会使用知识工具读取笔记，此时工具只搜索附加的知识。[范围化访问](/features/workspace/knowledge#scoped-access-keeps-things-organized)对此进行了说明。

你也可以**直接将笔记从侧边栏拖到聊天中**，将其作为上下文引用附加，无需打开菜单。同样的拖放操作也适用于侧边栏中的**聊天**、**文件夹**和**模型**。

笔记还可以放入模型或文件夹的**知识**字段，与知识库和文件并列。请参阅[附加知识和笔记](/features/workspace/knowledge#attaching-knowledge-and-notes)。

## 智能体式笔记管理 {#agentic-note-management}

启用[**原生函数调用**](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)后，模型可以自主处理笔记。为你启用笔记功能后，模型的**笔记**内置工具类别会提供这些工具。无论附加了什么知识，它们都会在每场聊天中提供，并可访问你有权读取的所有笔记：

| 工具 | 功能 |
|------|-------------|
| `search_notes` | 按标题和内容搜索笔记 |
| `view_note` | 读取一个页面，或读取整篇笔记及其页面列表 |
| `write_note` | 创建新笔记 |
| `replace_note_content` | 更新笔记的一个页面，既可整体替换，也可就地编辑部分内容 |

> **你：**搜索我的“Project X”笔记，找到数据库架构。
>
> **你：**在我的“每周待办”笔记中添加一项审查 PR 的新任务。

## 固定笔记 {#pinning-notes}

将重要笔记固定到侧边栏以便快速访问。固定笔记与固定聊天类似，会显示在侧边栏专用的**笔记**文件夹中。

### 如何固定 {#how-to-pin}

* 在**笔记列表**中：点击任意笔记上的 **⋯** 菜单，选择**固定到侧边栏**
* 在**笔记编辑器**中：点击右上角的 **⋯** 菜单，选择**固定到侧边栏**

### 如何取消固定 {#how-to-unpin}

* 在**侧边栏**中：将鼠标悬停在固定笔记上，点击 **✕** 按钮
* 在**笔记列表**或**编辑器**中：点击 **⋯** 菜单，选择**取消固定**

只有至少固定一篇笔记并启用笔记功能时，侧边栏的笔记文件夹才会显示。

:::info 固定状态按用户独立

固定笔记只会影响**你的**侧边栏：拥有同一笔记访问权限的协作者可以独立固定或取消固定，不会改变你看到的内容。固定笔记按固定时间排序（最新在前），切换固定状态不再计为编辑，因此不会更新笔记的“更新时间”时间戳。此变更之前已有的固定状态仅为笔记所有者保留；其他用户需要重新固定希望显示在自己侧边栏中的共享笔记。

:::

## 管理与共享 {#management-and-sharing}

通过右上角的**更多 (...)**菜单访问管理选项。

### 导出 {#export}

* **纯文本 (.txt)**或**纯文本 (.md)**，用于原始内容
* **PDF 文档 (.pdf)**，保留视觉格式和粘贴到笔记中的图像（自动检测深色模式）

**更多 (...)**菜单中的**下载**会导出整篇笔记，每个页面位于各自标题下。页面 **⋯** 菜单中的**下载页面**只导出该页面。

### 共享 {#sharing}

**更多 (...)**菜单中的**共享**提供**复制链接**和**复制到剪贴板**。复制的链接只能由原本就有权访问该笔记的人打开。

授予访问权限需要使用**更多 (...)**菜单旁右上角的**访问**按钮。它会打开**访问控制**面板，你可以在其中设置笔记的可见性，并以**读取**或**写入**权限共享给个人和组。**读取**允许对方打开笔记并从中开始聊天，但编辑器保持只读；**写入**还允许编辑正文及其文件。该按钮需要写入权限和**笔记共享**权限，并且只有所有者或管理员可以更改共享设置。列表的工作方式与 [Open WebUI 中的其他位置](/features/authentication-access/rbac/groups#resource-access-rbac)相同。

笔记列表中笔记的 **⋯** 菜单也会打开相同面板。

保存笔记不会更改其共享对象。

[共享文件夹](/features/chat-conversations/chat-features/conversation-organization#sharing-folders)中的笔记也会向该文件夹的所有共享对象开放，权限与其文件夹权限一致。文件夹的**读取**权限允许他们阅读笔记，**写入**权限允许他们编辑笔记。

拥有访问权限的人可以同时在笔记上工作，并在输入时实时看到彼此的编辑，每个人的姓名会显示在其光标上方。顶栏会显示其他打开该笔记的用户头像。点击头像可跳转到他们所在的页面和光标。每位用户最多可以同时打开 20 个笔记页面进行实时编辑，该数量跨所有浏览器标签页和设备统计。启用[评论](/features/chat-conversations/chat-features/comments)后，任何拥有访问权限的人都可以讨论笔记或其中的段落。

以读取权限打开的页面也会计入 20 个页面的上限。超过上限后打开可编辑页面时，编辑器会显示为空，你在其中输入的任何内容都会被忽略，因此不会保存。切换页面、下载笔记或离开页面时会显示 `Tab is not connected. Reconnect before leaving this tab.`。请关闭其他标签页或设备中已打开的笔记，然后重新加载页面。对于每个被拒绝的页面，服务器日志会记录 `is at the open-document limit. Rejecting join.`。

单个页面的实时编辑最多保留 16 MiB 编辑历史。超过该大小后，你的编辑仍会保存到笔记，但其他打开该页面的人将无法再实时收到你的输入。服务器日志会显示 `is invalid or over the size limit. Rejecting update.`。要重新开始，请让所有人关闭该页面。最后一人离开时会清除历史，页面随后从已保存的笔记重新打开。

管理员可以通过环境变量或管理员面板控制共享：

* [`USER_PERMISSIONS_NOTES_ALLOW_SHARING`](/reference/env-configuration#user_permissions_notes_allow_sharing)控制**访问**按钮和菜单项，以及**访问控制**面板中的访问列表是否显示（默认 `False`）
* [`USER_PERMISSIONS_NOTES_ALLOW_PUBLIC_SHARING`](/reference/env-configuration#user_permissions_notes_allow_public_sharing)用于公开链接（默认 `False`）

这些选项也可以在**管理员面板 > 用户 > 组**中配置为**笔记共享**和**笔记公开共享**。两者初始均关闭，只有开启**笔记共享**后才会显示公开开关。管理员始终可以公开共享笔记。请参阅[权限](/features/authentication-access/rbac/permissions#2-sharing-permissions)。

### 附件 {#attachments}

文件存放在页面中添加它们的位置。将文件拖放或粘贴到编辑器中，或在**更多 (...)**菜单中选择**上传文件**，文件就会落在光标处。图像会内联显示，其他文件会成为可拖动的文件区块，点击可打开，点击其 **✕** 可移除。添加和移除文件需要笔记写入权限。任何对共享笔记拥有读取权限的人都可以打开其附加文件，笔记的聊天也会使用这些文件。这同样适用于笔记所有者上传的文件，这些文件对所有者仍保持只读。

当前打开页面中的非图像文件，会作为检索上下文附加到从此笔记打开的聊天中发送的每条消息。

### 格式化 {#formatting}

**更多 (...)**菜单中的**格式化**决定编辑器是否在输入和粘贴时自动设置格式。该选项默认开启，需要写入权限才能更改。

关闭后，Markdown 字符会保留为普通字符，粘贴的 URL 会保留为文本而不会变成链接，粘贴操作也只带入纯文本，不带源内容的样式。笔记中已经格式化的内容会保持不变，因此此设置只影响后续操作，不会移除现有格式。

### 快速创建 {#quick-creation}

* 前往 `/notes/new`，创建以当天日期为标题的笔记
* 添加[查询参数](/features/chat-conversations/chat-features/url-params#12-new-note)：`/notes/new?title=My%20Title&content=Initial%20text`
* 从[搜索窗口](/features/chat-conversations/chat-features/history-search#searching-your-history)（`Cmd+K` / `Ctrl+K`）创建：打开其**操作**菜单（再次按 `Cmd+K` / `Ctrl+K`），选择**创建新笔记**，搜索文本会用作笔记内容
* 将 `.md` 文件拖到笔记列表上即可导入

前三种方式会打开**创建新笔记**对话框并显示标题和内容，确认后即创建笔记。

### 视图选项 {#view-options}

可在**由你创建**和**与你共享**筛选条件之间切换，也可在**列表**和**网格**布局之间切换。

[搜索窗口](/features/chat-conversations/chat-features/history-search#searching-your-history)还可以按标题和内容查找你的笔记以及与你共享的笔记。

### 快速删除 {#quick-delete}

笔记列表打开时，按住 **Shift**，每篇笔记的 **⋯** 菜单按钮都会变成删除按钮。点击后会直接删除该笔记，不显示菜单，也不要求确认。此操作在**列表**和**网格**布局中都有效，按住 Shift 还会关闭任何已打开的笔记菜单。松开 Shift 或点击窗口以外的位置，菜单按钮就会恢复。不按 Shift 时不会有任何变化：删除仍需通过菜单并要求确认。当通过 `Tab` 聚焦到按钮或链接时，按住 Shift 不会将菜单按钮变成删除按钮，因此 `Shift+Tab` 仍可照常向前浏览列表。

:::info 管理员可见性
笔记是工作区项目。默认情况下（`BYPASS_ADMIN_ACCESS_CONTROL=True`），管理员可以查看所有用户的笔记。将 `BYPASS_ADMIN_ACCESS_CONTROL` 设置为 `False` 可限制此行为。详情请参阅[环境配置](/reference/env-configuration#bypass_admin_access_control)。要为整个实例关闭笔记，请参阅 [`ENABLE_NOTES`](/reference/env-configuration#enable_notes)。
:::

## 使用场景 {#use-cases}

### 持续完善的草稿 {#living-drafts}

在笔记中起草内容，选择要点并让笔记的聊天将其扩展为段落，然后保持第二场对话用于头脑风暴标题。笔记就是最终成果，而不只是参考资料。

### 高保真代码上下文 {#high-fidelity-code-context}

RAG 使用向量搜索，这种方式具有概率性，可能会遗漏关键行。将特定函数粘贴到笔记并附加，模型就能按照原有排列看到 100% 的代码。

### 数据脱敏 {#data-sanitization}

将包含敏感数据的服务器日志粘贴到笔记中，遮盖密钥（或让笔记的聊天对文本进行匿名化），然后将脱敏后的笔记附加到聊天。这可以防止敏感数据泄露到聊天历史中。

## 限制 {#limitations}

### 上下文窗口占用 {#context-window-usage}

笔记会以完整文本送达模型。将非常大的笔记附加到上下文窗口较小的模型，可能会导致模型丢失较早的对话上下文。

### 写入权限 {#write-access}

手动附加时，笔记为**只读**。在启用 `replace_note_content` 工具的**原生模式**下，模型可以修改笔记。请检查更改，并在需要时使用**撤销/重做**。

该工具一次编辑一个页面。模型必须先使用 `view_note` 读取页面；如果页面在读取后发生了变化，编辑会被拒绝。

该工具有两种模式。传递完整的 `content` 会替换整个页面，因此模型省略的任何内容都会丢失。传递 `replace_text` 操作则只更改页面的一部分，其余内容保持不变。每个操作通过以下两种方式之一指定要更改的文本：

- **按文本。**`find` 保存要替换的确切文本。匹配为字面匹配并区分大小写。如果文本出现多次，`occurrence` 会选择一个匹配项（从 0 开始计数），`replace_all: true` 会替换所有匹配项。两者均未设置时不会更改任何内容，模型会收到所有匹配项的位置以供选择。
- **按位置。**`start` 和 `end` 是从 0 开始的字符偏移量，基于 `view_note` 返回的原始 Markdown。结束位置不包含在范围内，同一请求中的范围不得重叠。即使较早的替换更改了文本长度，每个操作也要使用原始偏移量。可选的 `expected` 字段保存该范围的当前文本，不匹配时会拒绝编辑。

例如，要将 `red blue` 改为 `green navy`，请在一个请求中发送以下两个操作：

```json
[
  {"action": "replace_text", "start": 0, "end": 3, "expected": "red", "content": "green"},
  {"action": "replace_text", "start": 4, "end": 8, "expected": "blue", "content": "navy"}
]
```

较早的 `replace_range` 操作仍可作为位置形式的别名使用，但已弃用。请明确提出部分编辑要求（添加一节、更改这些行），以便模型使用这些操作。

笔记不保留服务器端历史。**撤销/重做**只能遍历编辑器记录的版本，而这些版本会在将聊天响应插入笔记或逐步浏览版本时记录；因此，对于没有此类版本的笔记，工具编辑无法在其中撤销。之前的文本仍保留在聊天中：模型在编辑前使用 `view_note` 读取笔记，该工具结果会保留在聊天消息中。展开该消息中的工具调用，即可复制旧内容。如果模型编辑了你已打开的页面，或者有人删除了该页面，横幅还会提供之前文本的下载。
