# 子代理

子代理让模型可以将一项明确的工作交给另一个并行运行的代理，然后利用其结果继续处理。模型通过调用 `delegate_task` 内置工具决定何时委派任务。

子代理会独立执行一次完整的聊天补全。它使用与发起它的聊天相同的工具、技能和过滤器，在当前模型或为当前模型设置的某个[子代理模型](/features/workspace/models#capabilities-and-bindings)上运行，独立完成任务并返回最终答案。工作会在一个单独的聊天中进行，该聊天不会出现在你的聊天列表中，因此父对话仍保持清晰易读。

子代理默认禁用。管理员可以通过 [`ENABLE_SUBAGENTS`](/reference/env-configuration#enable_subagents) 环境变量或 **设置 > 子代理**（管理员区域）开关启用它们。

## 子代理会收到哪些信息 {#what-a-sub-agent-is-told}

子代理构建指令的方式与新聊天消息相同，以父聊天的原始配置为起点：聊天自己的系统提示词（来自 **模型控制 > 控制** 或你的 **设置**）、模型的系统提示词、聊天变量，以及消息中提及的任何技能的完整文本。文件夹的系统提示词、工具服务器和终端指令会应用于子代理自己的运行过程，同时还会应用[子代理系统提示词](#admin-limits)。

后台子代理的结果会继续父聊天，此时也采用相同方式构建指令。

## 为什么委派任务 {#why-delegate}

委派任务通过三种方式提升专注度和并行能力。

- **每个任务都有干净的上下文。**子代理只收到任务及交给它的上下文，因此长聊天不会稀释工作内容。
- **真正的并行。**当模型在一条回复中请求多个委派时，它们会同时运行。
- **只返回简短答案。**只有子代理的最终结果会返回父聊天，中间的工具调用、搜索和无效尝试都留在子代理自己的聊天中。

典型用途包括同时研究多个问题、处理需要大量工具调用的任务，以及执行中间步骤不应出现在主线程中的独立工作。

## 前台与后台 {#foreground-and-background}

在频道和自动化运行之外，子代理在**后台**运行。子代理工作时，模型会继续处理。子代理完成后，其结果会发布回父聊天，并且**聊天会自动继续，无需你发送任何内容**。结果显示为可折叠行，其中包含子代理状态、任务标题和运行时长。展开即可阅读结果，点击**打开线程**可打开子代理的聊天。如果此时父聊天正忙，结果会等待聊天空闲后再投递。

在频道和自动化运行中，子代理在**前台**运行。回复会等待子代理完成，并将其答案作为工具结果接收，与其他工具调用相同。

### 跟踪子代理 {#following-sub-agents}

聊天顶栏的**状态**按钮会在**线程**下列出聊天的子代理和已计划的[定时器](/features/chat-conversations/chat-features/timers)。点击子代理可在标签页中打开其聊天，也可以将其**停止**。**取消**会在定时器触发前将其移除。

### 聊天之间的消息 {#messages-between-chats}

启用子代理后，已保存聊天中的模型还会获得 `send_message` 工具。它可以向你的另一个聊天发送消息，例如子代理或父聊天。正在工作的聊天会在工具调用之间读取消息，空闲聊天则会被唤醒来读取消息。消息在接收聊天中显示为可折叠行，并带有发送聊天的标题。展开即可阅读消息，点击**打开线程**可打开发送聊天。正在等待你批准工具的聊天不会接收消息。

## 交接文件 {#handing-over-files}

子代理开始时不带任何附件。父聊天上传的内容不会自动随任务传递，因此委派任务不会在不知不觉中将长对话中的每个文件都带入第二次模型调用。

要传递文件，模型需要在 `delegate_task` 的 `file_ids` 参数中指定文件。这些文件会附加到子代理的初始消息中，就像你亲自附加一样。图像会作为图像交给模型，因此视觉模型可以真正查看它；文档在子代理中的可用方式与普通聊天完全相同：开启**预加载文件**时会注入，关闭时则通过**文件**内置工具读取。

只能传递父聊天中已经附加的文件，并且每个 ID 都会在运行前接受检查。如果其中一个 ID 未知或不再可用，调用会返回 `Error: file_ids not attached or unavailable: <ids>`，并且不会启动子代理。

写入 `context` 的文件 ID 只是一段文本。子代理只会收到 ID，不会收到文件，因此任何需要它打开的文件都应放入 `file_ids`。

## 启用子代理 {#enable-sub-agents}

子代理需要同时满足四项条件。

1. **全局启用**：[`ENABLE_SUBAGENTS`](/reference/env-configuration#enable_subagents)，或 **设置 > 子代理**（管理员区域）。
2. **为模型启用**：**设置 > 模型 > 编辑**（管理员区域）中**内置工具**下的**子代理**类别（对于自己的模型，则位于 **工作区 > 模型**）；功能启用后，该类别默认开启。
3. **用户权限**：[默认权限和组权限](/features/authentication-access/rbac/permissions#4-features-permissions)中**功能**下的**子代理**开关，或 [`USER_PERMISSIONS_FEATURES_SUBAGENTS`](/reference/env-configuration#user_permissions_features_subagents)。没有该权限的用户无法使用 `delegate_task`、`send_message` 和 `timer`。
4. **聊天中的内置工具**：`delegate_task` 是内置工具，因此**函数调用**不得设置为**传统（Legacy）**，并且必须开启模型的**内置工具**能力。聊天、频道和自动化运行均符合条件。临时聊天不会获得子代理工具。

管理员始终通过权限检查。

## 管理员限制 {#admin-limits}

在 **设置 > 子代理**（管理员区域）中配置这些选项，或使用对应的环境变量。

![子代理设置](/images/admin/admin-subagents.png)

| 设置 | 变量 | 默认值 | 用途 |
|---|---|---|---|
| 最大并发数 | [`SUBAGENTS_MAX_CONCURRENT`](/reference/env-configuration#subagents_max_concurrent) | 空（无限制） | 同时运行的前台子代理（频道和自动化运行）数量。超出数量的任务会等待空闲槽位。 |
| 最大后台数 | [`SUBAGENTS_MAX_ASYNC`](/reference/env-configuration#subagents_max_async) | 空（无限制） | 同时运行的后台子代理（所有其他聊天）数量。超出数量的任务会立即被拒绝。 |
| 最大迭代次数 | [`SUBAGENTS_MAX_ITERATIONS`](/reference/env-configuration#subagents_max_iterations) | 空（无限制） | 单个子代理可以运行的工具调用轮数。达到上限后，它会在不使用工具的情况下写出最终答案，并将该答案返回父聊天。 |
| 最大输出 | [`SUBAGENTS_MAX_OUTPUT`](/reference/env-configuration#subagents_max_output) | 空（无限制） | 返回父聊天的字符数。较长的结果会被截断。 |
| 系统提示词 | [`SUBAGENTS_SYSTEM_PROMPT`](/reference/env-configuration#subagents_system_prompt) | 内置 | 替换内置子代理提示词。结果会添加到模型自己的系统提示词中。 |

更改这些限制前，需要了解其中三项行为。

- **它们按工作进程计数。**使用多个工作进程或副本时，实际上限是限制值乘以进程数。
- **更改最大并发数需要重启。**其限制会应用于第一次受限前台委派时创建的信号量，此后不会调整大小。最大后台数会立即应用。
- **限制值必须是正整数。**留空或设为 `0` 表示无限制。使用 [`ENABLE_SUBAGENTS`](/reference/env-configuration#enable_subagents) 关闭该功能。

## 子代理无法执行的操作 {#what-a-sub-agent-cannot-do}

子代理在以下方面比父聊天更受限制。

- **不能递归。**子代理不能再次委派任务或设置定时器，因此委派不会无限扩散。
- **不能使用 `ask_user`。**子代理不能暂停并向你提问；需要你先批准的工具调用会使其暂停，直至你批准。它仍可以向父聊天发送消息。
- **不能写入记忆。**它可以读取记忆，但不能添加、修改或删除记忆，从而避免委派工作在不知不觉中重写你的个性化内容。
- **后台不能使用代码解释器**，除非引擎是 Jupyter，因为基于浏览器的 Pyodide 引擎需要活动会话。
- **子代理目标。** **子代理**列表提供实例自己的模型。
- **无法访问你的终端标签页。**子代理无法使用读取或向你所打开终端标签页输入内容的工具。

每个子代理都在自己的聊天中运行。这些聊天会从聊天列表和搜索中隐藏，并随父聊天一起删除。与其他聊天相同，只有在 [`ENABLE_ADMIN_CHAT_ACCESS`](/reference/env-configuration#enable_admin_chat_access) 开启时，管理员才能按 ID 阅读它们。

## 成本 {#cost}

每次委派都是另一次使用相同工具的完整聊天补全，并且可能循环至迭代上限。一条回复可以同时启动多个子代理，而每个后台结果都会重启父聊天来处理它，这又构成一轮对话。

默认不设置限制，因此运行多少个子代理以及循环多久完全由模型决定。对于按量计费的 API，请设置[管理员限制](#admin-limits)。

委派成本会与其他所有项目一起显示在[分析](/features/administration/analytics)中。

## 从聊天中管理子代理 {#managing-sub-agents-from-chat}

### 可用工具 {#available-tools}

| 工具 | 用途 |
|---|---|
| `delegate_task` | 将任务委派给并行子代理。 |
| `send_message` | 向用户的另一个聊天发送消息，例如子代理或发起它的聊天。 |

`delegate_task` 接受要执行的 `task`、需要携带的可选 `context`（决定、文件路径、发现）、指定子代理需要打开之附件的可选 `file_ids`（请参阅[交接文件](#handing-over-files)）、用于选择模型所属子代理模型之一的 `model_id`，以及任务的简短 `title`（用于命名子代理聊天）。`send_message` 接收目标聊天的 `chat_id` 和 `message`。

模型编辑器中的**子代理**列表为父模型提供额外可选目标。当 `delegate_task` 调用省略 `model_id` 时，即使列表中包含其他模型，子代理仍会在当前模型上运行。

如果缺少预期目标，请检查该目标是否已在父模型上配置，并且运行聊天的用户是否可以使用。Open WebUI 只提供用户可访问的已配置目标。如果没有符合条件的目标，工具会省略 `model_id` 参数。

:::info 子代理类别也控制定时器
`timer` 工具来自同一类别和同一个 [`ENABLE_SUBAGENTS`](/reference/env-configuration#enable_subagents) 开关。关闭子代理会阻止新建定时器，而[已设置的定时器仍会触发](/features/chat-conversations/chat-features/timers#operator-notes)。
:::
