在 Open WebUI 中，**系统提示词（System Prompt）**和**高级参数（Advanced Parameters）**分为三个设置层级：按聊天、按模型和按账户。这一层级体系在保持结构化管理和控制的同时，提供了灵活性。

## 系统提示词与高级参数层级图 {#system-prompt-and-advanced-parameters-hierarchy-chart}

| **层级** | **定义** | **修改权限** | **覆盖能力** |
| --- | --- | --- | --- |
| **按聊天** | 特定聊天实例的系统提示词和高级参数 | 用户可以修改。系统提示词会替换按账户设置的提示词，并在模型的系统提示词之后发送 | 此处设置的高级参数会替代按账户和按模型设置的值，作为实际发送的值 |
| **按账户** | 特定用户账户的默认系统提示词和高级参数 | 用户可以设置。聊天自己的系统提示词会在该聊天中替换此提示词 | 此处设置的高级参数会替换按模型设置的值，但会被按聊天设置的值覆盖 |
| **按模型** | 特定模型的默认系统提示词和高级参数 | 管理员可以设置，用户不能修改 | 系统提示词最先发送，位于文件夹、聊天或账户的系统提示词之前，不会替换它们。高级参数适用于所有未自行设置这些参数的聊天 |

### 系统提示词如何组合 {#how-system-prompts-combine}

Open WebUI 会将以下各层级的系统提示词按此顺序合并为一条 `system` 消息，每部分占一行：

1. 在**工作区 > 模型（Workspace > Models）**中设置的模型**系统提示词**。
2. 聊天位于设有系统提示词的[文件夹](/features/chat-conversations/chat-features/conversation-organization#system-prompt)中时，该文件夹的**系统提示词**。
3. **控制（Controls）**中聊天的**系统提示词**。聊天未设置时，由**设置 > 常规（Settings > General）**中账户的**系统提示词**代替。两者绝不会同时发送。

`{{CURRENT_DATE}}` 等变量、[聊天变量](#chat-variables)和[用户变量](#user-variables)会在每个层级填充。Ollama 和兼容 OpenAI 的连接使用相同顺序。对 `/api/chat/completions` API 的请求遵循相同顺序，但请求自己的 `system` 消息会代替聊天或账户提示词。直接发送到 `/openai/chat/completions` 或 `/ollama/api/chat` 的请求只会获得模型的系统提示词，该提示词位于请求携带的任何 `system` 消息之前。

### 1. **按聊天设置：** {#1-per-chat-basis}

- **说明**：按聊天设置是指为特定聊天实例配置的系统提示词和高级参数。这些设置仅适用于当前对话，不影响以后的聊天。
- **设置方法**：打开**模型控制（Model controls）**菜单（消息输入框旁的旋钮图标）并展开**控制**。其中包含聊天的文件、阀门、系统提示词和高级参数；管理员及具有**允许聊天控制（Allow Chat Controls）**[权限](/features/authentication-access/rbac/permissions#3-chat-permissions)的用户可以看到。
- **覆盖能力**：此处设置的**系统提示词**会在该聊天中替换按账户设置的提示词（**#2**）。它不会替换模型的系统提示词（**#3**），后者仍会在其之前发送。此处设置的**高级参数**是该聊天实际发送的值，即使模型自身也携带该参数。

### 2. **按账户设置：** {#2-per-account-basis}

- **说明**：按账户设置是指为特定用户账户配置的默认系统提示词和高级参数。未定义较低层级的设置时，用户特定的更改可以作为回退。
- **设置方法**：用户可以在 Open WebUI 的**设置**菜单中的**常规**部分，为其账户设置自己的系统提示词和高级参数。
- **覆盖能力**：用户可以在账户上设置自己的系统提示词。对于**控制**中的**系统提示词**留空的每个聊天，都会发送此提示词；如果模型有系统提示词，则账户提示词在模型提示词之后发送。此处设置的**高级参数**会替代模型的参数发送，但会被聊天在**控制**中设置的任何值覆盖。

### 3. **按模型设置：** {#3-per-model-basis}

- **说明**：按模型设置是指为特定模型配置的默认系统提示词和高级参数。这些设置适用于使用该模型的所有聊天实例。
- **设置方法**：管理员可以在 Open WebUI **工作区**的**模型**部分，为特定模型设置默认系统提示词和高级参数。
- **覆盖能力**：**用户**账户不能修改按模型设置（**#3**）的**系统提示词**或特定**高级参数**。此限制可防止用户不当地更改默认设置。
- **系统提示词保留**：管理员在**工作区**部分设置模型的**系统提示词**后，该提示词会随使用此模型的每个聊天发送；**用户**账户无法从**常规**设置或聊天的**控制**中移除或编辑它。在这些位置设置的系统提示词会添加到模型提示词之后，而不是替代它。
- **参数优先级**：管理员在模型上设置的**高级参数**适用于所有未自行设置同一参数的聊天。**用户**账户在**常规**设置或聊天**控制**中设置该参数时，会发送自己的值，按聊天设置的值优先于按账户设置的值。任何这些层级都未设置的参数会回退到[全局模型默认值](/features/workspace/models#global-model-defaults-admin)中的实例级值。这包括上下文长度：聊天**控制**中设置的 `num_ctx` 就是实际发送的值，即使模型自身也携带该参数。**流式聊天响应（Stream Chat Response）**是例外：模型上设置的值优先，然后是聊天的值，最后是账户的值。
- **模型控制**：模型具有[模型控制](/features/workspace/models#model-controls)时，其中选择的选项（或控件的默认选项）高于所有层级：其参数会替换聊天**控制**、**常规**设置、模型或全局模型默认值中设置的相同参数。该选择按模型保存在账户上，因此会应用于使用该模型的所有聊天。

:::note `top_k` 接受整数

`top_k` 计算候选 token 数，因此只接受 0 到 1000 的整数。其滑块和数字框的步长均为 1；输入小数、负数或任何其他非整数时，不会接受该输入，而是保留先前的值。无论按聊天、按账户还是按模型编辑此参数，均适用此规则。

:::

## 高级参数中的 Ollama 参数 {#ollama-parameters-in-advanced-params}

**高级参数**还会列出以 Ollama 自身选项命名的参数。每项初始均为**默认（Default）**，不会发送任何内容。点击**默认**会将该行切换为**自定义（Custom）**，并填入下面的起始值；此后每个请求都会发送该值，直到再次点击**自定义**。

对于来自 Ollama 连接的模型，Open WebUI 会以相同名称将每个参数放入请求的 `options` 中。对于来自兼容 OpenAI 的连接的模型，会以相同名称将它们作为请求体的顶级字段发送，由提供方决定使用还是拒绝。

| 参数 | 发送给 Ollama 的形式 | 起始值 | 滑块范围 | 控制内容 |
| --- | --- | --- | --- | --- |
| **mirostat** | `options.mirostat` | `0` | 0 至 2 | 启用 Mirostat 采样（`1` 或 `2`），用于控制困惑度。`0` 表示关闭。 |
| **mirostat_eta** | `options.mirostat_eta` | `0.1` | 0 至 1 | Mirostat 对目前已生成文本的响应速度。 |
| **mirostat_tau** | `options.mirostat_tau` | `5` | 0 至 10 | Mirostat 下连贯输出与多样输出之间的平衡。值越低，输出越集中。 |
| **repeat_last_n** | `options.repeat_last_n` | `64` | -1 至 128 | 重复惩罚会回溯查看多少个最近的 token。 |
| **tfs_z** | `options.tfs_z` | `1` | 0 至 2 | 无尾采样。`1` 表示关闭，值越高，移除的低概率 token 越多。 |
| **repeat_penalty** | `options.repeat_penalty` | `1.1` | -2 至 2 | 对重复 token 的惩罚强度。`1` 表示关闭。 |
| **use_mmap** | `options.use_mmap` | 已启用 | 开或关 | 加载模型文件时是否使用内存映射。 |
| **use_mlock** | `options.use_mlock` | 已启用 | 开或关 | 是否将模型内存锁定在 RAM 中，使其不会交换到磁盘。 |
| **num_keep (Ollama)** | `options.num_keep` | `24` | -1 至 10240000 | 刷新上下文时保留多少 token。 |
| **num_batch (Ollama)** | `options.num_batch` | `512` | 256 至 8192 | 每批一起处理多少 token。值越高，需要的内存越多。 |
| **num_gpu (Ollama)** | `options.num_gpu` | `0` | 0 至 256 | 卸载到 GPU 的模型层数。 |

有关各选项在你的 Ollama 版本中的作用，请参阅 Ollama 的 [Modelfile 参数](https://docs.ollama.com/modelfile#valid-parameters-and-values)及其 [API 参考](https://github.com/ollama/ollama/blob/main/docs/api.md)中的“生成请求（带选项）”示例。这两个页面都未列出上面的所有选项。

**use_mmap**、**use_mlock**、**num_thread (Ollama)**、**num_gpu (Ollama)** 和 **keep_alive (Ollama)** 仅对管理员账户显示在**设置 > 常规**和聊天的**控制**中。**工作区 > 模型**中的模型编辑器和管理员[全局模型默认值](/features/workspace/models#global-model-defaults-admin)始终显示它们。任何层级设置的值都遵循上述[参数优先级](#3-per-model-basis)。

## **优化系统提示词设置，实现最大灵活性** {#optimize-system-prompt-settings-for-maximum-flexibility}

:::tip

**额外建议**
**此建议同时适用于管理员和用户账户。为了让系统提示词获得最大灵活性，建议考虑以下设置：**

- 将要使用的主要系统提示词（**即赋予 LLM 特定角色**）填写到**常规**设置的**系统提示词**字段中。这会将其设为账户级提示词，使其能够作为所有 LLM 的系统提示词，而无需在**工作区**部分的模型内进行调整。

- 对于次要系统提示词（**即赋予 LLM 要执行的任务**），选择将其放在**模型控制 > 控制**下的**系统提示词**字段中（按聊天设置），或由管理员放在**工作区**部分的**模型**部分中（按模型设置），以便直接设置。账户级系统提示词会与按模型设置的系统提示词共同生效，因为两者都会发送。**控制**中的按聊天系统提示词会在该聊天中替换账户级提示词。

- 作为管理员，应使用**模型**部分按模型分配 LLM 参数，以获得最佳灵活性。对于这两种次要系统提示词，请确保其设置方式能最大限度提高灵活性，并减少不同账户或聊天实例所需的调整。管理员账户和所有用户账户都需要理解**控制**和**模型**部分中的系统提示词应用到 **LLM** 的优先顺序。

:::

:::note 拒绝系统消息的模型

Open WebUI 会将系统提示词作为对话开头的 `system` 消息发送，无论它来自聊天、账户、文件夹还是模型。某些模型的聊天模板只接受用户和助手交替的对话轮次，模型服务器会拒绝请求并返回 `Conversation roles must alternate user/assistant` 等错误。请使用接受 system 角色的模型或聊天模板，或者在所有层级清除该模型的系统提示词。语音模式、技能和代码解释器等会向系统消息添加自身指令的功能，在这类模型上也会触发相同错误。

:::

## 聊天变量 {#chat-variables}

聊天变量可将模型的系统提示词变成一个简短表单。管理员在系统提示词中写入占位符，Open WebUI 会要求打开该模型聊天的用户填写。答案保存在该聊天中，并供其中每条消息重复使用。

在模型的系统提示词中声明一个变量：

```txt
{{chat.variables.key_name}}
```

这会生成一个单行文本字段。在竖线后添加定义可指定字段类型：

```txt
{{chat.variables.project_name | text:placeholder="Which project?":required}}
{{chat.variables.tone | select:options=["Formal","Casual"]:default="Formal"}}
```

语法和可用字段类型与[提示词输入变量](/features/workspace/prompts#available-input-types)相同。键必须使用小写蛇形命名：以字母开头，后接字母、数字或下划线。

:::danger 必须包含 `chat.variables.` 前缀

只有携带完整 `chat.variables.` 前缀的占位符才会声明聊天变量。裸 `{{project_name | text:required}}` 使用的是[提示词输入变量](/features/workspace/prompts#custom-input-variables)语法，它在提示词内容中有效，但在系统提示词中不起作用。

在系统提示词中这样写不会声明任何变量：聊天输入旁不会出现控件，也不会打开表单，占位符本身会作为字面文本发送给模型。系统不会发出任何警告，因此看起来就像模型忽略了此功能。

可检查模型编辑器中的**已检测变量（Detected Variables）**列表。该列表会随输入更新，缺少前缀的占位符绝不会出现在其中。

:::

### 填写变量 {#filling-them-in}

当所选模型声明聊天变量时，聊天输入旁会出现一个控件，用于打开**聊天变量（Chat Variables）**表单。选择模型不会打开它：只有按下该控件或尝试发送消息时才会显示。以后可以通过同一控件更改这些值，更改会应用于之后发送的消息。

只有没有可用于发送消息的内容时，发送消息才会打开表单而不实际发送，具体指以下任一情况：

- 某个 `required` 字段既没有值，也没有 `default`；或者
- **每个**字段都没有值，也没有 `default`。

否则，消息会直接发送给模型，任何未填写的变量都会替换为空字符串。

:::tip 在 `required` 和 `default` 之间选择

表单是输入门槛，而不是确认步骤，因此只有在聊天缺少答案就无法合理继续时才会中断。带有 `default` 的字段已经有答案，因此变量的所有字段都有默认值的模型会立即开始聊天。

这也意味着，只要有一个 `default`，就足以阻止表单因旁边的其他可选字段而出现。仍可通过聊天输入旁的控件访问这些字段，只是不会主动询问。

因此：必须由用户提供答案时，将字段标记为 `required`；允许聊天不作询问直接开始时，设置 `default`。

:::

值存储在聊天中，因此重新打开聊天会保留它们；分叉或克隆自己的聊天也会携带这些值。他人聊天的副本以空的聊天变量开始。在临时聊天中，它们随每个请求传递，并且只在该聊天存续期间有效。

单个值最多可包含 20,000 个字符，一个聊天的所有变量合计最多可包含 100,000 个字符。

:::warning 编辑定义可能清空现有聊天

组装提示词时，系统会根据当前定义验证值；如果其中任何一个值验证失败，该提示词中的每个聊天变量都会渲染为空，而不只是有问题的变量。因此，从 `select` 中移除选项会静默清空存储了该已移除值的聊天的整组变量。更改定义后，请重新打开受影响的聊天并重新填写表单。

:::

### 一个聊天中的多个模型 {#several-models-in-one-chat}

选择多个模型会合并它们的变量。相同定义会合并为一个字段；只要任一模型将其标记为必需，该字段就是必需的。如果两个所选模型以不同方式定义同一个键，系统会阻止发送，并列出冲突的键及定义它们的模型。请取消选择其中一个模型，或使定义一致。

### 编写检查 {#authoring-checks}

模型编辑器会在**已检测变量**下列出检测到的内容，并分为**聊天变量**和**用户变量（User Variables）**。它会警告以下情况：键不是小写蛇形命名、`select` 没有 `options=[...]`、同一个键有两种不同定义，以及用户变量带有定义；用户变量由每个用户自行配置，定义对其无效。

## 用户变量 {#user-variables}

用户变量可让一个共享系统提示词为每位使用者产生不同结果。管理员在模型的系统提示词中写入占位符，每位用户填写自己的值。

每位用户都在**设置 > 账户 > 用户变量（Settings > Account > User Variables）**下，以键值对列表的形式管理自己的值。在系统提示词中使用以下方式引用：

```txt
{{user.variables.key_name}}
```

请求时，每个占位符都会替换为该用户为该键设置的值。用户未设置的键会替换为空字符串，因此提示词中绝不会显示原始占位符。

例如，单个共享模型可以携带 `Address the user as {{user.variables.preferred_name}} and answer in {{user.variables.language}}.`，并正确适用于每位用户，而无需管理员为每个人维护一个模型。

### 键和值的规则 {#rules-for-keys-and-values}

- 键必须使用小写蛇形命名：以字母开头，后接字母、数字或下划线（`preferred_name`、`team2`）。不匹配的键会被拒绝。
- 值是纯文本。单个值最多可包含 20,000 个字符，一位用户的所有变量合计最多可包含 100,000 个字符。
- 值按用户存储，并且只会替换到该用户自己的请求中。

值属于个人信息，因此应将其视为用户提供的文本，而不是存放密钥的位置：变量中的任何内容都会插入发送给该聊天所配置模型的提示词。

### 使用用户变量还是聊天变量？ {#user-variables-or-chat-variables}

两者都写入模型的系统提示词，也都由用户而不是管理员填写。区别在于向谁询问，以及答案保留多久。

| | 聊天变量 | 用户变量 |
| --- | --- | --- |
| 编写形式 | `{{chat.variables.key}}` | `{{user.variables.key}}` |
| 由谁填写 | 打开聊天的人在表单中填写 | 每位用户在**设置 > 账户**中填写一次 |
| 保留多久 | 仅该对话 | 该用户发送的每个请求 |
| 字段类型 | 有类型，在竖线后定义 | 仅纯文本 |
| 何时询问 | 聊天开始时 | 从不询问，提前设置 |
