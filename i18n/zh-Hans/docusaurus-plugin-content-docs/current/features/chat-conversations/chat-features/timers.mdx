# 定时器

定时器让模型可以稍后再次找你。模型使用提示词和时间调用 `timer` 内置工具；到达指定时间后，该提示词会被发送回同一聊天并得到回答，就像是你亲自输入的一样。

定时器适用于任何需要自然等待的场景：十分钟后检查长时间运行的作业、明天跟进某项决定，或者提醒你处理对话中已经具备上下文的事项。由于定时器会在原始聊天中重新触发提示词，模型仍可利用完整对话。

定时器是**一次性**的。对于任何重复执行的需求，请使用专为计划任务设计的[自动化](/features/chat-conversations/chat-features/automations)。

## 启用定时器 {#enabling-timers}

定时器**没有独立的开关**。它们属于**子代理**功能，由默认关闭的 [`ENABLE_SUBAGENTS`](/reference/env-configuration#enable_subagents) 启用。

:::warning 定时器由子代理设置启用
`timer` 工具会与 `delegate_task` 一同注入，并共享相同的启用条件：[`ENABLE_SUBAGENTS`](/reference/env-configuration#enable_subagents)、每个模型的**子代理**内置工具类别以及[子代理权限](/features/chat-conversations/chat-features/subagents#enable-sub-agents)。没有单独的定时器类别或权限，因此**关闭子代理也会移除 `timer` 工具**，启用定时器就意味着启用子代理。
:::

与其他内置工具一样，定时器还要求在从界面发起的聊天中使用原生函数调用，并且在子代理聊天内不可用。

## 设置定时器 {#setting-a-timer}

模型使用提示词、时间以及可选的取消事件来设置定时器。时间可以表示为**相对偏移量**，也可以表示为**必须包含明确时区的 RFC 3339 时间戳**。不带时区的时间戳会被拒绝，系统不会猜测时区；所设时间必须位于未来。

相对偏移量支持多种表述方式：`10s`、`5m`、`1h`、`2d` 均可使用，`+10s`、`in 10 seconds`、`5 minutes` 和 `2 hours` 也同样有效。支持的单位包括秒、分钟、小时和天。

定时器会在接近指定时间时触发：调度器每秒检查一次。[`TIMER_POLL_INTERVAL`](/reference/env-configuration#timer_poll_interval) 可以增大该间隔，以降低准时性为代价减少空闲轮询，但不能将其设置为一秒以下。

## 定时器触发时会发生什么 {#what-happens-when-a-timer-fires}

提示词会作为一条消息追加到原始聊天中，聊天自动重新加载，模型则使用设置定时器时该聊天所具有的模型、工作区工具、技能、过滤器和设置进行回答。该配置会预先捕获，因此之后对聊天所做的更改不会影响待触发定时器的行为。

定时器触发时会重新构建系统提示词，所使用的组成部分与原始消息相同：聊天自己的系统提示词（来自 **模型控制 > 控制** 或你的 **设置**）、模型的系统提示词、聊天变量，以及消息中提及的任何技能的完整文本。文件夹的系统提示词、工具服务器和终端指令也会像聊天中的其他消息一样应用。

工具服务器会随聊天的工具 ID 一起传递，附加文件、所选机器和提示词变量也是如此。你在 [Tether](/ecosystem/tether#bring-your-own-models-and-tools) 中添加的工具服务器只有在定时器触发时 Tether 设备已连接才能解析；如果提示词的全部工作都依赖该服务器，请务必注意这一点。

定时器绝不会打断你：如果到期时聊天正在生成内容，它会等待聊天空闲后再触发。

触发定时器本身**不会**通知你，只会在聊天中生成回复。若要在其他地方收到通知，请将定时器与[通知](/features/chat-conversations/chat-features/notifications)结合使用，让定时器的提示词引导模型调用 `notify`。

## 取消定时器 {#cancelling-a-timer}

定时器可以携带 `cancel_on` 事件；如果其中一个事件先发生，定时器就会被取消：

| 事件 | 含义 |
|---|---|
| `chat.read` | 你打开并阅读了该聊天。 |
| `chat.user_message` | 你亲自在该聊天中发送了一条消息。 |

“除非我已经处理，否则一小时后提醒我”就是通过这种方式实现的：如果你自行回来处理，提醒就不会再出现。

:::info 待触发定时器会列在状态面板中
聊天顶栏的**状态**按钮会列出该聊天中待触发的定时器，点击**取消**即可移除其中一个。没有 `cancel_on` 事件的定时器除非在此处取消，否则一定会触发。定时器触发后，聊天中会出现一个可折叠的**定时器**行。
:::

## 运维注意事项 {#operator-notes}

- **定时器在重启后仍然保留。**它们存储在数据库中而非内存中，调度器会在启动时恢复。如果定时器在服务器停机期间已经到期，它会在启动后不久触发，而不会被跳过，因此只会迟到，不会缺席。
- **即使之后禁用子代理，待触发定时器仍会触发。**该设置控制的是*创建*定时器，而不是调度器。关闭它会阻止新建定时器，但不会取消已设置的定时器。
- **调度器每次轮询最多认领 10 个到期定时器。**这是批处理限制，而不是每个用户的配额，因此积压任务会分批处理。
- **用户可以设置的定时器数量、提前时间或彼此间隔均没有限制。**自动化具有 [`AUTOMATION_MAX_COUNT`](/reference/env-configuration#automation_max_count) 和 [`AUTOMATION_MIN_INTERVAL`](/reference/env-configuration#automation_min_interval)；定时器没有对应限制。
- **每次定时器触发都会产生一次模型调用**，因为它会在聊天中生成实际回复。

## 从聊天中管理定时器 {#managing-timers-from-chat}

### 可用工具 {#available-tools}

| 工具 | 用途 |
|---|---|
| `timer` | 设置一次性定时器，在触发时将提示词发送回此聊天。 |

### 要求 {#requirements}

- 已启用 [`ENABLE_SUBAGENTS`](/reference/env-configuration#enable_subagents)。
- 已在模型上启用**子代理**内置工具类别。
- 具有[子代理权限](/features/chat-conversations/chat-features/subagents#enable-sub-agents)（管理员始终通过）。
- 在从界面发起的聊天中使用原生函数调用。
