# 自动补全

Open WebUI 提供 **AI 驱动的自动补全**功能，可在输入提示词时实时建议文本补全内容。它就像聊天输入的“Copilot”，利用你配置的任务模型帮助更快地编写提示词。

## 工作原理 {#how-it-works}

启用后，Open WebUI 会监测聊天框中的输入。暂停输入时，它会将当前文本发送给轻量级**任务模型（Task Model）**。此模型会预测接下来可能输入的词语或句子，并以覆盖在输入内容上的“幻影文本”形式显示。

- **接受建议**：按 `Tab` 接受建议。向右方向键仅移动插入光标。
- **在触摸屏上接受**：在聊天输入区域向右滑动超过 50 像素。上下移动距离大于左右移动距离的滑动不算。
- **拒绝/忽略**：只需继续输入，即可覆盖建议。

:::info
**性能建议**

自动补全功能高度依赖**任务模型**的响应速度。建议使用小型、快速的**非推理**模型，以确保建议即时显示。

**推荐模型：**
- **Qwen 3.5**（`qwen3.5:0.8b` 或 `qwen3.5:2b`）
- **GPT-5.6 Luna**（针对低延迟和低成本优化）
- **Gemini 3.5 Flash-Lite**

此功能应避免使用推理模型和大型思维链模型——延迟会使自动补全体验变得迟缓。
:::

## 配置 {#configuration}

自动补全功能由两层系统控制：**全局**可用性和**用户**偏好。

### 1. 全局配置（管理员） {#1-global-configuration-admin}

管理员控制服务器是否提供自动补全功能。

### 1. 配置自动补全（全局） {#1-configuring-autocomplete-global}

**管理员面板设置：**
前往**设置 > 界面（Settings > Interface）**（管理区域），在**生成（Generation）**下切换**自动补全生成（Autocomplete Generation）**。

### 2. 用户配置（个人） {#2-user-configuration-personal}

即使已全局启用，如果用户觉得该功能容易分散注意力，也可以自行关闭。

- 前往**设置 > 界面**。
- 切换**提示词自动补全（Prompt Autocompletion）**。

个人设置的标签与管理员设置不同，后者显示为**自动补全生成**。两者控制的是同一功能。

:::note
如果管理员已全局禁用自动补全，用户将**无法**在个人设置中启用它。
:::

## 性能与故障排除 {#performance--troubleshooting}

### 为什么没有显示建议？ {#why-arent-suggestions-appearing}
1. **检查设置**：确保管理员和用户设置中**均已**启用。
2. **任务模型**：前往**设置 > 界面**（管理区域），检查选择了哪个**任务模型**。未设置任务模型时，由聊天当前使用的模型生成建议，因此会阻止生成的是聊天中未选择模型。管理员开关下有两个字段：**自动补全生成输入最大长度（Autocomplete Generation Input Max Length）**（`AUTOCOMPLETE_GENERATION_INPUT_MAX_LENGTH`，默认 `-1` 表示无限制；将其保存为空时，会存储环境变量的值，未设置该变量时则存储 `-1`）和**自动补全生成提示（Autocomplete Generation Prompt）**。此功能在两端默认均关闭：管理员开关（`ENABLE_AUTOCOMPLETE_GENERATION`，默认 `False`）和每个用户的**提示词自动补全**开关。
3. **延迟**：如果任务模型很大或运行在速度较慢的硬件上，预测结果可能到达得太晚而失去作用。请切换到较小的模型。
4. **推理模型**：确保未使用“推理”模型（例如 o1 或 o3），因为其内部思考过程会产生过高延迟，导致实时自动补全无法正常工作。如果必须使用此类模型，可在**设置 > 界面**（管理区域）的**任务模型参数（Task Model Parameters）**下调低其 `reasoning_effort`。该设置由所有后台任务共享，因此请先阅读[任务模型](/features/administration/task-models#task-model-parameters)。

### 性能影响 {#performance-impact}
自动补全实质上会在你每次暂停输入时（经防抖处理）向 LLM 发送请求。
- **本地模型**：这可能会占用宿主机大量 GPU/CPU 资源。
- **API 提供方**：这会产生大量 API 调用（不过每次调用的 token 数通常很少）。请注意提供方的**速率限制**（每分钟请求数/RPM 和每分钟 token 数/TPM），以免服务中断。

:::warning
对于在有限本地硬件上运行的多用户实例，建议**禁用**自动补全，将资源优先用于实际的聊天生成。
:::
