# 文件夹与项目

Open WebUI 提供强大的文件夹组织功能，将简单的聊天容器转变为功能完整的**项目工作区**。文件夹不仅可以分组相关对话，还可以定义特定上下文、系统提示词和知识库，并应用于其中的所有聊天。

## 启用文件夹 {#enabling-folders}

文件夹默认启用。管理员可以通过以下方式控制此功能：

- **管理员面板**：文件夹功能与其他功能一起接受全局控制。
- **环境变量**：[`ENABLE_FOLDERS`](/reference/env-configuration#enable_folders)。设为 `True`（默认）可启用，设为 `False` 可禁用。

## 核心功能 {#core-features}

### 创建文件夹 {#creating-folders}

创建新文件夹来组织对话：

1. 在**侧边栏**中，点击“文件夹”部分标题上的 **+ 按钮**。
2. 选择**“新建文件夹（New Folder）”**。
3. 输入文件夹名称。
4. 点击**保存（Save）**。

### 将对话移入文件夹 {#moving-conversations-into-folders}

通过将现有聊天移入文件夹来组织它们：

- **拖放**：点击侧边栏中的任意对话，将其拖入文件夹。
- **对话菜单**：将鼠标悬停在侧边栏中的对话上，点击出现的三点菜单，然后选择**移动（Move）**并选择目标文件夹。至少存在一个文件夹后，此入口才会显示。

如果你有权将聊天归入某个文件夹，拖动聊天经过该文件夹时，文件夹会高亮，让你在松开前看到聊天将放入何处。你自己的文件夹始终接受聊天。对于[与你共享的文件夹](#sharing-folders)，只有拥有写入权限时才会接受聊天；只有只读权限时不会高亮。

### 嵌套文件夹 {#nested-folders}

文件夹可以嵌套在其他文件夹中，形成层级结构：

- **从菜单创建子文件夹**：点击任意文件夹上的三点菜单，选择**“创建文件夹（Create Folder）”**，即可直接在其中创建新的子文件夹。
- **拖放**：将一个文件夹拖到另一个文件夹上，使其成为子文件夹。
- **重新排序**：将一个文件夹拖到另一个文件夹的正上方或正下方，即可将其放在该位置，并与目标文件夹处于同一层级。顺序会随设置保存，因此在每台设备上都相同；尚未手动放置的文件夹会按名称排在末尾。共享文件夹始终按名称排序。
- **导出**：文件夹上的同一个三点菜单还提供**导出（Export）**，用于下载文件夹中的聊天。此操作需要[允许聊天导出（Allow Chat Export）](/features/authentication-access/rbac/permissions#3-chat-permissions)权限。菜单中没有移动入口，只能通过拖放更改文件夹的父级。
- 文件夹可以展开或折叠，以显示或隐藏其内容。
- 子文件夹名称在同一父文件夹内必须唯一。如果输入重复名称，系统会自动追加数字（例如“笔记 1”）。

子文件夹中的聊天使用该文件夹自己的**系统提示词（System Prompt）**和**知识（Knowledge）**设置。例如，如果父文件夹附加了手册，也需要将手册附加到子文件夹，才能让其聊天自动使用该手册。

### 未读徽章 {#unread-badge}

文件夹名称旁会显示其中你尚未阅读，或正在等待你批准工具调用的聊天数量。

- 计数包括文件夹自己的聊天及其子文件夹中的所有聊天，因此即使折叠父文件夹，也能看到下级有哪些项目等待处理。
- 聊天自你上次打开后发生变化，就会计为未读。已归档聊天从不计入；回复仍在生成的聊天要等回复完成后才计入。因工具批准而暂停的聊天会立即计入一次。
- 打开聊天会立即在你打开的所有窗口中将其从计数中清除：服务器会即时重新计算你的文件夹计数并推送到其他会话，而不是等到下次重新加载。
- 未读状态只与你自己的阅读情况有关。共享文件夹不显示徽章，属于其他人的聊天无论最近是否有变动，都不会对你显示为未读。
- 自动为聊天生成标题不会使其重新变为未读。

文件夹页面也会为每个聊天标记相同状态：未读对话显示圆点，答案仍在流式生成的对话显示加载指示器，等待批准的对话显示黄点。页面会在你查看时持续更新：聊天开始或结束生成时就地更新，新聊天进入文件夹时无需完整刷新即可插入，断开的连接恢复后页面会重新加载。从该页面打开聊天会立即清除其圆点，无需等待聊天加载。有关按活动状态排序、分组和筛选的信息，请参阅[文件夹页面](#the-folder-page)。

#### 标记已读和未读 {#marking-read-and-unread}

- **将聊天标记为未读**：打开侧边栏中聊天的三点菜单，选择**标记为未读（Mark as unread）**。聊天会重新显示圆点，与其他未读聊天一起上移，文件夹计数也会再次增加。快速浏览后仍想持续关注某段对话时，可以使用此功能。
- **将文件夹标记为已读**：打开文件夹的三点菜单，选择**全部标记为已读（Mark all as read）**。对于自己拥有的文件夹，这会清除该文件夹及其中所有嵌套文件夹内你的未读聊天。对于与你共享的文件夹，它只会清除该文件夹中你自己的聊天。已归档聊天不受影响。
- **将所有内容标记为已读**：侧边栏中的**聊天（Chats）**部分标题有自己的菜单，其中的**全部标记为已读（Mark all as read）**会清除你拥有的全部未读聊天，包括未放入文件夹和已放入文件夹的聊天，并同时将所有文件夹徽章归零。已归档聊天同样不受影响。

### 在文件夹中开始聊天 {#starting-a-chat-in-a-folder}

点击侧边栏中的文件夹后，它会成为你的**当前工作区**：

1. 点击侧边栏中的任意文件夹将其选中。
2. 聊天界面会显示该文件夹处于活动状态。
3. 你开始的任何新聊天都会自动在此文件夹中创建。
4. 新聊天会**继承文件夹的设置**（默认模型、机器、工作目录、系统提示词和知识）。

文件夹的三点菜单也提供**新建聊天（New Chat）**，会以相同方式打开该文件夹。

侧边栏中的每个文件夹都是指向自己页面的链接，因此鼠标中键点击或 Ctrl/Cmd 点击可以在新标签页中打开文件夹。

文件夹会为你保留自己的标签页，因此再次打开它会恢复你在其中留下的聊天、文件和终端。新聊天页面会在**继续（Continue）**下列出你有进行中工作的文件夹，包括聊天正在运行或等待你批准，或者仍有标签页打开的文件夹，方便你从中断处继续。

将聊天移入文件夹需要对该文件夹拥有**写入权限**。这意味着文件夹属于你，或者通过直接或上级文件夹继承的共享权限，让你获得写入权限。共享文件夹的只读权限允许你打开并阅读其中的聊天，但在其中发送新聊天的第一条消息会被拒绝，系统不会在不提示的情况下将聊天移入文件夹。

在为聊天指定文件夹的三个位置，都会执行相同检查：通过 API 创建聊天、将现有聊天移入文件夹，以及在文件夹中开始的聊天发送第一条消息。指定不存在的文件夹，会像指定无权写入的文件夹一样被拒绝。

## 文件夹页面 {#the-folder-page}

点击侧边栏中的文件夹，其页面会以类似小型项目跟踪器的布局显示其中的所有聊天。它适合收集较多对话的文件夹，例如研究项目、请求队列或每周报告，让你了解哪些已经完成、哪些正在等待、哪些需要关注。在与你共享的文件夹中，页面的工作方式相同，而你可以更改的内容取决于访问权限。

### 列表和看板 {#list-and-board}

打开**显示选项（Display options）**（搜索和筛选旁的滑块图标），选择一种**布局（Layout）**。

- **列表（List）**为每个聊天显示一行。**分组（Grouping）**可按**状态（Status）**、**优先级（Priority）**、**标签（Tags）**或**活动状态（Activity）**将其拆分为可折叠组，也可以通过**无（None）**保留为单个列表。空组默认隐藏，开启**显示空组（Show empty groups）**后才会显示。
- **看板（Board）**将每个聊天显示为卡片。**列（Columns）**可选择以**状态（Status）**、**优先级（Priority）**、**标签（Tags）**或**活动状态（Activity）**划分各列，**行（Rows）**则可使用其余维度之一添加横向泳道。以状态为列时，看板的工作方式类似 Kanban 视图。

**排序（Ordering）**支持按**更新时间（Updated）**、**标题（Title）**或**优先级（Priority）**升序或降序排列。布局、分组、列、行和排序会保存在浏览器中，而筛选条件在每次访问时都从空值开始。

**活动状态（Activity）**显示聊天目前正在做什么：**未读（Unread）**（自你上次打开后发生变化）、**正在生成（Generating）**、**等待批准（Waiting for approval）**（因工具批准而暂停）和**已读（Read）**。行和卡片会用圆点或加载指示器标记前三种状态，让需要你的聊天更加醒目。

### 搜索和筛选 {#searching-and-filtering}

搜索图标或 `/` 键会打开搜索框，可匹配聊天标题和消息文本。筛选图标或 `f` 键会打开一个菜单，其中包含**状态（Status）**、**优先级（Priority）**、**标签（Tags）**、**用户（Users）**、**活动状态（Activity）**和**更新时间（Updated）**（**今天（Today）**、**最近 7 天（Last 7 days）**或**最近 30 天（Last 30 days）**）。状态、优先级、标签和用户都支持同时选择多个值，标签列表还包含用于无标签聊天的**未添加标签（Untagged）**。

列表或看板中的每个聊天都有与侧边栏相同的三点菜单，提供重命名、移动、克隆、分享、归档、删除和标记为未读。在其他人发起的聊天中，菜单只有**重命名（Rename）**。在以只读方式与你共享的文件夹中，不是你发起的聊天没有菜单。

### 状态 {#statuses}

状态表示聊天当前所处的阶段，例如**进行中（In progress）**或**已完成（Done）**。文件夹初始没有状态，没有状态的聊天显示为**无状态（No status）**。可在**编辑状态…（Edit statuses…）**下添加自己的状态；在文件夹拥有任何自定义状态之前，这里会提供**待办池（Backlog）**、**待处理（To do）**、**进行中（In progress）**、**等待中（Waiting）**和**已完成（Done）**作为建议。

点击聊天开头的状态图标选择状态，或在使用状态的看板上将其卡片拖到另一列或泳道。聊天所有者始终可以设置状态。在共享文件夹中，任何可以编辑该文件夹的人都可以设置其中所有聊天的状态。对于设有状态的聊天，状态旁会显示其处于当前状态的时长，例如 **3d**。此前处于同一状态的时间也会计入其中。

任何可以编辑文件夹的人，都可以通过状态菜单底部的**编辑状态…（Edit statuses…）**，或状态看板末尾的**添加状态（Add status）**更改文件夹状态。**状态（Statuses）**对话框支持更改名称（最多 40 个字符，在文件夹内唯一）、图标（内置形状或**使用表情符号…（Use emoji…）**）和颜色，并可通过拖动调整顺序，也可以添加和删除状态。被删除状态中的聊天会恢复为**无状态（No status）**。

聊天还可以通过其优先级图标设置优先级（**紧急（Urgent）**、**高（High）**、**中（Medium）**或**低（Low）**），权限规则与状态相同。

### 标签 {#tags}

标签按主题标记聊天，并为上述分组、看板和筛选选项提供数据。聊天所有者可以添加标签；在共享文件夹中，任何可以编辑文件夹的人也可以添加。将鼠标悬停在聊天行上会出现**标签（Tag）**按钮，也可以点击已有标签；对于自己的聊天，还可以从聊天顶栏菜单的**标签（Tags）**子菜单中添加。这些方式都会打开同一个选择器：输入文字查找标签，勾选即可添加或移除。要创建新标签，请选择**创建“名称”（Create “name”）**。已勾选标签旁的彩色圆点会打开颜色选项，颜色会应用于使用该标签的所有位置。文件夹编辑者在他人聊天上添加、移除或重新着色的标签仍属于聊天所有者，因此会显示在所有者自己的标签列表中。没有编辑权限的人只能看到标签，无法使用选择器。

### 笔记 {#notes}

文件夹可以在聊天旁边保存[笔记](/features/notes)，例如项目简报或会议记录。在文件夹页面顶部的切换控件中选择**笔记（Notes）**，即可列出文件夹中的笔记，无论作者是谁。可以通过以下任一方式添加笔记。

- 点击文件夹页面标题中切换控件右侧的 **+**，或在侧边栏中文件夹的 **⋯** 菜单里选择**新建笔记（New Note）**。
- 将笔记从“笔记”列表拖到侧边栏中的文件夹上，或在笔记的 **⋯** 菜单中选择**移动（Move）**并挑选文件夹。选择**移动 > 无文件夹（Move > No folder）**可将笔记移出。

添加笔记需要文件夹的写入权限。删除文件夹时，如果勾选了**删除此文件夹内的所有内容（Delete all contents inside this folder）**，其中所有者的笔记也会被删除；其他人放入的笔记会移出文件夹，并仍归各自所有。

### 自动化 {#automations}

页面标题提供**聊天（Chats）**、**笔记（Notes）**、**自动化（Automations）**和**知识（Knowledge）**切换控件。**笔记（Notes）**会向拥有笔记功能的用户显示。**自动化（Automations）**会向拥有[自动化](/features/chat-conversations/chat-features/automations)功能的用户显示，其中列出文件夹的自动化，并提供**新建自动化（New automation）**按钮。有关各类用户可以执行的操作，请参阅“自动化”页面上的[文件夹](/features/chat-conversations/chat-features/automations#folders)。

### 通过标签页重命名 {#renaming-from-the-tab}

双击顶部的文件夹标签页即可重命名文件夹。此操作需要文件夹的编辑权限。

## 文件夹设置（项目配置） {#folder-settings-project-configuration}

文件夹可以配置为具有独立 AI 行为和上下文的完整项目工作区。要编辑文件夹设置：

1. 将鼠标悬停在侧边栏中的文件夹上。
2. 点击**三点菜单**（⋯）。
3. 选择**“编辑（Edit）”**打开文件夹设置弹窗。

在桌面端，将指针停留在侧边栏的文件夹名称上会显示文件夹预览：聊天数量、默认模型、附加的知识条目数量；对于与你共享的文件夹，还会显示所有者姓名。拥有写入权限时，预览还会提供**编辑文件夹（Edit Folder）**按钮，用于打开相同的设置。

![共享的 Product Launch 文件夹的悬停预览：5 个聊天、由 Alex Chen 共享、默认模型为 Team Assistant、两个知识条目，以及“编辑文件夹”按钮](/images/features/chat/folder-hover-preview.webp)

### 文件夹名称 {#folder-name}

更改文件夹名称，使其更准确地反映用途或项目。

### 描述 {#description}

添加一段简短说明，介绍文件夹的用途。它会显示在文件夹页面的文件夹名称下方，超过两行后截断。

### 文件夹背景图片 {#folder-background-image}

上传背景图片，自定义文件夹的视觉外观。这有助于在工作区中直观区分不同项目。

### 默认模型 {#default-model}

选择此文件夹中的新聊天初始使用的模型，或保留**使用默认值（Use default）**以回退到你通常使用的默认模型。在文件夹的某个聊天内切换模型不会更改文件夹默认值，因此如需更改，请在此处设置。

### 默认机器和工作目录 {#default-machine-and-working-directory}

在**高级（Advanced）**下，**机器（Machine）**用于选择文件夹运行所在的机器。其中的聊天、文件和终端都会使用该机器，并从**工作目录（Working directory）**启动；此字段为空时，使用机器自己的默认目录。如果机器按聊天或模型使用独立实例，每个聊天可以选择另一台机器。文件夹的机器对你不可用期间，你在该文件夹中自己聊天的消息输入框会被禁用。文件夹按钮可以浏览机器目录，你还可以在其中[将 Git 仓库克隆](/features/open-terminal/file-browser#cloning-a-repository)到新文件夹。选择机器后，**默认模型（Default Model）**还会提供该机器的[代理](/features/open-terminal/agents)。

### 系统提示词 {#system-prompt}

为文件夹指定专用的**系统提示词（System Prompt）**，自动应用于其中的所有对话：

- 系统提示词会**添加到文件夹中的每个聊天**，包括之后移入的聊天。它在模型的系统提示词之后、聊天或账户的系统提示词之前发送（[顺序](/features/chat-conversations/chat-features/chat-params#how-system-prompts-combine)）。
- 这可以针对特定任务或角色定制 AI 行为。
- 系统提示词是可选的。你可以只将文件夹用于组织，而不设置提示词。

:::info

只有拥有设置系统提示词的权限（由管理员设置控制）时，系统提示词字段才会显示。

:::

### 附加知识 {#attached-knowledge}

文件夹页面还包含**知识（Knowledge）**部分，列出文件夹中的新聊天会使用的内容。

在文件夹的**知识（Knowledge）**字段（位于**高级（Advanced）**下）中附加**知识库、笔记和文件**，其选择器与模型编辑器相同（[附加知识和笔记](/features/workspace/knowledge#attaching-knowledge-and-notes)）：

- 文件夹中的每个聊天都会使用这些内容，并[将知识工具限制在附加条目范围内](/features/workspace/knowledge#scoped-access-keeps-things-organized)。
- 使用 **Native** 函数调用时，模型会获得文件夹知识列表，并通过**知识库（Knowledge Base）**[内置工具](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)读取，无论**预加载文件（Preload files）**是否开启。使用 **Legacy** 函数调用时，在**预加载文件（Preload files）**开启期间，系统会通过 RAG（检索增强生成）检索并注入知识。
- 知识是可选的。不附加任何文件，文件夹也可用于组织。
- **将文件夹附加到另一个聊天。**文件夹会列在 `#` 菜单中，也可以从侧边栏拖入消息输入框。这会附加与文件夹关联的文件和知识库，且仅在**预加载文件（Preload files）**开启时有效。关闭预加载文件时，请直接使用 `#` 附加文件夹的知识库和文件，或在文件夹内开始聊天。

**由谁的访问权限决定可附加内容。**附加操作同时需要你的访问权限和**文件夹所有者的**访问权限。之后，文件夹中的每个聊天都遵循所有者的访问权限。

- 将文件、知识库或笔记附加到文件夹时，附加者和所有者都必须能够读取它。因此，拥有共享文件夹写入权限的人，也不能向其中附加所有者自己无法打开的文档，包括附加者自己的私人文档，同样不能附加附加者自己无法打开的文档。相同检查也适用于在共享文件夹内创建的子文件夹，该子文件夹属于父文件夹的所有者。
- 文件夹中的每个聊天在使用附件前，都会根据所有者当前的访问权限重新检查附件。如果所有者在附加知识库后失去访问权限，该知识库将不再用于文件夹中的聊天。
- 不是文件、知识库或笔记的条目，或不带 ID 的条目，会被忽略。

## 共享文件夹 {#sharing-folders}

与特定用户或用户组共享文件夹及其中聊天，让团队使用同一组对话开展工作。

共享文件夹需要**文件夹共享（Folders Sharing）**权限，该权限默认关闭。管理员可以在**管理员面板 > 用户 > 用户组（Admin Panel > Users > Groups）**中开启，也可以使用 [`USER_PERMISSIONS_FOLDERS_ALLOW_SHARING`](/reference/env-configuration#user_permissions_folders_allow_sharing) 配置。

1. 在侧边栏或文件夹页面上打开文件夹的**三点菜单**（⋯），选择**分享（Share）**。这会打开文件夹的**访问（Access）**对话框。管理员以及拥有**文件夹共享（Folders Sharing）**权限的文件夹所有者可以看到此入口。**编辑文件夹（Edit Folder）**对话框顶部的**访问（Access）**按钮会打开同一个对话框。
2. 添加要共享的用户或用户组。每个条目一开始都是**写入（Write）**权限。根据需要，在其**访问列表（Access List）**行中切换为**读取（Read）**：
   - **读取（Read）**：可以打开文件夹并阅读其中的聊天，不能在其中开始聊天或将聊天移入；在侧边栏中将聊天拖到文件夹上时，也不会将其作为放置目标。
   - **写入（Write）**：还可以重命名文件夹、在其中开始聊天、将自己的聊天移入其中，并在其中创建子文件夹。在侧边栏中将聊天拖到文件夹上时，文件夹会高亮并接受聊天。
3. 选择**共享模式（Sharing mode）**。你可以在任何人获得访问权限之前设置，使文件夹在添加人员时即可使用：
   - **仅克隆（Clone only）**（默认）：共享对象可以阅读文件夹中的聊天，并克隆聊天以便自己继续。
   - **允许回复（Allow replies）**：对文件夹拥有**写入（Write）**权限的人可以直接向其中的聊天发送消息，这些聊天随后会像[允许回复的共享聊天](/features/chat-conversations/chat-features/chatshare#allowing-replies)一样工作。拥有**读取（Read）**权限的人可以阅读并克隆这些聊天，与**仅克隆（Clone only）**相同。子文件夹中的聊天遵循该子文件夹自己的共享模式，需要在子文件夹自己的**访问（Access）**对话框中设置。设置之前，这些聊天以只读方式打开。

每项更改都会在操作时立即生效。

只有文件夹所有者或管理员可以更改文件夹的共享对象及共享模式。拥有写入权限的人不会在**编辑文件夹（Edit Folder）**对话框中看到**访问（Access）**按钮。

**添加访问权限（Add Access）**选择器只列出尚未共享该文件夹的人员和用户组，因此无法重复添加同一个人，列表也会随着添加而缩短。要在**读取（Read）**和**写入（Write）**之间更改某人权限，或完全移除其权限，请改用此人在**访问列表（Access List）**中的行。

共享文件夹会显示在接收者的侧边栏中。需要了解以下规则：

- **子文件夹继承共享。**文件夹上授予的访问权限会级联到其中嵌套的所有内容。某人通过继承获得子文件夹的**写入（Write）**权限，同时又直接获得该子文件夹的**读取（Read）**授权时，以**写入（Write）**为准。共享模式按文件夹应用，因此要回复子文件夹中的聊天，需要在该子文件夹上启用**允许回复（Allow replies）**。
- **其他人的聊天会显示在其名下。**在设为**仅克隆（Clone only）**的文件夹中，聊天为只读。启用**允许回复（Allow replies）**且拥有文件夹**写入（Write）**权限时，聊天会带着消息输入框打开，你可以向其中写入内容。每条消息都带有发送者的姓名和头像，无论是在对话中，还是**概览（Overview）**标签页的消息节点上，都会显示。
- **文件夹所有者可以整理其他人的聊天。**在你拥有的文件夹中，你可以重命名其他人发起的聊天（仅限标题），并将它们移动到同一共享树中的其他文件夹。
- **共同编辑和重新生成。**启用**允许回复（Allow replies）**后，拥有**写入（Write）**权限的人可以将任何提示词编辑为新分支，并重新生成任何回复，与[允许回复的共享聊天](/features/chat-conversations/chat-features/chatshare#allowing-replies)相同。
- **每个聊天都会显示参与者。**在共享文件夹中，侧边栏和文件夹页面上的每个聊天都会显示参与者的头像，聊天所有者排在最前。最多显示三个头像，随后显示 **+2** 等数量。点击数量可查看所有人。将鼠标悬停在头像上或点击头像，可打开此人的个人资料卡片。
- **共享文件夹中的聊天可以作为上下文附加。**将聊天从侧边栏拖到另一个聊天的消息输入框中，模型就会收到该对话的消息，与你自己的聊天相同。文件夹的读取权限即可满足要求，无论是直接授予还是从上级文件夹继承。
- **归档聊天会将其移出文件夹。**只能通过该文件夹看到聊天的人会失去访问权限。
- **只有所有者或管理员可以删除共享根文件夹。**拥有写入权限的人可以添加和编辑聊天及子文件夹。
- **写入权限涵盖文件夹页面。**拥有写入权限的人可以设置文件夹中每个聊天的状态和优先级，并更改文件夹状态；拥有读取权限的人可以查看状态。请参阅[文件夹页面](#the-folder-page)。
- **自动化可以向共享文件夹发布内容。**任何拥有写入权限的人都可以在其中创建自动化，所有可以向文件夹写入内容的人都可以暂停自动化。请参阅“自动化”页面上的[文件夹](/features/chat-conversations/chat-features/automations#folders)。
- **克隆聊天以便自己继续。**在设为**仅克隆（Clone only）**的文件夹中，或只有**读取（Read）**权限时，使用**克隆聊天（Clone Chat）**或**分叉聊天（Fork chat）**在自己的聊天中继续对话。请参阅[克隆或分叉共享聊天](/features/chat-conversations/chat-features/chatshare#cloning-or-forking-a-shared-chat)。
- **文件夹不能公开共享**，管理员也不行。共享对象始终是特定用户或用户组。

## 示例使用场景 {#example-use-case}

:::tip **创建“Python 专家”项目**

假设你正在开展一个 Python 开发项目：

1. **创建一个文件夹**，命名为“Python 专家”。
2. **编辑文件夹**并设置系统提示词：
   ```
   You are an expert Python developer. You provide clean, efficient, and well-documented code. When asked for code, prioritize clarity and adherence to PEP 8 standards.
   ```
3. **附加知识**：在文件夹的**知识（Knowledge）**字段中添加项目的技术规范 PDF 或库文档。
4. **点击文件夹**，将其选为当前工作区。
5. **开始聊天**：每个新对话都将拥有：
   - Python 专家角色
   - 对项目文档的访问权限
   - 文件夹内的自动组织

:::

## 标签（补充组织方式） {#tags-complementary-organization}

除文件夹外，**标签**还为对话提供灵活的标记系统：

- **添加标签**：根据内容或用途为对话应用关键词标签。
- **按标签搜索**：在搜索窗口中输入 `tag:<name>` 列出具有该标签的聊天，或输入 `tag:none` 查找无标签聊天。请参阅[筛选结果](/features/chat-conversations/chat-features/history-search#filtering-results)。
- **灵活组织**：标签可以随时添加或移除，不会影响文件夹结构。
- **颜色和文件夹视图**：标签可以设置颜色，文件夹页面可以按标签对聊天进行分组、筛选和布局。请参阅文件夹页面上的[标签](#tags)。
- **自动标签**：任务模型可以为你的聊天添加标签。在**设置 > 界面（Settings > Interface）**中通过**聊天标签自动生成（Chat Tags Auto-Generation）**为自己关闭此功能。只有管理员开启**标签生成（Tags Generation）**时，此开关才会显示。

:::tip **按主题添加标签**

如果你经常讨论“营销”或“开发”等主题，请使用这些词语标记对话。搜索特定标签时，无论相关对话位于哪个文件夹，都可以快速找到它们。

:::
