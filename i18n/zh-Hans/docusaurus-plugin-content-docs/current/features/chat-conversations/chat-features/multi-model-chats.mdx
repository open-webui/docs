# 多模型聊天

Open WebUI 允许你在单个聊天界面中**同时与多个模型交互**。这项强大的功能让你能够比较回复、核实事实，并并排利用不同 LLM 的独特优势。

## 概述 {#overview}

在多模型聊天中，你的提示词会同时发送给两个或更多所选模型。它们的回复会显示在平行列中（或根据屏幕大小堆叠显示），让你立即了解不同 AI 架构如何处理同一个问题。

## 使用方法 {#how-to-use}

1.  **启用比较模式**：在模型选择器中，点击搜索字段旁边的 <img src="/images/features/chat/multi-model-compare.svg" alt="" width="20" height="20" /> **比较**按钮。
2.  **选择模型**：启用比较模式后，选择希望同时对话和比较的模型。
    *   *示例配置*：选择 **GPT-5.6 Sol**（用于推理）、**Gemini 3.6 Flash**（用于创意写作）和 **Claude Sonnet 5**（用于综合性能）。
3.  **发送提示词**：照常输入你的问题。
4.  **查看结果**：观察所有模型在聊天窗口中同时生成回复。

在比较中，所有所选模型的默认工具和技能都会合并。只有每个所选模型都具有某个默认过滤器时，该过滤器才会默认开启。只有每个所选模型都具备相应能力，并在[默认功能](/features/workspace/models#capabilities-and-bindings)下开启时，**网络搜索**、**图像生成**、**视频生成**和**代码解释器**才会默认开启。重新生成回复时，会使用该列当前选择的模型。

## 继续对话 {#continuing-the-conversation}

你的下一条消息只会从当前选中的一个回复继续。聊天中的每个模型都会将同一回复作为上一条答案接收。其他回复不会发送给任何模型，甚至不会发送给生成它们自己的模型。

要选择对话所基于的回复，请点击该回复。所选回复具有实线边框和填充背景，其他回复则具有虚线边框。如果在 **设置 > 界面** 中开启了**在标签页中显示多模型回复**，请改为点击模型的标签页。所选标签页会以正常亮度显示，其他标签页则会变暗。

## 使用场景 {#usage-scenarios}

*   **模型比较/基准测试**：测试哪个模型编写的 Python 代码更好，或者哪个模型在小众主题上产生的幻觉更少。
*   **事实核验**：对模型进行“交叉质询”。如果两个模型给出 X，而一个模型给出 Y，你可以进一步调查。
*   **多样化视角**：针对同一个查询，从一个模型获得“创意”视角，再从另一个模型获得“技术”视角。

## 权限 {#permissions}

管理员可以按角色或按组控制多模型聊天的访问权限。

*   **位置**：管理员面板 > 用户 > 组 > **默认权限** > **权限** > **允许聊天中使用多个模型**。要设置特定组的值，请编辑该组并打开其**权限**标签页。
*   **环境变量**：`USER_PERMISSIONS_CHAT_MULTIPLE_MODELS`（默认值：`True`）。

如果禁用，用户将不会在模型选择器中看到**比较**按钮，也无法发起多模型会话。此时，新聊天会以单个模型开始，即原本会打开的模型列表中的第一个模型。打开现有多模型聊天时，也只会使用其中的第一个模型继续。管理员始终不受限制。

## 合并回复（智能体混合） {#merging-responses-mixture-of-agents}

获得多个模型的回复后，Open WebUI 提供了一项高级功能，可以将它们**合并**为单个更优质的答案。这实现了**智能体混合（Mixture of Agents，MOA）**工作流。

### 什么是合并？ {#what-is-merging}

合并会获取所有活动模型的输出，并将它们（连同你的原始提示词）发送给“合成器模型”。合成器模型会阅读所有答案草稿，并将它们组合成最终经过润色的回复。

### 如何合并 {#how-to-merge}

1. 开始一个**多模型聊天**，获取所选模型的回复。
2. 点击回复右下方的分支状图标，其工具提示为**合并回复**。它只出现在聊天的最后一轮交流中，并且只有在每个模型都完成后才会出现。管理员可以在 **设置 > 界面**（管理员区域）的**可见控制项**下向非管理员隐藏它。
3. Open WebUI 会在各个答案下方添加一条**合并回复**，汇总先前输出中的最佳部分。

合并答案会与聊天一起保存，因此当你回到对话时它仍然存在。无论是重新打开的对话，还是刚刚生成的对话，合并的工作方式都相同，因此你可以将比较搁置数天，等回来时再随时合并。

### 合并的优势 {#advantages-of-merging}

*   **更高的准确性**：研究表明，汇总多个模型的输出往往优于任何单个模型独立运行的结果。
*   **兼取所长**：你可能同时获得模型 A 的代码准确性和模型 B 的清晰解释。
*   **减少幻觉**：合成器模型可以过滤各个回复中发现的不一致之处。

### 配置 {#configuration}

此功能没有需要配置的内容，在开始寻找设置前了解这一点很有用：

*   **模型**：合并会使用比较中已有的一个模型运行，即你点击**合并**时正在查看其回复的模型。它不使用任务模型，因此 **设置 > 界面**（管理员区域）下的设置对其没有影响。
*   **提示词模板**：合并使用内置提示词，告知模型如何合成答案。没有对应的管理员字段或环境变量。

:::info 实验性
合并/MOA 是一项高级功能。结果质量取决于执行合成的模型，因此请从你最强大模型的回复发起合并，而不要从小模型的回复发起。
:::
