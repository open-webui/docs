# 自动化

自动化可按设定的周期自动运行提示词。默认情况下，每次运行都会创建一个聊天，并通过常规聊天补全管道执行，因此模型默认值、工具、过滤器和其他管道行为仍然适用。

运行使用[记忆](/features/chat-conversations/memory)的方式与聊天相同。为你启用记忆后，运行会获得记忆工具；启用**记忆系统上下文（Memory System Context）**后，你存储的记忆会包含在其上下文中，并遵循与聊天相同的模型、权限和管理员设置。记忆是否启用取决于你在**设置 > 个性化（Settings > Personalization）**中的**记忆（Memory）**开关；如果从未设置，则由[默认界面设置](/features/administration/interface-defaults)决定；如果这些设置也不存在，则由实例是否启用 Memories 决定。

管理员可以通过 [`ENABLE_AUTOMATIONS`](/reference/env-configuration#enable_automations) 环境变量或**设置 > 常规（Settings > General）**（管理区域）中的开关，全局启用或禁用自动化。禁用后，自动化工作进程会停止处理，API 终结点返回 `403`，侧边栏条目也会隐藏。

## 可以自动执行哪些操作 {#what-you-can-automate}

- 按计划运行提示词（每小时、每天、每周、每月、自定义 RRULE）
- 通过 [webhook](#webhooks) URL 从其他服务启动运行，并可选择向其传递文本
- 与用户和组[共享](#sharing)自动化，让他们可以跟踪其运行
- 使用**立即运行（Run now）**手动触发运行
- 暂停或恢复自动化，而无需将其删除
- 查看每个自动化的执行历史
- 可选择将计划创建的聊天归档到可编辑的[文件夹](/features/chat-conversations/chat-features/conversation-organization#the-folder-page)（包括共享文件夹），让团队在一处查看每次运行
- 为运行指定机器和工作文件夹，并从该机器运行 [Agent](/features/open-terminal/agents)

## 访问控制 {#access-control}

非管理员用户使用自动化需要相应权限。

- **管理员**：始终可以访问自动化
- **用户**：需要**功能 > 自动化（Features > Automations）**权限

每次运行都使用创建者的账户，因此创建者决定自动化执行什么操作。管理员可以打开所有自动化。其他人通过[共享](#sharing)或共享[文件夹](#folders)访问自动化；未与其共享的自动化会保持隐藏。**功能 > 自动化**权限决定用户是否可以拥有自动化。

管理员无法通过界面暂停或删除其他用户的自动化。要停止用户的自动化，请将其角色设为**待审核（Pending）**，或移除其**功能 > 自动化**权限。此后每次运行都会以失败结束，并显示 `Owner no longer permitted to run automations`；计划仍会继续推进，因此角色或权限恢复后，运行也会恢复。

有关权限类别，请参阅 [RBAC 权限](/features/authentication-access/rbac/permissions#4-features-permissions)。

要授予用户访问权限：

1. 打开**管理员面板 > 用户 > 组（Admin Panel > Users > Groups）**
2. 编辑**默认权限（Default permissions）**或特定组
3. 启用**功能 > 自动化**

也可以通过 [`USER_PERMISSIONS_FEATURES_AUTOMATIONS`](/reference/env-configuration#user_permissions_features_automations) 设置此默认值。

:::tip 快速访问
在用户菜单中按住 **Shift** 可显示固定/取消固定按钮。将自动化固定后，侧边栏栏轨会添加一个快捷图标，点击即可访问。
:::

## 管理员限制 {#admin-limits}

管理员可以为非管理员用户设置自动化使用的全局限制。这些限制通过环境变量配置。**管理员不受数量和间隔限制。**

| 设置 | 作用 | 环境变量 |
|---------|--------|--------------|
| **最大自动化数量（Max Automation Count）** | 限制用户可创建的自动化数量 | [`AUTOMATION_MAX_COUNT`](/reference/env-configuration#automation_max_count) |
| **最小重复间隔（Min Recurrence Interval）** | 拒绝运行频率高于配置间隔（以秒为单位）的计划 | [`AUTOMATION_MIN_INTERVAL`](/reference/env-configuration#automation_min_interval) |
| **最大并发运行数（Max Concurrent Runs）** | 限制每个服务器进程同时执行的自动化运行数。后续运行会等待空闲槽位；更改该值后需要重启 | [`AUTOMATION_MAX_CONCURRENT`](/reference/env-configuration#automation_max_concurrent) |

- **最大数量**仅在创建时检查。降低限制不会删除现有自动化。
- **最小间隔**在创建和更新时都会检查。一次性自动化（`COUNT=1`）不受此限制。
- 这三项默认均为空（无限制）。设置为正整数即可强制执行。最大并发运行数也适用于管理员。

## 创建自动化 {#create-an-automation}

1. 打开**用户菜单 > 自动化（User Menu > Automations）**
2. 点击**新建自动化（New Automation）**
3. 设置：
   - **标题（Title）**
   - **指令（Instructions）**（提示词）
   - **模型（Model）**
   - **计划（Schedule）**；或者选择**无（None）**，使自动化仅在点击**立即运行**或调用其 [webhook](#webhooks) 时运行
4. （可选）为自动化创建的聊天选择一个**文件夹（Folder）**。选择器会列出你自己的文件夹；要发布到共享文件夹，请改为从该文件夹页面创建自动化（请参阅[文件夹](#folders)）
5. 点击**创建（Create）**

创建后，Open WebUI 会打开位于 `/automations/{id}` 的专用自动化编辑器页面。

### 运行使用的模型设置 {#model-settings-used-by-a-run}

对于由 Ollama 或兼容 OpenAI 的连接提供支持的模型，运行会使用模型的**系统提示词（System Prompt）**和**高级参数（Advanced Params）**。在**指令**中输入希望模型执行的任务。自动化编辑器没有**模型控制（Model controls）**选择器。运行使用模型的[默认选项](/features/workspace/models#model-controls)，选择**立即运行**时也是如此。

当相应能力和实例设置均已启用时，模型的**默认功能（Default Features）**可以为运行启用 Web 搜索、图像生成或视频生成。**默认功能**中的**代码解释器（Code Interpreter）**开关仅适用于交互式聊天。

### 聊天标题 {#chat-titles}

运行创建聊天时，其初始标题是自动化保存的**标题**。`{{CURRENT_DATE}}` 等提示词变量会在**指令**中展开，但在**标题**中会按字面文本显示。

### 为运行指定机器 {#giving-a-run-a-machine}

自动化编辑器提供**机器（Machine）**列表，选择机器后还会显示**工作目录（Working Directory）**字段。运行会使用该机器，并从该文件夹启动。字段为空时，从机器的默认文件夹启动。至少有一台你可用的机器时才会显示该列表；在此处选择的机器会替换模型上配置的机器。

如果编辑器中未选择机器，运行会使用其模型上配置的机器。在**工作区 > 模型（Workspace > Models）**中设置：编辑模型，并从**默认机器（Default machine）**字段选择机器。至少有一台你可用的机器且模型的**终端（Terminal）**能力已启用时，才会显示该列表；终端能力默认启用。

:::info 自动化中的终端限制
有关机器（包括频道自动化的限制），请参阅[创建机器](/features/open-terminal/terminals/orchestration/creating-terminals#machine-scope)。
:::

### 运行 Agent {#running-a-coding-agent}

选择机器后，**模型**列表还会提供该机器报告的 Agent，名称为 `<agent>/<model>`。更改机器或文件夹会重新加载列表，**创建**和**保存**会等待加载完成。Agent 自动化必须先选择机器才能保存。其结果始终会发送到聊天。每次运行前，Open WebUI 都会检查机器和 Agent 是否仍然可用；任意一个不存在，运行都会失败。

## 编辑与管理 {#edit-and-manage}

在自动化列表中，点击某个自动化即可打开其专用编辑器页面。

该页面就是编辑器。名称和指令位于顶部，下面是包含**状态（Status）**、**计划（Schedule）**、**模型（Model）**、**目标位置（Destination）**、**机器（Machine）**和**下次运行（Next run）**的**属性（Properties）**列表。点击任意值即可就地更改。一旦有内容与已保存的自动化不同，页眉就会显示**保存**按钮。**状态**开关会立即暂停或恢复自动化，无需点击**保存**。

页眉还包含**立即运行**、**复制链接（Copy link）**和带有**复制（Duplicate）**及**删除（Delete）**的**更多（More）**菜单。**复制**会打开预填相同设置的新自动化表单，并在名称后添加“(Copy)”。点击**创建**之前不会保存任何内容。

属性下方的**活动（Activity）**按最新优先列出运行，每次运行都标记为**已运行（Ran）**或**失败（Failed）**并显示时间。点击运行可打开其聊天。滚动时会逐步加载运行记录。

**目标位置**菜单包含**每次运行都在新聊天中开始（Start each run in new chat）**开关（频道中显示为**每次运行都在新话题中开始（Start each run in new thread）**），默认开启。关闭后，每次运行都会继续在同一个持续聊天或频道话题中进行，因此每次运行都能看到之前的运行。

对于频道，**在话题中回复（Reply in thread）**（默认开启）决定模型回复的位置。开关开启时，每次运行都会将提示词发布为频道消息，回复则显示在该消息下的话题中。开关关闭时，每次运行都会将提示词和回复作为普通的顶级频道消息发布，不创建话题。

### 快速删除 {#quick-delete}

打开自动化列表时按住 **Shift**，每个自动化的菜单按钮和开关都会变成删除按钮。点击后会立即删除该自动化，不作询问。松开 **Shift** 后，菜单和开关会恢复。通过菜单删除仍会要求确认。当通过 `Tab` 聚焦到某个按钮或链接时，按住 **Shift** 不会将菜单按钮和开关变成删除按钮，因此 `Shift+Tab` 仍可照常向后浏览列表。

## 导出与导入 {#export-and-import}

自动化列表页眉有一个拆分的**创建**按钮，其下拉菜单包含**导入 JSON（Import JSON）**和**导出 JSON（Export JSON）**，用于在实例或账户之间迁移自动化。

**导出 JSON**会将你拥有的所有自动化下载为 `automations-export-<timestamp>.json`，不受搜索框或状态过滤器影响。每个条目都保留名称、计划和其他设置、文件夹分配及启用状态。ID、时间戳和运行历史不会写入文件，因此导出的是定义的副本，而不是过去运行的备份。

**导入 JSON**接受包含自动化裸数组或带有 `automations` 键的对象的 `.json` 文件。其他内容都会作为无效 JSON 格式被拒绝。

导入会执行和不会执行的操作：

- 每个条目都会成为**新的**自动化。不会与已有内容进行匹配，因此两次导入同一文件会产生重复项。
- 除非文件将 `is_active` 设置为 `false`，否则条目会**以启用状态创建**。因此，导入可能立即在目标实例上启动计划运行；如果不希望如此，请先禁用它们。
- 仅当你自己的账户中存在具有该 ID 的文件夹时，才会保留文件夹；否则会丢弃文件夹，并在没有文件夹的情况下导入自动化。
- 每个条目都会经过正常创建流程，因此计划验证和[管理员限制](#admin-limits)仍然适用。第一个被拒绝的条目（例如无效 `RRULE` 或达到 [`AUTOMATION_MAX_COUNT`](/reference/env-configuration#automation_max_count)）会中止剩余导入；在此之前创建的条目会保留。

## 文件夹 {#folders}

自动化可以将其聊天发布到文件夹，这样定期报告或摘要会与该主题的其他工作放在一起，文件夹的未读标记会显示尚未阅读的运行数量。在编辑器中通过**目标位置**设置：**新聊天（New chat）**会将聊天保留在未分组列表中，**文件夹（Folder）**会列出你自己的文件夹，**频道（Channel）**则改为发布到频道（请参阅[频道](#channels)）。

文件夹自己的页面可作为其自动化的主页。在页眉的切换控件中选择**自动化**（对拥有自动化权限的用户可见）即可打开。**自动化**部分会列出文件夹的自动化及其计划、上次运行日期（或**已暂停（Paused）**或**尚未运行（Not run yet）**）和开关；其**新建自动化**按钮会创建一个从此文件夹开始运行的自动化。自动化创建的聊天在文件夹列表和看板中带有一个小时钟标记。

- 自动化可以发布到创建者可编辑的任何文件夹，包括共享文件夹。请从共享文件夹页面创建；**目标位置**选择器仅列出你自己的文件夹。
- 每个有权访问文件夹的人都能在列表中看到该自动化并阅读其运行，包括只读访问者。任何可编辑文件夹的人也可以运行、暂停以及更改其名称和计划。创建者保留对其他所有内容和删除操作的控制权。
- 只要创建者仍可编辑文件夹，运行就会继续归入其中。创建者失去该访问权限后，下一次运行会清除文件夹设置，并在任何文件夹之外创建聊天；自动化会继续运行。
- 文件夹是归档目标：文件夹的系统提示词和附加知识会应用于聊天，与该文件夹中的其他聊天一样。
- 清除文件夹属于正常编辑。之后的聊天会回到未分组列表；已经创建的聊天保留在原位置。
- 删除文件夹不会删除指向它的自动化。这些自动化会失去文件夹并继续运行。
- 导入的自动化仅在你的账户中存在具有该 ID 的文件夹时保留文件夹；否则会在没有文件夹的情况下导入。

## Webhooks {#webhooks}

Webhook 会为自动化提供一个 URL。调用该 URL 即可启动运行，因此 CI 作业、监控警报或 Git 托管服务无需等待计划即可触发自动化。一个自动化可以有计划、Webhook 或两者兼有；两者都没有时，只能通过**立即运行**启动。

要添加 Webhook，请打开自动化，将 **Webhook** 设为开启并**保存**。保存后会显示 URL。**重新生成（Regenerate）**会创建新 URL，旧 URL 随即失效。URL 泄露时应使用此功能。只有创建者能看到 URL 并重新生成。

- **运行的文本。** 在指令中放置 `{{name}}` 占位符，例如 `Summarize this alert: {{message}}`。URL 的同名查询参数或 JSON 请求体中的同名字段会填充该占位符。请求体中的 `variables` 对象也可用，GitHub 或 Gitea 等服务的请求体会按原样读取。占位符可以像任何[提示词](/features/workspace/prompts)一样携带默认值和类型；缺少必需值、类型错误或请求体不是 JSON 对象时，会返回 `400`，且不会启动运行。
- **允许 GET。** 默认支持 `POST`。打开**允许 GET（Allow GET）**后也会接受 `GET`，适用于只能打开链接的服务。关闭时，调用 `GET` 会返回 `405`。
- **限制。** 超过 64 KB 的请求体会返回 `413`。每个自动化每分钟接受 30 次调用，后续调用返回 `429`。已暂停的自动化返回 `409`。成功调用返回 `202`。

:::warning 任何拥有 URL 的人都可以启动自动化
URL 就是凭据，因此只应与需要它的服务共享。调用无需登录，任何持有 URL 的人都能在创建者账户下启动运行，并决定传入提示词的文本。仅当自动化的指令可以安全地使用不可信文本运行时，才为其创建 Webhook。
:::

管理员可通过**管理员设置 > 常规（Admin Settings > General）**中的**自动化 Webhooks（Automation Webhooks）**或 [`ENABLE_AUTOMATION_WEBHOOKS`](/reference/env-configuration#enable_automation_webhooks)（默认开启）控制 Webhook。关闭后，现有 URL 会停止工作。创建 Webhook 需要管理员权限或**功能 > 自动化**权限；创建者失去该权限后，其 Webhook 会停止工作。

## 共享 {#sharing}

自动化可以与特定用户和组共享，让团队跟踪报告，而无需每个人都创建自己的自动化。使用自动化页眉中的**共享（Share）**，像其他[共享项目](/features/authentication-access/rbac/permissions#2-sharing-permissions)一样选择用户和组。非管理员用户需要**自动化共享（Automations Sharing）**权限才能共享。

- **读取（Read）**允许用户打开自动化、查看其计划，以及阅读其运行创建的聊天。自动化列表的**与我共享（Shared with me）**选项卡显示直接与你共享的自动化。
- **写入（Write）**还允许运行、暂停以及更改其名称和计划。
- 只有创建者可以更改指令、模型、目标位置和 Webhook，因为运行始终使用创建者的账户。创建者和管理员可以共享和删除。

位于共享文件夹中的自动化遵循文件夹的访问权限（请参阅[文件夹](#folders)）。

## 频道 {#channels}

将**目标位置**设为**频道**后，运行会发布到[频道](/features/channels)，而不是创建聊天。列表会显示你的频道，不含私信。

- 保存需要标准频道的写入权限或组频道的成员资格。非管理员用户还需要**频道（Channels）**权限。
- 每次运行都会将指令作为你的消息发布到频道。模型的回复会进入该消息下的话题；如果管理员的**模型响应模式（Model Response Mode）**设为**频道（Channel）**，则回复会进入时间线。
- 模型只接收指令，不接收频道中的先前消息。
- 点击**活动**中的运行会打开频道。
- Agent 自动化需要聊天目标位置。使用**频道**保存会被拒绝，并显示 `Agent automations require a chat destination.`；如果机器来自模板，则显示 `This machine requires a chat destination.`。后一条消息也会拒绝仅限聊天的模板机器。
- 实例关闭频道时，运行会因 `Channel not found` 而失败；创建者失去**频道**权限时，会因 `Owner no longer permitted to use channels` 而失败。

## 计划 {#scheduling}

支持的计划模式：

- **一次（Once）**
- **每小时（Hourly）**
- **每天（Daily）**
- **每周（Weekly）**
- **每月（Monthly）**
- **自定义（Custom）**（`RRULE`）

**每天**、**每周**和**每月**会按照账户存储的时区，在所选分钟执行。登录或重新加载已登录的应用时，Open WebUI 会从浏览器读取时区。如果服务器没有该账户的有效时区，则使用服务器自己的本地时区。

如果计划看起来不正确，请检查设备时区并重新加载 Open WebUI 进行同步。对自动化做一次编辑并点击**保存**，即可使用更新后的时区重新计算下次运行。

自定义计划接受标准 RRULE 语法。无效或已耗尽的规则会被拒绝。

要每天运行两次，请选择**计划 > 自定义**，并输入 `RRULE:FREQ=DAILY;BYHOUR=8,16;BYMINUTE=0`，即可在计划时区的 08:00 和 16:00 运行。

在 Open WebUI 0.13.4 中，重新打开此计划可能只显示**每天**及第一个时间。保持**计划**不变而编辑其他字段并保存，会保留存储的规则。如果在**每天**中更改时间，保存会将规则替换为单个每日时间。要更改多时间规则中的时间，请选择**自定义**，重新输入完整规则，然后点击**保存**。

自定义规则的读取遵循以下几条规则：

- **日内规则对齐到时钟。** 没有 `DTSTART` 的 `SECONDLY`、`MINUTELY` 或 `HOURLY` 规则以时钟为基准，因此每 5 分钟表示 `:00`、`:05`、`:10`，而不是从恰好保存的时间起每五分钟。
- **在仍有意义时会遵循 `DTSTART`。** 为规则指定开始时间后，计划会从该时间开始计数，并保留预期相位。如果开始时间过于久远，严格遵循它需要遍历超过 100,000 次出现才能到达现在，则规则会回退到时钟对齐，而不是停滞。
- **`INTERVAL` 必须是正整数。** 零或负数会被拒绝，而不会静默视为一。
- **每个计划只能有一条规则。** 多条 `RRULE` 行会被拒绝，完全不支持 `EXRULE`；请将排除条件构建到规则本身中。
- 属性名称不区分大小写，因此 `freq=daily` 与 `FREQ=DAILY` 行为相同。

## 说明 {#notes}

- 自动化在后台工作进程循环中按轮询间隔运行。
- 每次运行都会记录状态（`success` 或 `error`）和可选的错误详情。在聊天中回复的运行会在回复完成后记录为 `success`。回复失败或被取消时会记录为 `error`，运行仍保留**查看聊天（View chat）**链接，方便打开聊天。
- 要在运行失败时收到通知，请将[通知目标](/features/chat-conversations/chat-features/notifications#events)订阅到 `automation.run_failed`。
- 删除自动化也会移除其运行历史。

## 从聊天管理自动化 {#managing-automations-from-chat}

使用**原生函数调用模式（Native Function Calling Mode）**和支持该模式的模型时，还可以通过内置工具直接在聊天对话中创建和管理自动化。这样，你可以直接说*“安排每天上午 9 点生成摘要报告”*，模型就会为你创建自动化。

### 可用工具 {#available-tools}

| 工具 | 作用 |
|------|-------------|
| `create_automation` | 使用名称、提示词和 RRULE 计划创建新的计划自动化，并可选择为其聊天指定文件夹。使用当前聊天模型。 |
| `update_automation` | 更新现有自动化的名称、提示词、计划、模型或文件夹 |
| `list_automations` | 列出你的计划自动化及其状态、文件夹、计划和后续运行 |
| `toggle_automation` | 暂停或恢复计划自动化 |
| `delete_automation` | 删除计划自动化及其全部运行历史 |

### 前提条件 {#requirements}

聊天自动化工具需要满足以下条件才可用：

1. 必须为模型启用**原生函数调用（Native Function Calling）**
2. 必须为模型启用**内置工具（Builtin Tools）**能力
3. 必须在模型的内置工具设置中启用**自动化**类别（默认启用）
4. 必须全局启用 **`ENABLE_AUTOMATIONS`**（默认启用）
5. 用户必须具有**功能 > 自动化**权限（管理员始终满足）

这些工具接受的文件夹参数是文件夹 ID，并会根据你拥有的文件夹进行检查：不属于你或已不存在的文件夹会返回错误，而不会被应用。

- 对于 `update_automation`，省略参数或传入空字符串会保留自动化当前的文件夹。传入 `null` 会清除文件夹。`model_id` 同样如此：空值会被忽略，而不会清除自动化的模型。
- 对于 `list_automations`，省略参数或传入空字符串会列出所有文件夹中的自动化。

有关所有内置工具的完整详情，请参阅[内置工具参考](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode)。
