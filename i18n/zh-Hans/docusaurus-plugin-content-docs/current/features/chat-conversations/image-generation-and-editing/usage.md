在 Open WebUI 对话中，可以根据提示词生成图像，也可以上传图像并描述所需的更改。管理员必须先添加一个[图像连接](/features/chat-conversations/image-generation-and-editing)；使用时保持选择正常的聊天模型。

只有满足以下所有条件时，聊天中才可使用图像生成：

- 在**设置** > **图像**（管理员区域）中启用了**图像生成**，并且至少有一个你有权访问的连接提供生成模型。
- 你的角色拥有**图像生成**功能权限。管理员始终通过此项检查。
- 在**工作区** > **模型** > **编辑**中，模型已勾选**图像生成**能力。在非旧版模式下，还必须保持启用其**内置工具**能力和**图像生成**内置工具类别。以上各项默认均已开启。
- 该聊天已在消息输入框的 **+** 菜单中开启**图像**开关。在模型编辑器的**默认功能**下勾选**图像生成**，可使其在每个新聊天中默认启用。

如果 **+** 菜单中完全没有**图像**，则可能是图像生成已全局关闭、某个所选模型的**图像生成**能力已关闭，或你的角色缺少权限。URL 或密钥错误只会在生成时显现：开关仍然保留，但生成会失败。

## 使用图像生成 {#using-image-generation}

1. 在消息输入框的 **+** 菜单中开启**图像**。
2. 输入图像生成提示词。
3. 点击`Send`。

![图像生成教程](/images/tutorial_image_generation_2.png)

:::warning 继续使用你的聊天模型对话
聊天顶部的模型选择器应保持选择正常的聊天模型。切勿在此处选择图像模型。管理员会设置默认图像模型；当有多个图像模型可用时，你可以通过 **+** 菜单中的**图像**条目选择另一个。

将图像模型选为聊天模型是最常见的配置错误。一切看似配置妥当，但生成会失败或返回无用的结果，因为图像模型无法进行对话，也不会以其预期的方式收到绘图请求。如果图像生成突然无法使用，而设置看起来正确，请先检查模型选择器显示的内容。

例外情况是聊天模型自身可通过 **API 类型**为 `Responses` 的连接创建图像，例如通过 OpenRouter 使用 Gemini 图像模型。其图像会显示在回复中。
:::

后续行为取决于**函数调用**模式。可在聊天中的**模型控制** > **控制** > **高级参数**中按聊天设置，在**设置** > **通用** > **高级参数**中为自己设置，在模型编辑器中按模型设置，或在管理员模型设置的**模型默认值**下全局设置。按上述顺序，第一个不是**默认**的设置生效；如果均未设置，则使用原生模式。

**原生（Native）**模式采用下文所述的工具路径。在**旧版（Legacy）**模式下，开关开启时你发送的每条消息都会直接进入图像模型，无论请求内容是什么。当最近的对话包含图像且**图像编辑**已开启时，会执行编辑而非创建：最近两条包含图像的消息中的图像会与你的消息一起发送给编辑引擎，你的消息作为提示词，不经过提示词生成。如果编辑失败，错误会提供给聊天模型，并由其在回复中报告。在创建路径中，任务模型会先将你的消息改写为图像提示词，除非你在管理员图像设置的**旧版**下关闭**图像提示词生成**。提示词模板位于**设置** > **界面**（管理员区域）的**生成**部分。在两种模式下，如果聊天中选择了终端，生成和编辑的图像还会保存到其工作目录，以便模型继续使用终端工具处理这些图像。

## 选择图像模型 {#choosing-an-image-model}

当有多个图像模型可供你使用时，**+** 菜单会在**图像**旁显示当前选择。点击箭头可为此聊天选择另一个模型。**默认**会使用聊天模型的默认值；如果模型没有默认值，则使用管理员的默认值。

## 基于原生工具的生成（智能体式） {#native-tool-based-generation-agentic}

使用**原生函数调用**时（请参阅[**工具调用中心指南**](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native)），模型会直接调用图像生成工具。

### 工作原理 {#how-it-works}

- **自然语言**：你只需向模型提出请求：*“生成一幅控制论森林的图像。”*
- **取决于模型**：无法可靠调用工具的模型将始终不会调用 `generate_image`，因此在怀疑引擎配置之前，请先尝试更强的模型。
- **显示**：生成的图像会直接显示在聊天界面中。
- **编辑**：`edit_image` 工具也会提供给模型（例如*“将此图像中的天空变成红色”*），但前提是在管理员设置中启用了**图像编辑**。

这种方式允许模型在生成前对提示词进行“推理”，甚至可以在复杂请求中生成多张图像。

:::info
**旧版“生成图像”按钮：**
Open WebUI 没有根据消息内容生成图像的按钮。如需添加，请使用社区构建的 **[Generate Image Action](https://openwebui.com/posts/3fadc3ca-c955-4c9e-9582-7438f0911b62)**。
:::

## 恢复“生成图像”按钮 {#restoring-the-generate-image-button}

如果你偏好点击任意消息上的按钮来根据其内容生成图像的工作流，可以轻松恢复此功能：

1. 访问 Open WebUI 社区网站上的 **[Generate Image Action](https://openwebui.com/posts/3fadc3ca-c955-4c9e-9582-7438f0911b62)**。
2. 点击 **Get** 将其导入本地实例（或复制代码并粘贴到你的本地实例中）。
3. 导入后，进入**管理员面板** > **函数**，确保 **Generate Image** 操作已启用。

此操作会在消息操作栏中添加“生成图像”图标，让你能够直接从 LLM 回复生成图像。如果希望助手先迭代图像提示词，并在你满意后再生成图像，这会很有帮助。

:::info
**要求：**图像编辑遵循本页顶部列出的相同条件。要使用**图像编辑**或**图像+图像生成**，还需在**设置** > **图像**（管理员区域）中开启**图像编辑**，并具备将**编辑**列为能力的连接（OpenAI 兼容、Gemini，或具有编辑工作流的 ComfyUI），以及支持局部重绘或 img2img 的模型。
:::

## 图像编辑（局部重绘） {#image-editing-inpainting}

你可以直接在聊天中提供图像和文本提示词来编辑图像。

1. **上传一张图像**到聊天中。
2. **输入提示词**，描述要做的更改（例如“将背景改为日落”或“添加一顶帽子”）。
3. 模型会根据你的提示词生成图像的新版本。

在聊天中选择管理员添加的 [Open Terminal](/features/open-terminal) 或 [Tether](/ecosystem/tether) 终端后，模型还可以编辑存储在该终端中的任何图像，无论[聊天上传](/features/open-terminal/setup/connecting#chat-uploads)如何设置。模型会将其绝对路径传递给 `edit_image`，Open WebUI 则使用你对该终端的访问权限，在聊天使用的同一工作区中读取这些图像。每张图像必须是 PNG、JPEG、WebP 或 GIF 格式，最多 2500 万像素且不超过 50 MB。

## 图像合成（多图像融合） {#image-compositing-multi-image-fusion}

将多张图像无缝组合成一个协调一致的场景，这一过程在专业上称为**图像合成**或**多图像融合**。它允许你合并来自不同来源的元素（例如，将一张图像中的主体放入另一张图像的背景），同时协调光照、透视和风格。

1. **上传图像**到聊天中（例如，上传一张主体图像和一张背景图像）。
2. **输入提示词**，描述所需的合成效果（例如“组合这些图像，让猫坐在公园长椅上，并确保光照一致”）。
3. 模型会生成一张新的合成图像，按照你的指示融合各个元素。
