# 分析

Open WebUI 的**分析**功能为管理员提供实例中使用情况、Token 消耗和模型性能的全面洞察。这个强大的工具可帮助你了解用户如何与 AI 模型交互，并就资源分配和模型选择作出数据驱动的决策。

:::info 仅限管理员使用的功能
只有具有 **admin** 角色的用户才能访问分析。通过**设置 > 分析**（管理员部分）进入。
:::

:::tip 禁用分析

如果不需要“分析”选项卡，可以将 [`ENABLE_ADMIN_ANALYTICS`](/reference/env-configuration#enable_admin_analytics) 环境变量设置为 `False`，将其完全隐藏。这会阻止挂载分析 API 路由器，并从管理员导航中移除该选项卡。此更改需要重启后生效。

:::

## 概览 {#overview}

分析仪表板让你全面了解 Open WebUI 实例的活动，包括：

- 不同模型和时间段内的**消息量**
- 用于成本估算和资源规划的 **Token 使用量**跟踪
- 用于了解参与度的**用户活动**模式
- 展示数小时、数天或数月趋势的**时间序列数据**

所有分析数据均来自实例数据库中存储的消息历史。启用分析功能后，Open WebUI 会自动跟踪消息并建立索引，以提供快速、可查询的洞察。

---

## 访问分析 {#accessing-analytics}

1. 使用 **admin** 账户登录
2. 点击个人资料图标，打开**设置**
3. 打开**管理员**部分，在**质量**下选择**分析**

![分析仪表板](/images/admin/admin-analytics.png)

仪表板不再是独立页面。它会在设置窗口中打开，位于个人设置旁边，旧的 `/admin/analytics` URL 会重定向到此处。如果 [`ENABLE_ADMIN_ANALYTICS`](/reference/env-configuration#enable_admin_analytics) 已关闭，该 URL 会改为重定向到管理员面板的用户列表，并且不会列出“分析”入口。

## 个人用量 {#personal-usage}

这里介绍的仪表板是面向整个实例的管理员视图。除此之外，**每位用户都有查看自己活动的个人用量视图**，位于**设置 > 用量**。它不需要管理员角色，也不需要任何配置。

该视图的范围严格限定为当前登录用户自己的数据：

- Token 总数（输入和输出），包括累计总数和所涵盖时间段内的数量
- 消息和聊天数量，以及活跃天数
- 活动热力图，可按天、按周或累计总量查看
- 当前和最长的连续活跃记录
- 最常使用的模型和工具

所涵盖的时间段为过去两年（最近 730 天），无论账户何时创建，所有账户都使用相同的时间窗口，数据按用户自己的时区分桶。由于它只报告发起请求的用户本人的活动，因此不会暴露任何其他用户的信息。

## 仪表板功能 {#dashboard-features}

**概览** / **会话**开关用于选择视图。两者使用相同的时间段和组筛选器。[会话](#sessions)列出单个聊天。

### 时间段选择 {#time-period-selection}

在分析仪表板右上角，可以按时间段筛选所有数据：

- **过去 24 小时**
- **过去 7 天**
- **过去 30 天**
- **过去 90 天**
- **年初至今**——从今年 1 月 1 日到现在
- **过去 12 个月**
- **全部时间**——完整历史数据
- **自定义范围**——由你选择开始和结束日期

选择**自定义范围**后，时间段下拉菜单旁会显示两个日期字段。两个字段都填写完整之前不会执行查询，因此在你仍在选择日期时，仪表板会保持空闲，而不是显示加载旋转图标；第二个日期设置完成后便会立即加载。结束日期包含在范围内，因此会涵盖当天全部数据。

所选时间段会**自动保存**，并在不同浏览器会话之间保留，自定义日期也会保留。如果你离开“分析”时选择的是**自定义范围**且日期不完整，之后返回时仪表板会显示空白数值，直到你补全范围，而不会无限期加载。

### 组筛选 {#group-filtering}

如果已配置[用户组](/features/authentication-access/rbac/groups)，分析仪表板支持按组筛选：

- 使用时间段选择器旁边的**组下拉菜单**
- 选择特定组，**仅查看该组用户**的分析数据
- 选择“所有用户”可查看整个实例的分析数据

此功能适用于：
- **部门级报告**——跟踪特定团队的使用情况
- **成本分摊**——将 Token 消耗归入业务部门
- **试点项目**——监测测试组内的采用情况

更改时间段或组筛选器时，页面上的所有指标（包括用量图表）都会自动更新。

### 汇总统计 {#summary-statistics}

仪表板顶部显示所选时间段内的关键指标：

- **Token**——处理的所有输入和输出 Token 之和
- **输入**和**输出**——分别显示输入和输出 Token 数
- **消息**——生成的助手响应数量
- **聊天**——不同对话的数量
- **用户**——发送过消息的用户数量

Token 数值会缩写显示，例如 `1.2m`。将鼠标悬停在任何数值上即可查看准确值。

:::note 消息计数
分析统计的是**助手响应**，而不是用户消息。这能更准确地衡量 AI 模型的使用量和 Token 消耗。
:::

### 消息时间线图表 {#message-timeline-chart}

用量图表按模型细分，展示活动随时间的变化。图表上方的 **Token** / **消息**开关用于选择统计对象，默认显示 **Token**。同一开关还决定下方表格的排序方式，请参阅[模型用量表](#model-usage-table)。

图表有两种视图：

- **数量**——每个时间步显示堆叠条形图，每种颜色代表一个模型
- **活动**——每个模型占一行的热力图。每个单元格的颜色深度相对于该模型最繁忙的时间步，空白单元格表示没有记录的用量

点击图表下方图例中的模型，或**活动**视图中的行名称，可仅显示该模型。再次点击该模型或点击**所有模型**，即可显示所有模型。将鼠标悬停在某个时间步上，会显示该时间点每个模型的数值。图表中的时间为服务器时间。

时间间隔下拉菜单设置每个时间步的大小。其默认值和可选项随时间段变化：

| 时间段 | 默认值 | 可选项 |
|-------------|---------|---------|
| **过去 24 小时** | **10 分钟** | **10 分钟**、**每小时**、**每天** |
| **过去 7 天** | **每小时** | **每小时**、**每天** |
| **过去 30 天** | **6 小时** | **每小时**、**3 小时**、**6 小时**、**每天** |
| 更长的时间段 | **每天** | **每天** |

**比较**会在**数量**视图中将上一时间段显示在当前时间段旁边。上一时间段是紧邻所选时间段之前、长度相同的窗口。图表随后用实线绘制当前时间段，用虚线绘制上一时间段。将鼠标悬停在某个时间步上，会显示两个数值及其日期和百分比变化。**全部时间**没有更早的时间段，因此无法使用**比较**。

此图表可帮助你：
- 识别繁忙时段，进行容量规划
- 跟踪模型部署后的采用情况
- 检测异常活动峰值
- 监测变更或公告的影响

### 模型用量表 {#model-usage-table}

模型用量和用户活动共用图表下方的一个表格。表格上方的**模型** / **用户**开关用于选择显示的列表，默认显示**模型**。两个列表默认都按 **Token 总数**排序。在图表上方的开关中选择**消息**，会按消息数量排序，并将占比列变为**消息占比**。

下表详细列出每个模型的使用情况：

| 列 | 说明 |
|--------|-------------|
| **#** | 当前排序顺序中的排名 |
| **模型** | 带图标的模型名称 |
| **消息** | 生成的助手响应总数 |
| **用户** | 去重用户数 |
| **聊天** | 去重聊天数 |
| **输入** | 输入 Token 数 |
| **输出** | 输出 Token 数 |
| **总计** | 输入和输出 Token 之和 |
| **Token 占比** | 占所有 Token 的百分比。图表统计消息时显示为**消息占比** |

**功能：**
- **模型图标**——通过头像直观识别模型
- **Token 跟踪**——查看哪些模型消耗的资源最多
- **可点击的行**——点击任意模型可打开[模型详情弹窗](#model-details-modal)

**用例：**
- 找出最受欢迎的模型
- 计算每个模型的成本（将 Token 数乘以提供方费率）
- 决定保留或移除哪些模型
- 根据使用情况规划基础设施升级

### 模型详情弹窗 {#model-details-modal}

点击任何模型行会打开一个包含两个选项卡的详情弹窗：

#### “概览”选项卡 {#overview-tab}

“概览”选项卡提供：

- **反馈活动图表**——用户反馈（赞/踩）随时间变化的可视化历史
  - 在 **30D**、**1Y** 或 **All** 视图之间切换
  - 较长时间范围按周聚合
- **标签**——与此模型关联的最常用聊天标签（前 10 个）

这有助于你了解：
- 用户对模型质量的评价如何随时间变化
- 模型正在处理哪些主题/用例
- 用户满意度的趋势

#### “聊天”选项卡 {#chats-tab}

:::info 需要管理员聊天访问权限
只有在实例设置中启用了 [**`ENABLE_ADMIN_CHAT_ACCESS`**](/reference/env-configuration#enable_admin_chat_access)，才会显示“聊天”选项卡。
:::

“聊天”选项卡显示使用过此模型的对话：

- **用户信息**——每次聊天的发起者
- **预览**——每个对话的第一条消息
- **时间戳**——聊天最后更新的时间
- **点击打开**——直接前往共享聊天视图

此功能适用于：
- 了解用户如何与特定模型交互
- 审计模型使用情况，进行质量保证
- 查找用于培训或文档的示例对话

### 用户活动表 {#user-activity-table}

在表格上方的开关中选择**用户**，即可跟踪每位用户的参与度和 Token 消耗：

| 列 | 说明 |
|--------|-------------|
| **#** | 当前排序顺序中的排名 |
| **用户** | 带头像的用户名 |
| **消息** | 该用户发送的消息总数 |
| **输入** | 该用户的输入 Token 数 |
| **输出** | 该用户的输出 Token 数 |
| **总计** | 输入和输出 Token 之和 |
| **Token 占比** | 占所有 Token 的百分比。图表统计消息时显示为**消息占比** |

**功能：**
- **可排序的列**——按名称、消息、占比或三个 Token 列中的任意一列排序。表格显示该时间段内 Token 数最多的 50 名用户；图表统计消息时，则显示消息数最多的 50 名用户。API 的 `limit` 参数可提高该上限
- **用户识别**——头像和显示名称。将鼠标悬停在头像上或点击头像，可打开该用户的个人资料卡片
- **Token 归因**——查看每位用户的资源消耗

**用例：**
- 监测重度用户及其 Token 消耗
- 识别不活跃或低使用量账户
- 规划用户配额或速率限制
- 计算每位用户的成本，用于计费

## 会话 {#sessions}

:::info 需要管理员聊天访问权限
只有启用了 [**`ENABLE_ADMIN_CHAT_ACCESS`**](/reference/env-configuration#enable_admin_chat_access)，才会显示**会话**视图。该视图会显示其他用户聊天中的聊天标题、工具调用和错误。
:::

**会话**按每个聊天一行列出所选时间段内有消息的聊天，并按组筛选。子智能体、计时器和笔记聊天也会包含在内并带有标记。汇总信息显示会话、提示词、Token 和响应错误总数。点击下方的 Token 范围可筛选列表。

| 列 | 说明 |
|--------|-------------|
| **会话** | 聊天标题，以及所属文件夹或模型 |
| **用户** | 聊天的所有者 |
| **最后活跃** | 最后一条已保存消息的时间 |
| **响应** | 该时间段内的助手响应 |
| **Token** | 记录的输入和输出 Token。`-` 表示没有记录，`*` 表示记录不完整 |
| **响应错误** | 以错误结束的响应 |
| **时间跨度** | 从第一条到最后一条已保存消息的时间，包括空闲时间 |

**未记录**表示缺少时间戳。可以按聊天标题、用户或文件夹搜索，按模型筛选，或在**会话选项**菜单中隐藏子智能体聊天。

### 会话详情 {#session-details}

点击会话可查看其 Token 和缓存总数、每次响应的图表（**Token**或**时间线**）以及执行跟踪：每次响应及其工具调用、结果和错误，以及各项的执行状态和持续时间。**全部**、**工具**和**错误**用于筛选执行跟踪。**打开聊天**会在新选项卡中打开聊天。只有新回复才会保存计时数据。

标题会截断为 10 个单词。链接、文件路径、长标识符，以及 token 或 password 等词后面的值会被移除。

## Token 用量跟踪 {#token-usage-tracking}

### 什么是 Token？ {#what-are-tokens}

Token 是语言模型处理文本所使用的单位。**输入**（你的提示词）和**输出**（模型的响应）都会消耗 Token。大多数 AI 提供方根据 Token 用量收费，因此 Token 跟踪对成本管理至关重要。

### Token 跟踪的工作原理 {#how-token-tracking-works}

Open WebUI 将报告的 Token 用量存储在已保存的助手消息上。调用 `/api/chat/completions` 时，如果同时省略 `chat_id` 和 `parent_id`，无状态调用可以向 API 调用方返回用量，而不会保存助手消息，因此这部分用量不计入分析总数。分析会聚合已保存的用量，以显示：

- **输入 Token**——用户提示词和上下文中的 Token
- **输出 Token**——模型响应中的 Token
- **Token 总数**——输入和输出之和

Token 数据会在不同模型服务提供方（OpenAI、Ollama、llama.cpp 等）之间进行标准化，无论你使用哪个后端，都能提供一致的指标。

对提供方的每次调用只计一次，即使提供方在每个流式分块中重复发送用量也是如此。当模型使用工具，导致一次回复发起多次调用时，这些调用的用量会相加。没有用量数据的回复保持未记录状态；只有部分调用报告用量的回复会标记为不完整。

这些数字由提供方报告。大多数 OpenAI 兼容提供方在流式回复中不会报告任何用量，除非收到明确请求。**设置 > 模型 > 编辑**（管理员部分）中的 **Usage（用量）**能力（自己的模型则在**工作区 > 模型**中）用于发出此请求，因此未启用该能力的模型可能完全不显示 Token。请参阅[能力与绑定](/features/workspace/models#capabilities-and-bindings)。

:::info 计划任务和委托运行也会计入
Token 计数请求在服务器端添加，因此启用了 **Usage（用量）**的模型会在每次运行聊天时报告其 Token，包括 Open WebUI 通过[自动化](/features/chat-conversations/chat-features/automations)、[计时器](/features/chat-conversations/chat-features/timers)和[子智能体](/features/chat-conversations/chat-features/subagents)代表用户启动的聊天。这些运行与人们手动输入的聊天计入同一组总数。分析涵盖聊天中保存的回复，因此不包括模型在[频道](/features/channels)中对 @提及的回复。
:::

### Token 用量指标 {#token-usage-metrics}

**Token 用量**部分（可通过 Token 端点或仪表板访问）提供：

- **按模型细分的 Token**——每个模型的输入、输出和总 Token 数
- **Token 总消耗量**——整个实例的 Token 用量
- **消息数量关联**——每条消息的 Token 数，用于效率分析

:::tip 成本估算
要估算成本，请将 Token 数乘以提供方的价格：
```
Cost = (input_tokens × input_price) + (output_tokens × output_price)
```

GPT-5.6 示例：
- 输入：1,000,000 Token × $0.03/1K = $30
- 输出：500,000 Token × $0.06/1K = $30
- **总计：$60**
:::

## 用例 {#use-cases}

### 1. 资源规划 {#1-resource-planning}

**场景：** 你为团队运行 Open WebUI，需要规划基础设施容量。

**分析如何提供帮助：**
- 查看**消息时间线**，找出使用高峰时段
- 查看**模型用量**，了解哪些模型需要更多资源
- 监测 **Token 用量**，估算未来成本
- 跟踪**用户活动**，为团队增长做好规划

### 2. 模型评估 {#2-model-evaluation}

**场景：** 你已部署多个模型，希望了解用户更偏爱哪些模型。

**分析如何提供帮助：**
- 比较不同模型的**消息数量**，了解采用率
- 检查 **Token 效率**（每条消息的 Token 数），找出回复冗长的模型
- 引入新模型后，监测时间线图表中的**趋势**
- 结合[评估功能](/features/administration/evaluation/)，获得质量洞察

### 3. 成本管理 {#3-cost-management}

**场景：** 你使用付费 API 提供方，需要控制成本。

**分析如何提供帮助：**
- 按模型和用户跟踪 **Token 总消耗量**
- 找出**高用量用户**，讨论配额设置
- 比较不同模型服务提供方的 **Token 成本**
- 使用时间段筛选器进行定期审查

### 4. 用户参与度 {#4-user-engagement}

**场景：** 你希望了解团队如何使用 AI 工具。

**分析如何提供帮助：**
- 对比**活跃用户**与注册账户
- 找出可能需要支持或培训的**重度用户**
- 跟踪**采用趋势**随时间的变化
- 将用量与团队计划或培训课程关联起来

### 5. 合规与审计 {#5-compliance--auditing}

**场景：** 你的组织需要提供使用报告以满足合规要求。

**分析如何提供帮助：**
- 生成特定时间段的**活动报告**
- 跟踪所有 AI 交互的**用户归因**
- 监测**模型用量**，区分获批与未获批的模型
- 通过 API 将数据导出到外部报告工具

## 技术细节 {#technical-details}

### 数据存储 {#data-storage}

分析数据存储在 `chat_message` 表中，其中包含：

- **消息内容**——用户和助手消息
- **元数据**——模型 ID、用户 ID、时间戳
- **Token 用量**——输入、输出和总 Token 数
- **关系**——指向父消息和聊天的链接

升级时，Open WebUI 会创建 `chat_message` 表及其索引，并从聊天历史中回填现有消息。每条消息在保存时都会存入该表，聊天本身不再保存消息副本。因此，分析查询可以保持快速，并涵盖所有消息。

### 数据库索引 {#database-indexes}

以下索引可优化分析查询：

- `chat_id`——快速查找聊天中的所有消息
- `user_id`——快速生成用户活动报告
- `model_id`——高效查询模型用量
- `created_at`——按时间范围筛选
- 针对常见查询模式的复合索引

### API 端点 {#api-endpoints}

分析为高级用户和集成提供 REST API 端点：

**仪表板端点：**
```
GET /api/v1/analytics/summary
GET /api/v1/analytics/models
GET /api/v1/analytics/users
GET /api/v1/analytics/messages
GET /api/v1/analytics/daily
GET /api/v1/analytics/tokens
```

**模型详情端点：**
```
GET /api/v1/analytics/models/{model_id}/chats    # 获取使用此模型的聊天（ENABLE_ADMIN_CHAT_ACCESS 关闭时返回 403）
GET /api/v1/analytics/models/{model_id}/overview # 获取反馈历史和标签
```

**会话端点**（仅限管理员，`403` 表示 `ENABLE_ADMIN_CHAT_ACCESS` 已关闭）：
```
GET /api/v1/analytics/sessions                                          # 每个聊天对应一个会话
GET /api/v1/analytics/sessions/{chat_id}                                # 会话的消息，预览经过缩短和脱敏
GET /api/v1/analytics/sessions/{chat_id}/messages/{message_id}/events   # 单次响应的已保存步骤，片段经过脱敏
GET /api/v1/analytics/sessions/{chat_id}/trace                          # 会话的执行跟踪
```
这四个端点都接受下面的通用查询参数以及 `skip` 和 `limit`（最多 50）。

**个人用量端点**（任何已登录用户均可使用，仅返回其自己的数据）：
```
GET /api/v1/users/usage
```
接受 `days`（7-732）或显式的 `start_date` / `end_date` 范围，并按请求用户的时区对结果分桶。像**设置 > 用量**页面一样，不提供其中任何参数时，返回截至当前的最近 730 天数据。此端点不要求管理员权限，因为它只报告调用方自己的活动。

**通用查询参数：**

| 参数 | 类型 | 说明 |
|-----------|------|-------------|
| `start_date` | 整数 | Unix 时间戳（纪元秒）——范围起点 |
| `end_date` | 整数 | Unix 时间戳（纪元秒）——范围终点 |
| `group_id` | 字符串 | 筛选特定用户组（可选） |

**`/api/v1/analytics/daily` 参数：**

| 参数 | 类型 | 说明 |
|-----------|------|-------------|
| `granularity` | 字符串 | 每个时间桶的大小：`10m`、`hourly`、`3h`、`6h` 或 `daily`（默认）。时间桶使用服务器时间 |
| `metric` | 字符串 | `messages`（默认）统计助手响应数，`tokens` 计算输入和输出 Token 之和 |
| `compare` | 布尔值 | `true` 会在每个时间桶中添加一个 `previous` 对象，其中包含紧邻范围之前、长度相同的窗口数值，以及两个窗口的 `start` 和 `end`。必须同时提供 `start_date` 和 `end_date`，且 `start_date` 不得晚于 `end_date`，否则请求会失败并返回 `400` |

**`/api/v1/analytics/users` 参数：**

| 参数 | 类型 | 说明 |
|-----------|------|-------------|
| `metric` | 字符串 | `messages`（默认）按助手响应数对用户排名，`tokens` 按输入和输出 Token 总数对用户排名 |
| `skip` | 整数 | 跳过多少名排名靠前的用户，默认为 `0`。与 `limit` 配合使用可翻阅排名 |
| `limit` | 整数 | 返回多少名排名靠前的用户，默认为 50 名用户 |

响应包含 `total`（该范围内有活动的用户数量），位于 `users` 列表旁。

:::tip API 访问
所有分析端点都需要管理员身份验证。请附上管理员 Bearer 令牌：
```bash
curl -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  "https://your-instance.com/api/v1/analytics/summary?group_id=abc123"
```
:::

## 隐私与数据注意事项 {#privacy--data-considerations}

### 会跟踪哪些内容？ {#what-gets-tracked}

分析会跟踪：
- 消息时间戳和数量
- 每条消息的 Token 用量
- 模型 ID 和用户 ID
- 聊天 ID 和消息关系
- 响应和工具调用的开始与结束时间

分析**不会**跟踪：
- 仪表板中的消息内容。[会话](#sessions)显示缩短的聊天标题和工具名称
- 外部分享或导出
- 数据库之外的单条消息内容

### 数据保留 {#data-retention}

分析数据遵循实例的聊天保留政策。删除以下内容时：
- **聊天**——所有关联消息都会从分析中移除
- **用户**——其聊天以及聊天中的每条消息都会被删除，因此其历史记录会从分析中消失，而不是以匿名形式保留
- **消息历史**——分析数据也会被清除

## 常见问题 {#frequently-asked-questions}

### 为什么消息数量与我的预期不同？ {#why-are-message-counts-different-from-what-i-expected}

分析统计的是**助手响应**，而不是用户消息。如果一个聊天有 10 条用户消息和 10 条助手响应，则计数为 10。这能更准确地衡量 AI 用量和 Token 消耗。

### Token 跟踪有多准确？ {#how-accurate-is-token-tracking}

Token 的准确性取决于模型服务提供方：
- **OpenAI/Anthropic**——API 响应提供准确计数
- **Ollama**——对于支持 Token 报告的模型，计数准确
- **llama.cpp**——在可用时报告 Token
- **自定义提供方**——取决于具体实现

没有 Token 数据的响应不会为总数增加任何数值。

### 可以导出分析数据吗？ {#can-i-export-analytics-data}

可以，通过 API 端点导出。使用 `curl`、Python 脚本或 BI 工具等获取并导出数据：

```bash
curl -H "Authorization: Bearer TOKEN" \
  "https://instance.com/api/v1/analytics/summary?start_date=1704067200&end_date=1706745600" \
  > analytics_export.json
```

## 总结 {#summary}

Open WebUI 的分析功能通过提供以下能力，将实例转变为数据驱动的平台：

- 模型和用户活动的**实时洞察**
- 用于成本管理和优化的 **Token 跟踪**
- 用于了解使用模式随时间变化的**趋势分析**
- 用于社区建设的**用户参与度**指标
- 将所有数据保留在实例中的**隐私优先**设计

无论你管理的是个人实例还是大型组织部署，分析都能提供所需的可见性，帮助你优化性能、控制成本并更好地服务用户。
