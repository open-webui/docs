# 翻译

Open WebUI 会将其自身界面翻译成多种语言，但你在其中创建的内容，例如模型名称、工具说明和横幅文本，会按你输入的内容存储。通过翻译，可以按语言存储这些文本的版本，这样使用德语界面的用户会看到德语模型名称和德语提示词建议，而其他人仍会看到原文。

系统不会自动翻译任何内容。你需要自行编写每个版本，或导入他人准备好的文件。

除此之外，管理员还可以覆盖 Open WebUI 自身界面的措辞，即应用随附的按钮和标签。请参阅本页底部的[界面文本](#interface-text)。

---

## 哪些内容可以翻译 {#what-can-be-translated}

| 资源 | 字段 | 位置 |
| :--- | :--- | :--- |
| **模型** | 名称、说明、提示词建议、模型控件和选项名称 | 工作区 > 模型，模型编辑器中。请参阅[模型](/features/workspace/models#translations) |
| **工具** | 名称、说明、阀门标签 | 工作区 > 工具，工具编辑器中 |
| **技能** | 名称、说明 | 工作区 > 技能，技能编辑器中 |
| **函数** | 名称、说明、阀门标签、各操作的标签 | 管理员面板 > 函数，函数编辑器中 |
| **横幅** | 内容，不包括标题 | 设置 > 常规（管理区域），“横幅”标题旁 |
| **路由模型** | 名称、说明 | 设置 > 模型（管理区域），路由模型对话框中 |
| **默认提示词建议** | 建议内容本身 | 设置 > 模型 > 模型默认值（管理区域） |
| **Open WebUI 自身界面** | 应用随附的任何字符串 | 设置 > 常规（管理区域），“界面翻译”下。请参阅[界面文本](#interface-text) |

## 语言选择器 {#the-language-selector}

每个支持此功能的编辑器都有地球选择器。它最初位于**默认**，即原始文本；选择一种语言后，编辑器会切换到该语言：此时字段中保存翻译文本，并将原文显示为占位文本。切换回**默认**即可再次编辑原文。

系统提供 Open WebUI 随附的每种语言，包括英语。**默认**不是一种语言，而是原始文本，普通字段中保存的就是它。选择 `en-US` 会存储一个英语翻译，英语读者将看到它而不是原文，这通常不是你想要的效果：除非确实想为英语使用单独的措辞，否则请将英语内容留在**默认**中。

在资源编辑器中，已包含文本的语言会标有 `*`，让你一眼看出哪些语言已经翻译。

在模型编辑器、横幅列表和路由模型对话框中，已翻译的字段带有两个小按钮：**复制默认文本**会填入原文作为起点，**使用默认文本**会清除翻译并重新使用原文。工具和技能的名称及说明没有按钮，直接在字段中输入即可；再次清空字段即可恢复原文。

![切换到德语的模型编辑器，其中包含已翻译的名称、说明和提示词建议](/images/features/translations/model-editor-translations.png)

## 用户会看到哪个版本 {#which-version-a-user-sees}

Open WebUI 按以下顺序，根据用户界面所用的语言进行选择：

1. 完全匹配的语言，例如 `de-DE`
2. 基础语言 `de`，因此 `de` 翻译可覆盖 `de-DE` 和 `de-AT`
3. 原始文本

保存时会丢弃留空的字段，因此空翻译等同于没有翻译，并会显示原文。翻译重要的内容，其余内容留空即可。

翻译文本会跟随资源出现在其名称显示的所有位置：模型和工具选择器、新聊天界面、`@`、`$` 和 `/` 菜单、**+** 菜单、模型控制面板、回答下方的操作按钮、侧边栏和工作区列表。工作区搜索会同时匹配翻译名称和原名，因此搜索任意一个名称都能找到对应内容。

## 翻译阀门标签 {#translating-valve-labels}

工具和函数包含[阀门](/features/extensibility/plugin/development/valves)，即管理员或用户填写的设置。其标签也可以翻译，这对用户阀门尤其重要，因为普通用户会在聊天的**模型控制 > 控件**下看到这些标签。

在工具或函数编辑器中选择一种语言后，代码编辑器会替换为翻译表，其中列出插件公开的每个标签，包括管理员阀门和用户阀门。

![工具编辑器中的阀门翻译表，其中包含键、原始文本和德语翻译](/images/features/translations/tool-valve-translations.png)

键的形式取决于其所属的阀门：

| 键 | 标注的内容 |
| :--- | :--- |
| `valves.<field>.title` | 管理员阀门的标签 |
| `valves.<field>.description` | 其帮助文本 |
| `valves.<field>.enum.<value>` | 下拉阀门的一个选项 |
| `user_valves.<field>.` | 同样三种形式，用于用户阀门 |
| `actions.<action_id>.name` | 函数公开的一个操作的标签 |
| `actions.<action_id>.description` | 该操作的工具提示 |

操作键不会自动列出。请使用 **+** 按钮添加，并输入自己的键。

只有标签会改变。阀门名称、存储的值和默认值均保持不变，因此翻译后的插件行为与未翻译的插件完全一致。

### 导入和导出 {#importing-and-exporting}

**导出**会将当前语言下载为键与文本对的 JSON 文件，以插件和语言命名，并跳过所有留空内容。**导入**会读回该文件，这是将文件交给译者或将一组翻译复制到另一个实例的实用方法。

导入内容在接受前会经过检查。每个值都必须是字符串，原文中的任何 `{{ placeholder }}` 也必须出现在翻译中，因此翻译不会悄然丢失需要替换到其中的值。未通过任一检查的文件都会被拒绝，并指出有问题的键，且不会更改任何内容。

该表还有一个搜索框和一个**已修改**过滤器，可仅显示你实际翻译过的行，便于在包含大量阀门的插件中查找剩余内容。

## 翻译模型控件 {#translating-model-controls}

模型的[控件](/features/workspace/models#model-controls)包含人们在聊天中阅读的名称：控件名称、说明和每个选项的名称。在模型编辑器中选择一种语言后，**模型控件**行会列出其中每一项，并以原文作为占位文本。**使用默认文本**会一次清除该语言的所有控件翻译。

翻译与模型的其他翻译一起存储在 `meta.i18n` 中，每种语言一个映射，使用以下键：

| 键 | 标注的内容 |
| :--- | :--- |
| `model_controls.<key>.label` | 控件的名称 |
| `model_controls.<key>.description` | 其帮助文本 |
| `model_controls.<key>.options.<value>.label` | 一个选项的名称 |

`<key>` 是控件的 ID，`<value>` 是选项的 ID，它们与 API 在 `params.model_controls` 下使用的 ID 相同。只有名称会改变；每个选项发送的参数在所有语言中保持相同。

## 横幅 {#banners}

横幅内容在**设置 > 常规**（管理区域）中翻译，**横幅**标题旁使用相同的地球选择器。每个横幅都保留原始内容和按语言区分的版本，用户会看到与其界面语言匹配的版本。

![正在以德语编辑的横幅，语言选择器位于“横幅”标题旁](/images/features/translations/banner-translations.png)

这取代了以往在一条横幅中放入多种语言的做法。将其编写为翻译后，每位用户都能以自己的语言阅读一条消息，而不是看到堆叠在一起的多种语言。请参阅[横幅](/features/administration/banners)。

## 界面文本 {#interface-text}

以上内容都与用户创建的资源有关。本节介绍 Open WebUI 自身的措辞：应用随附的按钮、标签和消息。

打开**设置 > 常规**（管理区域），找到**界面翻译**。每行都是一对内容：左侧是应用实际使用的原始英语字符串，右侧是你希望改用的显示内容。选择器决定右列属于哪种语言，初始语言是你当前阅读界面所用的语言。

这些覆盖会合并到 Open WebUI 随附的语言文件之上。你覆盖的内容会优先生效，未改动的内容则保留随附措辞，因此只为更改一个词，无需提供完整的文本目录。

![已替换三个界面字符串的“界面翻译”面板](/images/features/translations/ui-translations.png)

界面上的效果如下：

![显示已替换标签的侧边栏](/images/features/translations/ui-translations-effect.png)

:::warning 语言必须完全匹配
这里不像资源翻译那样提供回退。存储在 `en-US` 下的覆盖对使用 `en-GB` 界面的用户不起作用，存储在 `de` 下的覆盖对 `de-DE` 也不起作用。请在用户实际使用的每个语言代码下存储覆盖，否则更改不会显示，也不会出现提示。
:::

英语在这里也算一种语言，因此可以用它为所有人重命名内容：在左侧填入 `Knowledge`，右侧填入 `Library`，保存在英语下，整个界面就会显示 Library。

**左侧必须与原始字符串完全一致**，包括大小写和标点。它是应用查找的键，因此哪怕只有细微差异，也永远不会匹配，任何内容都不会改变。

保存时会强制执行几条规则；违反规则的保存会被拒绝，并指出有问题的条目：

- 替换内容必须是文本。空白内容会被丢弃，这也是移除覆盖的方法。
- 原文中的任何 `{{ placeholder }}` 也必须出现在替换内容中，因此重写后的字符串不会丢失需要替换到其中的值。
- 同一原始文本不能出现在两行中。
- `__proto__`、`prototype` 和 `constructor` 不能用作语言或原始字符串。

某行上的**删除**只会移除选择器当前所选语言的替换内容，其工具提示会指出该语言。其他语言的替换内容会保留；当所有替换内容都被移除后，该行才会消失。

你自己的会话会在保存时立即更新。其他人则会在浏览器下次加载 Open WebUI 时看到更改。

### 通过 API 设置 {#setting-it-through-the-api}

这些覆盖位于管理员配置的 `I18N` 中，其结构为“语言 → 原始字符串 → 替换内容”的嵌套映射，可发送到 `POST /api/v1/auths/admin/config`，并可从 `/api/config` 中以 `i18n` 读取。那里同样会执行上述规则。

请求中省略 `I18N` 会保留已存储的内容，因此写入其他管理员设置的集成不会意外清除覆盖。发送 `{}` 则会将其清空。

## 注意事项 {#notes}

- 翻译与资源本身一起存储，因此导出模型、工具或技能时会一并包含翻译。
- 如果用户的界面语言尚未翻译，该用户会看到原始文本，而不会看到空白字段。
- 这里的任何内容都不会改变模型接收到的信息。模型仍会收到原始系统提示词、原始阀门值和原始工具规范，因此翻译说明不会改变任何行为。
