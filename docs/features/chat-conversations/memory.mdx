:::info Model-dependent quality
How well memories are stored and recalled depends heavily on the model. Frontier models manage memory well; small local models may store or retrieve information inconsistently.
:::

Open WebUI includes a memory system that lets models remember facts, preferences, and context across conversations.
With **Native Tool Calling**, the model manages this memory itself as an active "long-term memory."

## How it Works

The memory system stores snippets of information about you (e.g., "I prefer Python for backend tasks" or "I live in Vienna"). There are two ways these memories are used:

### 1. Manual Management (Settings)

Users can manually add, edit, or delete memories by navigating to:
**Settings > Personalization > Memory**

### 2. Native Memory Tools (Agentic Mode)

When using a model with **Native Function Calling (Agentic Mode)** enabled, quality models can manage your memory autonomously using built-in tools. For a detailed breakdown of how administrators can configure and manage these system-level tools, see the [**Central Tool Calling Guide**](/features/extensibility/plugin/tools#tool-calling-modes-default-vs-native).

:::tip Minimum model tier
Autonomous memory management needs a model that can decide which facts are worth saving and when to recall them. A frontier model is not required: **GPT-5.6 Luna**, **Gemini 3.5 Flash-Lite**, **MiniMax M3**, or locally **Qwen 3.6 27B** or **Muse Glimmer 30B** are the minimum. Only very small models struggle with memory selection. The list is not updated with every model release; any recent model with solid tool calling works.
:::

Each memory carries a **type** and an optional **path** (see [Memory Types & Paths](#memory-types--paths) below). The model manages memory through these tools:

Through these tools the model can save, update, correct, delete, search, list and browse memories by path. See the [built-in tools](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode) for details.

## Memory Types & Paths

Each memory has a **type** and an optional **path**:

- **Type**: `user` memories are facts, preferences, or instructions **about you** (e.g. "prefers Python for backend"); `context` memories are other durable context worth carrying between chats. The two are budgeted separately when injected into the prompt (see [Background Review & Limits](#background-review--limits)).
- **Path**: an optional stable "address" used to **group related memories** (e.g. `work/projects`), so the model can organize and browse them hierarchically with `list_memory_paths` / `read_memory_path` instead of one flat list.

These are set automatically by the memory tools; you do not need to assign them manually.

## Benefits of the Memory System

The model can remember preferences without you typing them, and correct or clean up memories on its own. Every memory a model adds can be reviewed and deleted in the Personalization settings.

## Enabling Memory Tools

1.  **Administrative Enablement**: Ensure the Memory feature is [enabled globally](#administrative-controls) by an administrator and that you have the required permissions.
2.  **Native Mode (Agentic Mode)**: Enable **Native Function Calling** in the model's advanced parameters (**Settings > Models > Edit** (admin section) the model **> Advanced Params**).
3.  **Per-Model Toggles**: Ensure the **Memory** capability and the **Memory** category under **Builtin Tools** are enabled for the model in **Settings > Models > Edit** (admin section) (or **Workspace > Models** for your own model), both on by default. The model also needs **Builtin Tools** on.

[Automations](/features/chat-conversations/chat-features/automations) get the memory tools under the same conditions, whenever memory is on for the user who owns them. That follows the user's **Memory** switch in **Settings > Personalization**. If the user never set it, the default interface settings decide, and without those the instance-wide **Memories** setting.

:::warning Blank replies instead of memory operations
Memory runs as a native tool call, so it only works on a connection whose streaming output follows the OpenAI schema. On an endpoint that omits the `index` field on streamed tool calls, notably Google's OpenAI compatibility layer, the call is dropped and the turn returns an empty assistant message with nothing in the logs. Because the model decides on its own when to call `list_memories` or `add_memory`, this shows up as occasional blank replies rather than an obvious memory failure. See [Blank Replies When the Model Uses a Tool](/troubleshooting/connection-error#blank-replies-when-the-model-uses-a-tool).
:::

:::info Central Tool Documentation
For complete details on all built-in agentic tools (including memory, web search, and knowledge bases) and how to configure them, see the [**Native/Agentic Mode Tools Guide**](/features/extensibility/plugin/tools#built-in-system-tools-nativeagentic-mode).
:::

## Administrative Controls

Administrators have full control over the Memory feature, including the ability to disable it globally or restrict it to specific user groups.

### Global Toggle
The Memory feature can be toggled on or off for the entire instance. When disabled, the "Personalization" tab is hidden from all users, the memory-related API endpoints are blocked, stored memories are no longer added to the model's context and the model is no longer given the memory tools.
- **Admin UI**: Settings > General > Features > **Memories** (admin section)
- **Environment Variable**: [`ENABLE_MEMORIES`](/reference/env-configuration#enable_memories) (Default: `True`)

### Granular Permissions
Administrators can also control Memory access on a per-role or per-group basis from the Permissions interface.
- **Admin UI**: Admin Panel > Users > Permissions > Features > **Memories**
- **Environment Variable**: [`USER_PERMISSIONS_FEATURES_MEMORIES`](/reference/env-configuration#user_permissions_features_memories) (Default: `True`)

Removing the permission hides **Personalization**, blocks the memory endpoints and stops memories reaching the model. Administrators are exempt from the permission check.

### Background Review & Limits

- **Background review**: when [`ENABLE_MEMORY_BACKGROUND_REVIEW`](/reference/env-configuration#enable_memory_background_review) is enabled (default **off**), Open WebUI periodically reviews recent conversation with the chat's own model and can add, replace, move or remove memories of either type, `user` included, every [`MEMORIES_REVIEW_INTERVAL_TURNS`](/reference/env-configuration#memories_review_interval_turns) turns (default `10`), instead of relying only on explicit tool calls.
- **Injection budgets**: [`MEMORIES_CONTEXT_CHAR_LIMIT`](/reference/env-configuration#memories_context_char_limit) and [`MEMORIES_USER_CHAR_LIMIT`](/reference/env-configuration#memories_user_char_limit) (both default `2000`) cap how many characters of `context` and `user` memories are injected into the prompt.

### Memory System Context
By default Open WebUI adds the user's stored memories to the model's context so the model is aware of them. With Native function calling they arrive once per reply as a hidden `recall_memories` tool result after the user's message, otherwise they are appended to the user's message. Recall also needs the model's **Memory** capability. This injection can be turned off independently of the memory tools: when disabled, the model can still add, update and delete memories on request, but remembered information is no longer added to the prompt automatically.
- **Admin UI**: Settings > General > Features > **Memory System Context** (admin section) (shown when Memories is enabled)
- **Environment Variable**: [`ENABLE_MEMORY_SYSTEM_CONTEXT`](/reference/env-configuration#enable_memory_system_context) (Default: `True`)

## Privacy & Security

Memories are stored locally in your Open WebUI database and are scoped to your user account. They are not shared with other users by default, and you can clear your entire memory bank at any time.
