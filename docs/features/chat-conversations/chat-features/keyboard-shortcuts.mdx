# Keyboard Shortcuts

Open WebUI ships with keyboard shortcuts for the things you do constantly, and most of them can be **rebound to keys you prefer**. Shortcuts are per user and stored with your settings.

Manage them in **Settings > Keyboard**. Each configurable shortcut can be reassigned individually, or unassigned with the **x** beside its keys, and a **Reset Defaults** button restores **all** of them at once. There is no per-shortcut reset.

## Turning Shortcuts Off

An **Enable Keyboard Shortcuts** toggle at the top of **Settings > Keyboard** switches all of them off at once. It is on by default.

Turn it off when Open WebUI's shortcuts collide with ones your browser or operating system already uses, `Cmd+Shift+C` for the browser inspector being a common example. While it is off, the configurable shortcuts below do not fire and the key combinations pass through to the browser or OS untouched, dictation included, and the small hotkey hints stop appearing in the interface.

To stop a single shortcut, unassign it instead of turning them all off. Click the **x** beside its keys and the row reads **Unassigned**, so that key combination reaches the browser like any other. That is the usual fix for **Regenerate response**, bound by default to the keys browsers use to reload the page. Click **Unassigned** to give the shortcut keys again.

Nothing locks you out: the **Settings > Keyboard** tab keeps working while shortcuts are disabled, so you can rebind them or switch them back on at any time. The chat input triggers (`/`, `@`, `#`), `Tab` to accept an autocomplete suggestion, and `Esc` to stop a response or close a dialog are unaffected, since they are not global shortcuts.

`Cmd` below means the `Ctrl` key on Windows and Linux. On macOS it means the `Command` key specifically: `Ctrl` is treated as its own modifier there and does not stand in for `Cmd`, so `Ctrl+K` will not open search on a Mac, only `Cmd+K` will.

## Configurable Shortcuts

These twenty-one can be rebound:

| Action | Default |
|---|---|
| New chat | `Cmd+Shift+O` |
| New temporary chat | `Cmd+Shift+'` |
| Delete chat | `Cmd+Shift+Backspace` |
| Open model selector | `Cmd+Shift+M` |
| Toggle dictation | `Cmd+Shift+L` |
| Navigate to previous chat | *(unassigned)* |
| Navigate to next chat | *(unassigned)* |
| Search | `Cmd+K` |
| Open settings | `Cmd+.` |
| Show shortcuts | `Cmd+/` |
| Toggle sidebar | `Cmd+Shift+S` |
| Toggle Controls | *(unassigned)* |
| Close modal | `Escape` |
| Focus input | `Shift+Escape` |
| Clear Input Selections | `Escape` |
| Generate message pair | `Cmd+Shift+Enter` |
| Regenerate response | `Cmd+R` |
| Allow tool call | `Cmd+Alt+Enter` |
| Deny tool call | `Cmd+Alt+Backspace` |
| Copy last code block | `Cmd+Shift+;` |
| Copy last response | `Cmd+Shift+C` |

**Generate message pair** adds the text in the chat input as your message, with a placeholder reply for each selected model that you can then edit by hand.

**Clear Input Selections** resets the chat input's choices: it removes the model override, deselects tools and filters and turns off web search, image generation and code interpreter. It only fires while the chat input has focus.

Anything not listed here is fixed and cannot be reassigned.

## Fixed Shortcuts

These eight are built in and cannot be rebound. **Settings > Keyboard** lists them for reference.

| Action | Key | Active when |
|---|---|---|
| Accept autocomplete generation, jump to prompt variable | `Tab` | The chat input is focused |
| Prevent file creation | `Cmd+Shift+V` | Pasting while **Paste Large Text as File** is on |
| Attach file from knowledge | `#` | Typed in the chat input |
| Add custom prompt | `/` | Typed in the chat input |
| Talk to model | `@` | Typed in the chat input |
| Stop generating | `Escape` | The chat input is focused and a response is being generated |
| Edit last message | `ArrowUp` | The chat input is focused |
| Toggle mute | `M` | Voice mode |

**Allow tool call** and **Deny tool call** apply to a reply that is waiting for approval, which only happens when [Tool Permissions](/features/extensibility/plugin/tools#tool-approval) is on and the chat is set to ask first. They act on the most recent call still waiting, so with several pending you answer them one keypress at a time. At any other moment they do nothing and the keystroke passes through.

Three of them ship **unassigned** and do nothing until you give them keys in **Settings > Keyboard**. **Navigate to previous / next chat** step through the sidebar chat list in order, moving to the chat above or below the one you have open, and start at the top of the list if the current chat is not in it. **Toggle Controls** opens and closes the chat controls panel. They are left unbound so they cannot collide with an existing binding on arrival, pick keys that suit you.

**Delete chat** follows the [Chat Delete permission](/features/authentication-access/rbac/permissions#3-chat-permissions). If an administrator has taken it away, the shortcut stays bound and listed but does nothing, in step with the delete actions being hidden from the sidebar and the menus. Admins are always exempt.

:::info Changes in this release
Shortcuts used to be a fixed list shown in a modal. They are now rebindable and live in **Settings > Keyboard**; the separate shortcuts modal is gone.

One default changed: **Delete chat** is now `Cmd+Shift+Backspace` only. It previously also responded to `Delete`.
:::

## Chat Input Triggers

Distinct from shortcuts, typing one of these characters in the chat input opens a suggestion menu. See [Chat Features](/features/chat-conversations/chat-features/) for the full list.

| Trigger | Offers |
|---|---|
| `/` | Commands, prompts and skills |
| `@` | Models, knowledge, files, folders and URLs |
| `#` | Knowledge and files |
| `$` | Skills |
| `:` | Emoji |

The `/` menu includes a **Model** entry that opens the model picker with its search box focused, so you can change model without leaving the keyboard or binding anything. Typing `/model` followed by a model id switches straight to it.

## Keyboard Navigation

Distinct from the shortcuts above, stepping through the interface with `Tab` and `Shift+Tab` works everywhere and is unaffected by the **Enable Keyboard Shortcuts** toggle. Whatever you have reached is marked with a clear outline, so you can always see where you are. Buttons that normally appear under the pointer, such as the actions under a message, appear when you reach them with `Tab` as well.

The first `Tab` on a page reaches a **Skip to main content** link. It moves focus past the sidebar into the chat, so the next `Tab` lands in the conversation. Tooltips show when a button receives keyboard focus, the same as on hover, and `Escape` closes an open tooltip.

Screen readers get names for the icon buttons in the chat, the chat input and the dialogs. A reply in progress is announced as **Generating...** and then **Response complete**, notifications such as copy confirmations are read out, and in voice mode the call's **Listening...** and **Thinking...** status is announced as it changes. On a new chat, the model name and the **Suggested** label are headings, and the suggestion list is named after that label. With several models selected, their logos are read by model name. Each sidebar chat is read with how long ago it was updated, and the **Info** button under a reply reads out its usage figures. In the model picker, the model the arrow keys are on is read out, and drawn with an outline unless it is already selected. Searching archived chats announces how many were found. The model picker also announces how many models match a search. The **Settings** window is named, and the **Keyboard** tab's shortcut categories are headings with a list under each. The notes on shortcuts marked with an asterisk show when you reach them with `Tab`, and screen readers read them. Select dropdowns mark the chosen option, the search window's list is named by its caption, the sidebar folder toggle says whether the folder is open, each Workspace page has a heading and copying a prompt in Workspace is announced. The chat title is the page's main heading. The sidebar's section titles and chat date groups are headings, and its folders and chats are lists. **Archived Chats** is a table whose column headers say how it is sorted, and the **Settings** tabs sit in **Personal** and **Admin** tab lists. Menu buttons say that they open a menu and whether it is open.

`Escape` on a model's **More** menu or the filter list in the model picker closes only that menu or list. Toast text in the light theme meets the 4.5:1 contrast minimum. **Archived Chats** text meets it too, and the **Archived Chats** and **Keyboard** lists stay usable at 400% zoom.

Opening a menu from the keyboard moves focus to its first item. Arrow keys move through the **+** menu, the **Integrations** menu, the terminal menu, the user menu and a sidebar chat's **Chat Menu**. Opening a filter list in Workspace or the model picker with `Enter` or `Space` moves focus to its options. Starting dictation from the keyboard moves focus to the recording bar. Opening or closing the sidebar moves focus to the other sidebar button. Choosing a Workspace section keeps focus on its link, and unarchiving a chat in **Archived Chats** keeps focus in the list, or on the search field once the list is empty. `Tab` reaches the note editor's **Record** button and its menu, and the delete button on each calendar in the Calendar sidebar. The tools in the **Available Tools** window open from the keyboard. In **Admin Panel > Evaluations**, the **Leaderboard** and **Feedback** lists can be sorted by their column headers and opened from the keyboard.
